## 1. Intuition & 101 Motivation

### 1.1 The Modality Gap & The Modular Paradigm
Human cognition seamlessly integrates raw continuous sensory signals (light striking the retina, acoustic vibrations hitting the tympanic membrane) with discrete symbolic linguistic reasoning. 

In early deep learning systems, researchers attempted to train unified multimodal models from scratch (e.g., training a single monolithic Transformer on concatenated raw pixel patches and text tokens). These early attempts suffered from two fatal flaws:
1. **The Data Asymmetry Barrier:** High-quality text corpora contain trillions of tokens with dense factual reasoning, logic, and mathematics. High-resolution paired image-text datasets (e.g. LAION, CC3M) are orders of magnitude smaller, noisy, and linguistically simplistic. Training from scratch degraded the base language model's complex reasoning and fluency.
2. **Computational Inefficiency:** Learning low-level edge detectors and visual primitives while simultaneously training high-level attention reasoning circuits requires exorbitant GPU compute that is largely redundant.

The breakthrough of modern **Multimodal Large Language Models (MLLMs)**—pioneered by Flamingo, BLIP-2, LLaVA, Qwen-VL, and Gemini—relies on **Modular Cross-Modal Alignment**:
> *Keep an already powerful, frozen pre-trained Vision Foundation Model (e.g. CLIP ViT, SigLIP, DINOv2) and an already powerful, frozen pre-trained Large Language Model (e.g. LLaMA-3, Qwen-2.5, Mistral). Insert a lightweight, differentiable **Cross-Modal Adapter** that projects visual patch representations into the LLM's native word embedding space.*

```
                 MODULAR MLLM HIGH-LEVEL ARCHITECTURE
                 
   Input Image (H x W x 3)                     Text Prompt ("Describe this image")
          │                                                    │
          ▼                                                    ▼
┌──────────────────┐                                  ┌──────────────────┐
│  Vision Encoder  │ (Pre-trained CLIP / SigLIP)      │  Text Tokenizer  │
│    (ViT Core)    │                                  │   (BPE / Word)   │
└─────────┬────────┘                                  └────────┬─────────┘
          │ Patch Features Z_v                                 │ Token IDs
          ▼                                                    │
┌──────────────────┐                                           │
│ Cross-Modal      │                                           │
│ Adapter / Proj   │ (MLP / Pixel-Shuffle / Resampler)         │
└─────────┬────────┘                                           │
          │ Projected Tokens H_v                               │ Embeddings H_t
          └──────────────────────────┬─────────────────────────┘
                                     │
                                     ▼
                     [ H_v || H_t ] (Unified Token Sequence)
                                     │
                                     ▼
                   ┌──────────────────────────────────┐
                   │   Autoregressive Decoder LLM     │
                   │   (Causal Attention over Vision) │
                   └─────────────────┬────────────────┘
                                     │
                                     ▼
                      Generated Response: "A fluffy dog..."
```

By treating visual representations as simply **another foreign language dialect** that can be translated into word token embeddings, the LLM's vast pre-trained world knowledge, reasoning circuits, and conversational fluency are preserved intact.

## 2. Rigorous Mathematical Formulation of Vision Backbones

A multimodal LLM is fundamentally bounded by what its vision encoder can "see". If fine-grained spatial details, OCR text, or subtle object boundaries are obliterated by the vision backbone, downstream LLM reasoning cannot recover them.

### 2.1 Vision Transformer (ViT) Patch Projection
Given an input image $\mathbf{I} \in \mathbb{R}^{3 \times H \times W}$:
1. The 2D image is partitioned into a grid of non-overlapping square patches of size $p \times p$ (typically $p = 14$ in modern CLIP/SigLIP models).
2. The total number of spatial patches is:
   $$N_p = \left( \frac{H}{p} \right) \times \left( \frac{W}{p} \right)$$
3. Each patch $\mathbf{x}_{(i, j)} \in \mathbb{R}^{3 \cdot p^2}$ is linearly projected into a hidden embedding of dimension $d_v$ via a 2D convolution with kernel size $p \times p$ and stride $p$:
   $$\mathbf{z}_0 = \left[ \mathbf{x}_{\text{cls}}; \; \mathbf{x}_{(1)} \mathbf{W}_e; \; \mathbf{x}_{(2)} \mathbf{W}_e; \dots; \; \mathbf{x}_{(N_p)} \mathbf{W}_e \right] + \mathbf{E}_{\text{pos}}$$
   where $\mathbf{W}_e \in \mathbb{R}^{(3 p^2) \times d_v}$, $\mathbf{x}_{\text{cls}} \in \mathbb{R}^{d_v}$ is the optional classification token, and $\mathbf{E}_{\text{pos}} \in \mathbb{R}^{(N_p + 1) \times d_v}$ is the learnable 2D positional embedding.
4. The patch tokens pass through $L_v$ Transformer encoder layers yielding final visual representations:
   $$\mathbf{Z}_v = \operatorname{ViT}(\mathbf{I}) \in \mathbb{R}^{N_p \times d_v}$$

### 2.2 Contrastive Language-Image Pre-training (CLIP) & InfoNCE Loss

CLIP (Radford et al., 2021) trains a Vision Transformer $f_v(\mathbf{I})$ and a Text Transformer $f_t(\mathbf{T})$ to maximize cosine similarity for matching pairs in a batch of size $B$.

Let $\mathbf{v}_i = \frac{f_v(\mathbf{I}_i)}{\|f_v(\mathbf{I}_i)\|_2} \in \mathbb{R}^{d}$ and $\mathbf{t}_i = \frac{f_t(\mathbf{T}_i)}{\|f_t(\mathbf{T}_i)\|_2} \in \mathbb{R}^{d}$ be the $L_2$-normalized visual and textual global representations for sample $i$.

The symmetric **InfoNCE loss** across batch size $B$ is:
$$\mathcal{L}_{\text{InfoNCE}} = - \frac{1}{2B} \sum_{i=1}^B \left( \log \frac{\exp(\mathbf{v}_i^T \mathbf{t}_i / \tau)}{\sum_{j=1}^B \exp(\mathbf{v}_i^T \mathbf{t}_j / \tau)} + \log \frac{\exp(\mathbf{v}_i^T \mathbf{t}_i / \tau)}{\sum_{j=1}^B \exp(\mathbf{v}_j^T \mathbf{t}_i / \tau)} \right)$$
where $\tau > 0$ is a learnable temperature parameter.

#### First-Principles Gradient Derivation of InfoNCE:
Let $s_{ij} = \mathbf{v}_i^T \mathbf{t}_j / \tau$. The image-to-text cross-entropy component for sample $i$ is:
$$\ell_i = - s_{ii} + \log \sum_{j=1}^B \exp(s_{ij})$$

Taking the gradient with respect to visual feature vector $\mathbf{v}_i$:
$$\nabla_{\mathbf{v}_i} \ell_i = - \frac{1}{\tau} \mathbf{t}_i + \sum_{j=1}^B \underbrace{\left( \frac{\exp(s_{ij})}{\sum_{k=1}^B \exp(s_{ik})} \right)}_{P_{ij}} \frac{1}{\tau} \mathbf{t}_j = \frac{1}{\tau} \left( \sum_{j=1}^B P_{ij} \mathbf{t}_j - \mathbf{t}_i \right)$$
where $P_{ij}$ is the softmax probability of pairing image $i$ with text $j$.

#### The Softmax Normalization Bottleneck:
To compute the denominator $\sum_{j=1}^B \exp(s_{ij})$, the forward pass requires collecting all $B$ text embeddings across **all participating GPU nodes**. 
In multi-node distributed training (e.g. $B = 32,768$ across 256 GPUs), this requires an expensive `all-gather` collective communication operation at every step. The communication overhead scales quadratically with cluster size, creating a severe memory and network barrier.

---

### 2.3 SigLIP: Sigmoid Loss for Language-Image Pre-Training (Zhai et al., 2023)

SigLIP (Google DeepMind, adopted in PaliGemma, Gemma-3, and modern LLaVA variants) replaces the global softmax normalization with independent **pairwise sigmoid binary cross-entropy**:

$$\mathcal{L}_{\text{SigLIP}} = - \frac{1}{B} \sum_{i=1}^B \sum_{j=1}^B \log \sigma\left( y_{ij} \left( \mathbf{v}_i^T \mathbf{t}_j \cdot e^t + b \right) \right)$$

where:
- $y_{ij} = +1$ if $i = j$ (matching positive pair).
- $y_{ij} = -1$ if $i \ne j$ (non-matching negative pair).
- $\sigma(z) = \frac{1}{1 + e^{-z}}$ is the standard logistic sigmoid function.
- $t \in \mathbb{R}$ is a learnable log-temperature ($e^t$ represents scale), and $b \in \mathbb{R}$ is a learnable bias.

```
       CLIP InfoNCE (Global Softmax)             SigLIP (Pairwise Sigmoids)
       
       Requires denominator sum across all       Every cell in the BxB matrix
       batch items (all-gather bottleneck):      is an independent binary decision:
       
       [ exp(s_11) / SUM_j exp(s_1j) ]           [ log sigma( s_11 * e^t + b ) ]
       [ exp(s_22) / SUM_j exp(s_2j) ]           [ log sigma( -s_12 * e^t - b ) ]
       
       Batch scaling: Communication-bound        Batch scaling: Embarrassingly parallel
```

#### First-Principles Gradient Derivation of SigLIP:
Let $z_{ij} = \mathbf{v}_i^T \mathbf{t}_j \cdot e^t + b$. Using the derivative of log-sigmoid:
$$\frac{d}{dz} \log \sigma(y \cdot z) = y \cdot (1 - \sigma(y \cdot z))$$

For positive pair ($i = j, y_{ii} = +1$):
$$\frac{\partial \mathcal{L}}{\partial z_{ii}} = - (1 - \sigma(z_{ii})) = - \sigma(-z_{ii})$$

For negative pair ($i \ne j, y_{ij} = -1$):
$$\frac{\partial \mathcal{L}}{\partial z_{ij}} = - (-1) \cdot (1 - \sigma(-z_{ij})) = + \sigma(z_{ij})$$

Taking the derivative with respect to $\mathbf{v}_i$:
$$\nabla_{\mathbf{v}_i} \mathcal{L}_{\text{SigLIP}} = \frac{e^t}{B} \left( \sum_{j \ne i}^B \sigma(z_{ij}) \mathbf{t}_j - \sigma(-z_{ii}) \mathbf{t}_i \right)$$

**Why SigLIP Dominates Modern Production MLLMs:**
1. **Zero Multi-Node Communication Bottleneck:** Unlike softmax, computing pairwise sigmoid losses does not require normalizing across all candidates simultaneously. Sub-batches can be evaluated in an embarrassingly parallel, chunked manner without distributed `all-gather`.
2. **Dense Multi-Positive Robustness:** When batch images contain identical semantic classes (e.g. two photos of golden retrievers), CLIP's softmax forces one to be treated as a negative, penalizing correct semantic alignment. SigLIP's independent sigmoid classification handles multi-label semantic overlap naturally.
3. **Superior Fine-Grained Representations:** Empirically yields significantly higher zero-shot accuracy, OCR transcription fidelity, and dense spatial localization precision.

## 3. High-Resolution Dynamic Patching: Beyond Square Resizing

In early MLLMs (like LLaVA-1.0), all input images were forcibly bilinearly interpolated and warped into a fixed square resolution (e.g., $224 \times 224$ or $336 \times 336$).

### The Destruction of Visual Information:
1. **Aspect Ratio Distortion:** A $16:9$ panoramic landscape or a tall, narrow mobile screenshot is severely squashed, destroying geometric angles, object contours, and font aspect ratios.
2. **Loss of High-Frequency Detail:** A $4K$ high-resolution document invoice or dense engineering schematic compressed to $336 \times 336$ loses $99\%$ of its pixels. Small alphanumeric text merges into unreadable gray blurs, making OCR impossible.

---

### 3.1 The AnyRes (Any-Resolution) Grid Selection Algorithm (LLaVA-NeXT)

Rather than distorting the image, modern MLLMs decompose arbitrary-resolution images into a grid of standard-resolution **sub-image tiles** plus an overarching **global thumbnail**.

Let:
- Input image dimensions be $(H_{\text{orig}}, W_{\text{orig}})$.
- Native Vision Transformer tile resolution be $P$ (e.g., $P = 384$).
- Maximum allowed tile budget be $N_{\max}$ (e.g., $N_{\max} = 6$).
- Pre-defined candidate grid configurations be $\mathcal{G} = \{ (m, n) \in \mathbb{N}^2 \mid m \cdot n \le N_{\max} \}$.
  For $N_{\max} = 6$, candidate grids include:
  $$\mathcal{G} = \{ (1, 1), (1, 2), (2, 1), (1, 3), (3, 1), (2, 2), (2, 3), (3, 2), (1, 4), (4, 1) \}$$

#### The Grid Selection Metric:
The algorithm selects the grid $(m^*, n^*) \in \mathcal{G}$ that minimizes the **logarithmic aspect ratio distortion**:

$$(m^*, n^*) = \arg\min_{(m, n) \in \mathcal{G}} \left| \ln \left( \frac{W_{\text{orig}}}{H_{\text{orig}}} \right) - \ln \left( \frac{n \cdot P}{m \cdot P} \right) \right| = \arg\min_{(m, n) \in \mathcal{G}} \left| \ln \left( \frac{W_{\text{orig}}}{H_{\text{orig}}} \cdot \frac{m}{n} \right) \right|$$

In the event of ties, the grid that minimizes total wasted padding area is selected:
$$\text{Area Waste} = (m \cdot n \cdot P^2) - (H_{\text{orig}} \cdot W_{\text{orig}} \cdot s^2)$$
where $s = \min\left( \frac{m \cdot P}{H_{\text{orig}}}, \frac{n \cdot P}{W_{\text{orig}}} \right)$ is the bilinear scaling factor.

```
                   ANYRES (ANY-RESOLUTION) GRID DECOMPOSITION
                   
         Original High-Res Image (e.g., 768 x 768)
         ┌────────────────────────┬────────────────────────┐
         │                        │                        │
         │      Tile (0, 0)       │      Tile (0, 1)       │
         │      [384 x 384]       │      [384 x 384]       │
         │                        │                        │
         ├────────────────────────┼────────────────────────┤
         │                        │                        │
         │      Tile (1, 0)       │      Tile (1, 1)       │
         │      [384 x 384]       │      [384 x 384]       │
         │                        │                        │
         └────────────────────────┴────────────────────────┘
                                    +
         Global Downsampled Thumbnail [384 x 384]
         
         Total Visual Tokens fed to LLM = 1 Global Tile + 4 Local Tiles
                                        = 5 * (24 x 24) = 2,880 visual tokens
```

### 3.2 Dynamic Sequence Assembly with 2D Layout Markers

After cropping the resized image into $m \times n$ tiles of size $P \times P$:
1. **Global Overview:** The entire original image is resized to $P \times P$ and encoded by the ViT to produce global feature tokens:
   $$\mathbf{Z}_{\text{global}} = \operatorname{ViT}(\mathbf{I}_{\text{global}}) \in \mathbb{R}^{N_p \times d_v}$$
2. **Local High-Resolution Tiles:** Each cropped tile $\mathbf{I}_{\text{tile}}^{(r, c)}$ is encoded by the ViT:
   $$\mathbf{Z}_{\text{local}}^{(r, c)} = \operatorname{ViT}(\mathbf{I}_{\text{tile}}^{(r, c)}) \in \mathbb{R}^{N_p \times d_v} \quad \text{for } r \in [1, m], \; c \in [1, n]$$
3. **2D Spatial Layout Assembly:**
   Language models process 1D sequences. To preserve the 2D geometric topology of the image tiles, **special layout tokens** are inserted:
   - A row newline token `\n` is appended after every tile row.
   - A separator token `[SEP]` is placed between the global overview and the local detail tiles:

$$\mathbf{H}_{\text{vision}} = \left[ \mathbf{H}_{\text{global}}, \; \text{[SEP]}, \; \mathbf{H}_{\text{tile}}^{(1, 1)}, \dots, \mathbf{H}_{\text{tile}}^{(1, n)}, \; \text{[NL]}, \; \mathbf{H}_{\text{tile}}^{(2, 1)}, \dots, \mathbf{H}_{\text{tile}}^{(2, n)}, \; \text{[NL]} \dots \right]$$

This explicit spatial token formatting allows the causal self-attention mechanism in the LLM to learn coordinate geometry and relative spatial reasoning effortlessly.

## 4. Cross-Modal Adapters: Architectural Typologies

How do we project visual feature vectors $\mathbf{Z}_v \in \mathbb{R}^{N_v \times d_v}$ into LLM token embeddings $\mathbf{H}_v \in \mathbb{R}^{N_v \times d_{\text{text}}}$?

```
                       CROSS-MODAL ADAPTER ARCHITECTURES
                       
  (A) Two-Layer MLP Projector          (B) Pixel-Shuffle Spatial Downsampling
      [Patch Tokens Z_v]                   [Spatial Grid 24x24 Tokens]
             │                                        │
             ▼                                        ▼
      Linear(d_v -> d_text)                Concatenate 2x2 neighboring patches
             │                             Dimension: d_v -> 4 * d_v
             ▼                             Token count: 576 -> 144 (75% compression!)
           GELU                                       │
             │                                        ▼
      Linear(d_text -> d_text)             Linear(4 * d_v -> d_text)
             │                                        │
             ▼                                        ▼
      [Tokens H_v] (1:1 tokens)            [Tokens H_v] (1/4 tokens!)
```

### 4.1 Linear & Two-Layer MLP Projectors (LLaVA-1.5)
- **Linear Projector:** $\mathbf{H}_v = \mathbf{Z}_v \mathbf{W}_p$. Forces an affine alignment between image features and word space.
- **Two-Layer MLP Projector with GeLU:**
  $$\mathbf{H}_v = \operatorname{GELU}(\mathbf{Z}_v \mathbf{W}_1 + \mathbf{b}_1) \mathbf{W}_2 + \mathbf{b}_2$$
  where $\mathbf{W}_1 \in \mathbb{R}^{d_v \times d_{\text{text}}}$, $\mathbf{W}_2 \in \mathbb{R}^{d_{\text{text}} \times d_{\text{text}}}$.
- **Limitation:** The token count remains strictly $1:1$ with ViT patches ($576$ tokens per tile). With 5 tiles in AnyRes, a single image consumes $2,880$ tokens, quickly exhausting the LLM's context window.

---

### 4.2 Pixel-Shuffle / 2×2 Spatial Downsampling (Qwen2-VL, InternVL2)
In natural images, adjacent $14 \times 14$ patches share immense redundant spatial information. 

The **Pixel-Shuffle spatial merger** groups blocks of $2 \times 2$ spatial feature vectors:
1. Reshape the 1D token sequence $\mathbf{Z}_v \in \mathbb{R}^{(H_p \cdot W_p) \times d_v}$ back to a 2D spatial grid:
   $$\mathbf{Z}_{\text{grid}} \in \mathbb{R}^{H_p \times W_p \times d_v}$$
2. Re-index and concatenate $2 \times 2$ neighboring spatial patches along the channel dimension:
   $$\mathbf{Z}_{\text{merged}} \in \mathbb{R}^{\frac{H_p}{2} \times \frac{W_p}{2} \times (4 \cdot d_v)}$$
3. Apply a single linear projection and LayerNorm to map back to the LLM hidden dimension $d_{\text{text}}$:
   $$\mathbf{H}_v = \operatorname{LayerNorm}\left( \mathbf{Z}_{\text{merged}} \mathbf{W}_{\text{proj}} \right) \in \mathbb{R}^{\frac{N_p}{4} \times d_{\text{text}}}$$

**Production Impact:**
- Compresses visual token count by **$75\%$** (576 tokens become 144 tokens)!
- Reduces LLM prefill Time-to-First-Token (TTFT) by $4\times$.
- Reduces KV-cache consumption by $4\times$, allowing multi-turn dialogues with multiple high-resolution images.

---

### 4.3 Perceiver Resampler / Q-Former (Flamingo, BLIP-2)
When processing video or massive multi-image documents, visual token counts must be bounded to a fixed constant regardless of input resolution.

The **Perceiver Resampler** cross-attends a fixed set of $K$ learnable query tokens $\mathbf{Q} \in \mathbb{R}^{K \times d}$ to the visual features $\mathbf{Z}_v \in \mathbb{R}^{N_v \times d_v}$:
$$\mathbf{H}_{\text{bottleneck}} = \operatorname{softmax}\left( \frac{(\mathbf{Q} \mathbf{W}_q)(\mathbf{Z}_v \mathbf{W}_k)^T}{\sqrt{d_k}} \right) (\mathbf{Z}_v \mathbf{W}_v) \in \mathbb{R}^{K \times d_{\text{text}}}$$
Regardless of whether the input is a $512 \times 512$ image or a 2-hour video, the LLM receives **strictly $K = 64$ visual tokens**!

## 5. Three-Stage Training Protocol & Loss Formulation

Modern production MLLMs are trained via a disciplined, multi-stage curriculum:

```
                      THE 3-STAGE MLLM TRAINING PROTOCOL
                      
 Stage 1: Pre-training          Stage 2: Instruction Tuning       Stage 3: Vision DPO / RLHF
 (Feature Alignment)            (Multi-Task Reasoning)            (Anti-Hallucination)
 
 ┌─────────────────┐            ┌─────────────────┐               ┌─────────────────┐
 │ Frozen Vision   │            │ Trainable ViT   │               │ Trainable MLLM  │
 │ Encoder (ViT)   │            │ (or Top Layers) │               │ Policy pi_theta │
 └────────┬────────┘            └────────┬────────┘               └────────┬────────┘
          ▼                              ▼                                 ▼
 ┌─────────────────┐            ┌─────────────────┐               ┌─────────────────┐
 │ Trainable       │            │ Trainable       │               │ Direct Pref Opt │
 │ MLP Adapter     │            │ MLP Adapter     │               │ (Pairwise Loss) │
 └────────┬────────┘            └────────┬────────┘               └────────┬────────┘
          ▼                              ▼                                 ▼
 ┌─────────────────┐            ┌─────────────────┐               ┌─────────────────┐
 │ Frozen LLM      │            │ Fully Trainable │               │ Frozen Ref MLLM │
 │ Backbone        │            │ LLM Backbone    │               │ pi_ref          │
 └─────────────────┘            └─────────────────┘               └─────────────────┘
 Data: 500K - 1M image-         Data: 1M - 3M complex visual      Data: Human / AI preference
 caption pairs (CC3M, LAION)    conversations, OCR, charts, QA    pairs (Chosen vs Rejected)
```

### 5.1 Stage 1: Modality Alignment Pre-Training
- **Objective:** Teach the adapter weights $\theta_{\text{adapter}}$ to project visual patch tokens into semantically meaningful word embeddings.
- **Status:** Vision Encoder **Frozen**, LLM **Frozen**, Adapter **Trainable**.
- **Dataset:** 500K to 1M broad image-caption pairs (CC3M, LAION filtered).
- **Loss Function:** Standard autoregressive next-token prediction applied over caption tokens:
  $$\mathcal{L}_{\text{Stage1}}(\theta_{\text{adapter}}) = - \sum_{t=1}^{T} \log P(y_t \mid y_{<t}, \mathbf{H}_v)$$

---

### 5.2 Stage 2: Visual Instruction Fine-Tuning (SFT)
- **Objective:** Enable multi-turn visual dialogue, complex spatial reasoning, dense document OCR, and chain-of-thought visual deduction.
- **Status:** Vision Encoder **Unfrozen / Trainable**, Adapter **Trainable**, LLM **Trainable**.
- **Dataset:** 1M to 3M diverse visual instruction samples (LLaVA-Instruct, ScienceQA, DocVQA, ChartQA).
- **Masked Cross-Entropy Loss Formulation:**
  In visual conversations, we must **never** compute loss on the user prompt or visual tokens (otherwise the model wastes capacity learning to predict the user's input).
  
  Let $X = (x_1, x_2, \dots, x_N)$ be the full packed sequence consisting of visual tokens $\mathbf{H}_v$, user prompt tokens $\mathbf{x}_{\text{prompt}}$, and assistant response tokens $\mathbf{y}_{\text{resp}}$.
  The loss is computed **strictly over assistant response tokens**:
  $$\mathcal{L}_{\text{Stage2}}(\theta) = - \sum_{i=1}^N m_i \cdot \log P_\theta(x_i \mid x_{<i})$$
  where the loss mask is:
  $$m_i = \begin{cases} 1 & \text{if } x_i \in \text{Assistant Response Tokens} \\ 0 & \text{if } x_i \in \mathbf{H}_v \cup \mathbf{x}_{\text{prompt}} \end{cases}$$

---

### 5.3 Stage 3: Vision Direct Preference Optimization (V-DPO)
- **The Problem:** MLLMs are notoriously prone to **Object Hallucination**—confidently stating that objects, colors, or spatial locations exist in the scene when they do not (e.g. answering "Yes, there is a red car parked on the sidewalk" when no car exists).
- **The Solution:** Collect preference pairs $(y_w, y_l)$ for a given image $\mathbf{I}$ and prompt $\mathbf{x}$, where:
  - $y_w$ (winning response): Factually grounded in visual evidence.
  - $y_l$ (losing response): Contains hallucinations, wrong attributes, or fabricated spatial relationships.
- **The V-DPO Objective:**
  $$\mathcal{L}_{\text{V-DPO}}(\theta; \theta_{\text{ref}}) = - \mathbb{E}_{(\mathbf{I}, \mathbf{x}, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w \mid \mathbf{I}, \mathbf{x})}{\pi_{\text{ref}}(y_w \mid \mathbf{I}, \mathbf{x})} - \beta \log \frac{\pi_\theta(y_l \mid \mathbf{I}, \mathbf{x})}{\pi_{\text{ref}}(y_l \mid \mathbf{I}, \mathbf{x})} \right) \right]$$
  where $\pi_{\text{ref}}$ is the frozen Stage 2 SFT model, and $\beta$ controls conservative divergence from the reference policy.

## 6. Dense Grounding & Bounding Box Spatial Coordinates

Production MLLMs (such as Qwen2-VL, Gemini, and InternVL) possess dense spatial perception: they can detect, segment, and point to exact visual coordinates within images.

### Coordinate Tokenization Paradigm:
Rather than adding custom detection heads (like Faster R-CNN or DETR), coordinates are **discretized as text tokens** normalized in range $[0, 1000]$:
$$\text{Box Format:} \quad [y_{\min}, x_{\min}, y_{\max}, x_{\max}]$$

For example, pointing to a person in the center of the image:
```
User: "Detect all pedestrians in the scene."
Assistant: "A pedestrian is located at [320, 450, 780, 560]."
```

During training:
- Coordinates are normalized: $x_{\text{norm}} = \text{round}\left( \frac{x}{W} \times 1000 \right)$, $y_{\text{norm}} = \text{round}\left( \frac{y}{H} \times 1000 \right)$.
- The language model learns to generate spatial coordinates autoregressively using standard cross-entropy loss, entirely unifying detection, segmentation grounding, and visual question answering!

## 7. Prof. Tom Yeh "AI by Hand" Visual Grids & Solved Numerical Problems

### 7.1 Problem 1: ViT Patching and 2×2 Pixel-Shuffle Arithmetic

**Scenario:**
Consider a microscopic toy image of size $H = 28, W = 28$ with $C = 1$ channel.
- ViT patch size: $p = 14$.
- Number of patches: $H_p = 28 / 14 = 2$, $W_p = 28 / 14 = 2$. Total patches $N_p = 4$.
- Vision embedding dimension: $d_v = 3$.
- LLM embedding dimension: $d_{\text{text}} = 6$.

Let the 4 extracted patch feature vectors be:
$$\mathbf{z}_{(0, 0)} = \begin{bmatrix} 1 \\ 0 \\ 2 \end{bmatrix}, \quad \mathbf{z}_{(0, 1)} = \begin{bmatrix} 3 \\ 1 \\ 0 \end{bmatrix}, \quad \mathbf{z}_{(1, 0)} = \begin{bmatrix} 0 \\ 2 \\ 1 \end{bmatrix}, \quad \mathbf{z}_{(1, 1)} = \begin{bmatrix} 2 \\ 2 \\ 0 \end{bmatrix}$$

**Questions:**
1. Compute the concatenated Pixel-Shuffle feature vector $\mathbf{z}_{\text{merged}}$.
2. If the projection matrix $\mathbf{W}_{\text{proj}} \in \mathbb{R}^{(4 \cdot d_v) \times d_{\text{text}}}$ is a simple block matrix where each block $\mathbf{I}_3$ maps channels forward:
   $$\mathbf{W}_{\text{proj}} = \begin{bmatrix} \mathbf{I}_3 & \mathbf{0} \\ \mathbf{0} & \mathbf{I}_3 \\ \mathbf{I}_3 & \mathbf{0} \\ \mathbf{0} & \mathbf{I}_3 \end{bmatrix} \in \mathbb{R}^{12 \times 6}$$
   calculate the resulting projected LLM token $\mathbf{h}_v \in \mathbb{R}^6$.
3. What is the spatial token reduction ratio?

---

**Step-by-Step Hand Calculations:**

**1. Pixel-Shuffle Concatenation:**
The 4 neighboring patches in the $2 \times 2$ block are concatenated along the channel axis:
$$\mathbf{z}_{\text{merged}} = \begin{bmatrix} \mathbf{z}_{(0, 0)} \\ \mathbf{z}_{(0, 1)} \\ \mathbf{z}_{(1, 0)} \\ \mathbf{z}_{(1, 1)} \end{bmatrix} = \begin{bmatrix} 1 \\ 0 \\ 2 \\ 3 \\ 1 \\ 0 \\ 0 \\ 2 \\ 1 \\ 2 \\ 2 \\ 0 \end{bmatrix} \in \mathbb{R}^{12}$$

**2. Linear Projection $\mathbf{h}_v = \mathbf{z}_{\text{merged}}^T \mathbf{W}_{\text{proj}}$:**
- Dimensions 1 to 3 of $\mathbf{h}_v$:
  $$\mathbf{h}_v[0:3] = \mathbf{z}_{(0, 0)} + \mathbf{z}_{(1, 0)} = \begin{bmatrix} 1 \\ 0 \\ 2 \end{bmatrix} + \begin{bmatrix} 0 \\ 2 \\ 1 \end{bmatrix} = \begin{bmatrix} 1 \\ 2 \\ 3 \end{bmatrix}$$
- Dimensions 4 to 6 of $\mathbf{h}_v$:
  $$\mathbf{h}_v[3:6] = \mathbf{z}_{(0, 1)} + \mathbf{z}_{(1, 1)} = \begin{bmatrix} 3 \\ 1 \\ 0 \end{bmatrix} + \begin{bmatrix} 2 \\ 2 \\ 0 \end{bmatrix} = \begin{bmatrix} 5 \\ 3 \\ 0 \end{bmatrix}$$
Total projected token:
$$\mathbf{h}_v = \begin{bmatrix} 1 & 2 & 3 & 5 & 3 & 0 \end{bmatrix}^T \in \mathbb{R}^6$$

**3. Token Reduction Ratio:**
- Initial ViT patch count: $4 \text{ tokens}$.
- Post Pixel-Shuffle count: $1 \text{ token}$.
- Compression: $\frac{4 - 1}{4} = \mathbf{75\% \text{ token reduction}}$.

### 7.2 Problem 2: InfoNCE vs. SigLIP Loss Calculation on a Toy 2×2 Batch

**Scenario:**
Consider a mini-batch of size $B = 2$ with pre-computed dot products $S_{ij} = \mathbf{v}_i^T \mathbf{t}_j$:
$$S = \begin{bmatrix} S_{11} & S_{12} \\ S_{21} & S_{22} \end{bmatrix} = \begin{bmatrix} 4.0 & 1.0 \\ 0.0 & 3.0 \end{bmatrix}$$
Let temperature scale be $\lambda = 1.0$ (with $\tau = 1.0$) and bias $b = 0.0$.

#### Method A: CLIP InfoNCE Loss
1. **Row 1 (Image 1):**
   - $P_{11} = \frac{\exp(4.0)}{\exp(4.0) + \exp(1.0)} = \frac{54.598}{54.598 + 2.718} = \frac{54.598}{57.316} = \mathbf{0.9526}$
   - Loss $\ell_{I1} = - \ln(0.9526) = \mathbf{0.0486}$
2. **Row 2 (Image 2):**
   - $P_{22} = \frac{\exp(3.0)}{\exp(0.0) + \exp(3.0)} = \frac{20.0855}{1.0 + 20.0855} = \frac{20.0855}{21.0855} = \mathbf{0.9526}$
   - Loss $\ell_{I2} = - \ln(0.9526) = \mathbf{0.0486}$
3. **Column 1 (Text 1):**
   - $P_{11}^{\text{col}} = \frac{\exp(4.0)}{\exp(4.0) + \exp(0.0)} = \frac{54.598}{55.598} = \mathbf{0.9820} \implies \ell_{T1} = \mathbf{0.0182}$
4. **Column 2 (Text 2):**
   - $P_{22}^{\text{col}} = \frac{\exp(3.0)}{\exp(1.0) + \exp(3.0)} = \frac{20.0855}{2.718 + 20.0855} = \mathbf{0.8808} \implies \ell_{T2} = \mathbf{0.1269}$
5. **Total InfoNCE Loss:**
   $$\mathcal{L}_{\text{InfoNCE}} = \frac{0.0486 + 0.0486 + 0.0182 + 0.1269}{4} = \frac{0.2423}{4} = \mathbf{0.0606}$$

---

#### Method B: SigLIP Pairwise Sigmoid Loss
Using $\mathcal{L}_{\text{SigLIP}} = - \frac{1}{B} \sum_{i} \sum_{j} \log \sigma(y_{ij} S_{ij})$:
1. **Positive Pair $(1, 1): y_{11} = +1, S_{11} = 4.0$:**
   $$\sigma(4.0) = \frac{1}{1 + e^{-4}} = \frac{1}{1 + 0.0183} = 0.9820 \implies - \ln(0.9820) = \mathbf{0.0182}$$
2. **Negative Pair $(1, 2): y_{12} = -1, S_{12} = 1.0$:**
   $$\sigma(-1.0) = \frac{1}{1 + e^{1}} = \frac{1}{3.718} = 0.2689 \implies - \ln(1 - 0.2689) = - \ln(0.7311) = \mathbf{0.3133}$$
3. **Negative Pair $(2, 1): y_{21} = -1, S_{21} = 0.0$:**
   $$\sigma(0.0) = 0.5000 \implies - \ln(0.5000) = \mathbf{0.6931}$$
4. **Positive Pair $(2, 2): y_{22} = +1, S_{22} = 3.0$:**
   $$\sigma(3.0) = \frac{1}{1 + e^{-3}} = \frac{1}{1.0498} = 0.9526 \implies - \ln(0.9526) = \mathbf{0.0486}$$
5. **Total SigLIP Loss ($B = 2$):**
   $$\mathcal{L}_{\text{SigLIP}} = \frac{0.0182 + 0.3133 + 0.6931 + 0.0486}{2} = \frac{1.0732}{2} = \mathbf{0.5366}$$

**Analytical Comparison:**
| Property | CLIP InfoNCE | SigLIP Sigmoid |
| :--- | :---: | :---: |
| **Loss Value** | $0.0606$ | $0.5366$ |
| **Denominator Dependency** | Sum over all batch items | None (Independent terms) |
| **Distributed Communication** | Requires global `all-gather` | Embarrassingly parallel (Local matrix ops) |
| **Multi-Positive Handling** | Penalizes co-occurring positives | Treats each pair as independent probability |

### 7.3 Problem 3: AnyRes Grid Selection Arithmetic

**Scenario:**
An input image has dimensions $W_{\text{orig}} = 1000, H_{\text{orig}} = 400$ (Aspect ratio $A_{\text{orig}} = 1000 / 400 = 2.50$).
ViT tile resolution is $P = 384$. Maximum tile budget $N_{\max} = 4$.

**Candidate Grids & Distortion Evaluation:**
$$D(m, n) = \left| \ln \left( \frac{W_{\text{orig}}}{H_{\text{orig}}} \right) - \ln \left( \frac{n}{m} \right) \right| = |\ln(2.50) - \ln(n / m)| = |0.9163 - \ln(n / m)|$$

| Grid $(m, n)$ | Grid Tiles ($m \cdot n$) | Grid Aspect Ratio ($n / m$) | $\ln(n / m)$ | Distortion $D(m, n)$ | Selected? |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **$(1, 1)$** | 1 | $1.00$ | $0.0000$ | $|0.9163 - 0.0000| = \mathbf{0.9163}$ | No |
| **$(1, 2)$** | 2 | $2.00$ | $0.6931$ | $|0.9163 - 0.6931| = \mathbf{0.2232}$ | No |
| **$(2, 1)$** | 2 | $0.50$ | $-0.6931$ | $|0.9163 - (-0.6931)| = \mathbf{1.6094}$ | No |
| **$(1, 3)$** | 3 | $3.00$ | $1.0986$ | $|0.9163 - 1.0986| = \mathbf{0.1823}$ | **YES (Optimal)** |
| **$(2, 2)$** | 4 | $1.00$ | $0.0000$ | $|0.9163 - 0.0000| = \mathbf{0.9163}$ | No |
| **$(1, 4)$** | 4 | $4.00$ | $1.3863$ | $|0.9163 - 1.3863| = \mathbf{0.4700}$ | No |

**Conclusion:**
The optimal grid is **$(1, 3)$** ($1 \text{ row} \times 3 \text{ columns} = 3 \text{ tiles}$), achieving minimum aspect ratio distortion ($0.1823$).
Total tiles fed to LLM: $1 \text{ Global Thumbnail} + 3 \text{ Local Tiles} = 4 \text{ tiles}$.

## 9. Production Gotchas, Do's and Don'ts

### The Image Size Coordinate Scaling Gotcha
- **Gotcha:** When prompting an MLLM to output bounding boxes, different visual tiles have different relative coordinate systems.
- **Remedy:** Always normalize coordinates to the **original uncropped image canvas** in range $[0, 1000]$. Never emit tile-local pixel offsets.

### The SigLIP Numerical Stability Trap
- **Gotcha:** If the learnable log-temperature $t$ in SigLIP is unconstrained, $e^t$ can grow past $100.0$, causing $\sigma(z_{ij})$ to saturate to exact $0.0$ or $1.0$ in FP16/BF16, resulting in zero gradients or NaN overflow.
- **Remedy:** Clamp the temperature scale $e^t \le 50.0$ or parameterize with an upper saturation ceiling.

### The Aspect Ratio Distortion Trap
- **Gotcha:** Bilinearly interpolating non-square aspect ratios (e.g. $10:1$ barcode or horizontal banner) into square tiles before AnyRes causes severe character merging.
- **Remedy:** Enforce reflection or black-padding to preserve native pixel aspect ratios prior to tile cropping.
