## 1. Canonical Motivation & Theoretical Foundation

### 1.1 The Generative AI Security & Data Egress Dilemma
Enterprises seeking to leverage Large Language Models (LLMs) and vector search for internal analytics traditionally encountered crippling architectural and governance hurdles:
* **Data Sovereignty Breaches**: Sending proprietary enterprise data to external third-party REST APIs (e.g., commercial LLM endpoints) risks exposing confidential IP and customer PII, frequently violating HIPAA, GDPR, and SOC2 requirements.
* **Complex Infrastructure Footprint**: Setting up self-hosted vector databases (Milvus, Pinecone, Qdrant), GPU clusters, and LangChain orchestration pipelines introduces substantial operational overhead, synchronicity issues, and security boundaries.
* **Loss of Governance**: When data leaves the warehouse for an external vector database, dynamic data masking, row-level security (RLS), and RBAC permissions are stripped away.

### 1.2 The Snowflake Cortex AI Thesis
Snowflake **Cortex AI** unifies state-of-the-art Generative AI, foundational LLMs, and dense vector search directly within the Snowflake governance boundary:
* Foundational models (Meta Llama 3, Mistral Large, Snowflake Arctic, Google Gemma) run on Snowflake-managed serverless GPU infrastructure colocated with the data.
* AI operations are invoked directly via **declarative SQL functions** (`SNOWFLAKE.CORTEX.COMPLETE()`, `EMBED_TEXT_768()`, `SUMMARIZE()`).
* Queries adhere 100% to existing Role-Based Access Control and Row Access Policies. No data ever leaves the secure Snowflake perimeter.

## 3. Vector Embeddings, Vector Data Type & Cortex Search

### 3.1 The First-Class `VECTOR` Type
Snowflake includes a native high-performance data type for semantic vector storage:
* `VECTOR(FLOAT, 768)` or `VECTOR(FLOAT, 1024)`.
* Vectors are stored as dense binary arrays inside standard micro-partitions, benefiting from the same compression, caching, and encryption as relational columns.
* **Vector Distance Primitives**:
  * `VECTOR_COSINE_SIMILARITY(v1, v2)`: Returns cosine similarity between two vectors $[-1.0, 1.0]$.
  * `VECTOR_L2_DISTANCE(v1, v2)`: Computes Euclidean distance.
  * `VECTOR_INNER_PRODUCT(v1, v2)`: Computes dot product.

### 3.2 Cortex Search Service: Hybrid Lexical + Vector Search
While raw vector distance queries work for ad-hoc exploration, high-concurrency production RAG systems require more than pure vector similarity. Pure vector search struggles with keyword precision (e.g., looking up exact serial numbers like `"SKU-9941-X"`).

**Cortex Search** provides a fully managed, serverless search engine combining:
1. **Dense Vector Search**: Deep semantic matching powered by neural embeddings.
2. **Sparse Lexical Search**: BM25 keyword matching for exact acronyms, numbers, and identifiers.
3. **Automated Continuous Indexing**: Automatically synchronizes with the source table as new micro-partitions arrive.
4. **Governed Security**: Prunes search results dynamically according to caller permissions.

## 5. Annotated Implementation: Production RAG Support Intelligence Lakehouse

Below is the complete end-to-end architecture: ingesting raw support conversations, extracting sentiment and vector embeddings, indexing into Cortex Search, and serving answers via a Retrieval-Augmented Generation (RAG) assistant.

```sql
-- ============================================================================
-- STEP 1: BRONZE UNSTRUCTURED SUPPORT LOGS & SILVER CORTEX ENRICHMENT
-- ============================================================================
USE ROLE DATA_ENGINEER;
USE DATABASE db_analytics_prod;
CREATE SCHEMA IF NOT EXISTS db_analytics_prod.cortex_ai;
USE SCHEMA db_analytics_prod.cortex_ai;

-- Raw ticket interactions table
CREATE OR REPLACE TABLE raw_customer_tickets (
    ticket_id VARCHAR(64) PRIMARY KEY,
    customer_id BIGINT,
    interaction_timestamp TIMESTAMP_NTZ,
    transcript_text TEXT
);

-- Populate baseline sample ticket data
INSERT INTO raw_customer_tickets VALUES
('TCK-101', 8810, '2026-03-01 10:15:00', 
 'The user reported that error code ERR-804 occurred during checkout when using PayPal. The transaction timed out after 30 seconds.'),
('TCK-102', 4402, '2026-03-01 11:30:00', 
 'Customer is requesting a refund for subscription Renewal-99. They find the enterprise pricing too steep but love the analytics UI.'),
('TCK-103', 1904, '2026-03-02 09:00:00', 
 'Critical latency alert: Snowpipe streaming channels in us-east-1 are experiencing backpressure. Latency increased from 2s to 45s.');

-- ============================================================================
-- STEP 2: ENRICHMENT WITH CORTEX SENTIMENT & DENSE EMBEDDINGS
-- ============================================================================
CREATE OR REPLACE TABLE silver_enriched_tickets AS
SELECT 
    ticket_id,
    customer_id,
    transcript_text,
    -- Serverless sentiment analysis (-1.0 to +1.0)
    SNOWFLAKE.CORTEX.SENTIMENT(transcript_text) AS sentiment_score,
    -- Automated executive summarization
    SNOWFLAKE.CORTEX.SUMMARIZE(transcript_text) AS executive_summary,
    -- Generate 768-dimensional dense vector embeddings
    SNOWFLAKE.CORTEX.EMBED_TEXT_768('snowflake-arctic-embed-m', transcript_text) AS text_embedding
FROM raw_customer_tickets;

-- Inspect enriched table
SELECT ticket_id, sentiment_score, executive_summary FROM silver_enriched_tickets;

-- ============================================================================
-- STEP 3: CONFIGURE CORTEX SEARCH SERVICE (HYBRID SEMANTIC SEARCH)
-- ============================================================================
CREATE OR REPLACE CORTEX SEARCH SERVICE support_ticket_search_service
  ON transcript_text
  ATTRIBUTES customer_id, ticket_id
  WAREHOUSE = WH_PROD_INGESTION_L
  TARGET_LAG = '1 HOUR'
  AS (
    SELECT 
        ticket_id,
        customer_id,
        transcript_text
    FROM silver_enriched_tickets
  );

-- ============================================================================
-- STEP 4: GOVERNED RAG PIPELINE EXECUTED VIA CORTEX COMPLETE()
-- ============================================================================
-- In modern Snowflake, RAG can be executed entirely via SQL using CTEs and Vector Similarity!

WITH query_input AS (
    SELECT 'How do I resolve PayPal checkout timeout ERR-804?' AS user_prompt,
           SNOWFLAKE.CORTEX.EMBED_TEXT_768('snowflake-arctic-embed-m', 'How do I resolve PayPal checkout timeout ERR-804?') AS prompt_vector
),
semantic_retrieval AS (
    SELECT 
        t.ticket_id,
        t.transcript_text,
        VECTOR_COSINE_SIMILARITY(t.text_embedding, q.prompt_vector) AS similarity_score
    FROM silver_enriched_tickets t, query_input q
    ORDER BY similarity_score DESC
    LIMIT 2
),
context_assembly AS (
    SELECT 
        LISTAGG(CONCAT('--- TICKET ID: ', ticket_id, ' ---\n', transcript_text), '\n\n') AS context_corpus
    FROM semantic_retrieval
)
SELECT 
    SNOWFLAKE.CORTEX.COMPLETE(
        'llama3-70b',
        CONCAT(
            'You are a senior technical support engineer. Answer the user question based strictly on the retrieved context below.\n\n',
            'CONTEXT:\n',
            c.context_corpus,
            '\n\nUSER QUESTION:\n',
            q.user_prompt,
            '\n\nANSWER:'
        )
    ) AS rag_response
FROM context_assembly c, query_input q;
```

## 6. Authoritative Gotchas, Pitfalls & Performance Anti-Patterns

### Anti-Pattern 1: Unbounded Context Token Burn in `CORTEX.COMPLETE()`
* **Problem**: Running `SNOWFLAKE.CORTEX.COMPLETE()` across a table containing 1,000,000 rows, passing an un-chunked 50-page PDF text string into every row's prompt.
* **Mechanism**: Cortex AI LLM functions are billed based on **tokens processed** (prompt tokens + completion tokens). Passing millions of tokens across hundreds of thousands of rows will consume thousands of credits in minutes, triggering emergency FinOps resource monitor suspensions.
* **Production Rule**:
  * Always pre-chunk text documents into semantic passages of **256 to 512 tokens**.
  * Use **Cortex Search** or vector similarity to retrieve only the top 3–5 relevant passages before invoking `CORTEX.COMPLETE()`.
  * Never invoke LLM generation directly inside unconstrained batch scans.

### Anti-Pattern 2: Mismatched Vector Dimensionality
* **Problem**: Generating embeddings with `EMBED_TEXT_768()` (768 dimensions), but defining the destination column as `VECTOR(FLOAT, 1024)` or comparing with a query embedding produced by a different model (e.g., 1536-dimensional Ada-002).
* **Mechanism**: Snowflake's type system strictly checks vector lengths. Attempting to compute `VECTOR_COSINE_SIMILARITY()` across vectors with different dimension sizes fails at runtime with a fatal vector dimensionality mismatch exception.
* **Production Rule**: Standardize on a single embedding model family across the entire lakehouse (e.g., `snowflake-arctic-embed-m` with 768 dimensions), and enforce matching type constraints across all schema DDL.

### Anti-Pattern 3: Non-Deterministic Output in Deterministic Pipelines
* **Problem**: Relying on raw `CORTEX.COMPLETE()` output to populate a relational column expected to contain strict categorical values (`'HIGH'`, `'MEDIUM'`, `'LOW'`).
* **Mechanism**: LLMs are probabilistic by default. While you may instruct the model to "Return only HIGH, MEDIUM, or LOW", the model might occasionally respond with: `"Sure! Here is the category: High."` This breaks downstream SQL joins, casts, and reporting constraints.
* **Production Rule**:
  * Utilize structured JSON prompting instructions:
    `"Respond ONLY with a valid JSON object of the form: {\"sentiment\": \"HIGH\"}"`
  * Parse the response with `PARSE_JSON()` and validate fields defensively using `TRY_CAST()`.

### Anti-Pattern 4: Bypassing Snowflake Governance with External LLM APIs
* **Problem**: Extracting customer interaction data to an external Python microservice running on AWS Lambda to call third-party OpenAI endpoints.
* **Mechanism**: Bypasses all Snowflake security controls. The external Lambda service must be granted wide read permissions, breaking Row Access Policies, exposing unmasked PII over public internet gateways, and violating data residency guarantees.
* **Production Rule**: Keep the entire AI lifecycle inside Snowflake Cortex. Sensitive customer records never leave the VPC/VNet, access remains bounded by RBAC, and all prompt interactions are recorded in the audit log.
