## 1. Theoretical Motivation: Metaprogramming at Definition Time

In *Fluent Python*, Luciano Ramalho emphasizes that a decorator is fundamentally **syntactic sugar** for higher-order function composition:

```python
@decorate
def target():
    ...

# Translates directly into:
def target():
    ...
target = decorate(target)
```

A decorator is a callable that takes another function as an argument, performs arbitrary processing (registration, instrumentation, validation, memoization), and returns either the original function or a replacement wrapper function.

### 1.1 The Crucial Insight: When Decorators Run
Decorators run **at import time** (when the module is loaded and the function is defined), **not** when the decorated function is called!

```python
registry = []

def register(func):
    print(f"Running register on {func.__name__} (IMPORT TIME!)")
    registry.append(func)
    return func # Returns unchanged original function

@register
def f1():
    print("Running f1() (RUNTIME!)")

# Output during module import:
# Running register on f1 (IMPORT TIME!)
```
This import-time execution makes decorators ideal for registry patterns (like Flask routes `@app.route()`, plug-in architectures, and CLI command dispatchers).

## 2. Underlying Architecture & `functools.wraps`

When a decorator replaces an original function with a wrapper function, the decorated function's metadata (`__name__`, `__doc__`, `__annotations__`) is accidentally erased and replaced by the wrapper's metadata.

```
Without functools.wraps:
f.__name__  ==> 'wrapper'
f.__doc__   ==> None (Documentation destroyed!)
inspect.signature(f) ==> (*args, **kwargs) (Type hints lost!)

With functools.wraps:
f.__name__  ==> 'f'
f.__doc__   ==> 'Original docstring preserved'
f.__wrapped__ ==> Pointer to raw unwrapped original function
```

### 2.1 The `functools.wraps` Mechanism
`functools.wraps` copies attributes defined in `functools.WRAPPER_ASSIGNMENTS` (`__module__`, `__name__`, `__qualname__`, `__doc__`, `__annotations__`) and updates `__dict__` from the inner function.

```python
import functools
import time

def clock(func):
    @functools.wraps(func) # Preserves function signature and metadata!
    def clocked(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - t0
        name = func.__name__
        arg_str = ", ".join(repr(arg) for arg in args)
        print(f"[{elapsed:0.8f}s] {name}({arg_str}) -> {result!r}")
        return result
    return clocked
```

```python
@clock
def factorial(n: int) -> int:
    """Computes factorial of n recursively."""
    return 1 if n < 2 else n * factorial(n - 1)

print(factorial(4))
print("Function Name:", factorial.__name__) # factorial (Preserved!)
print("Docstring:", factorial.__doc__)         # Computes factorial... (Preserved!)

# Accessing the raw unwrapped function:
unwrapped_fn = factorial.__wrapped__
print(unwrapped_fn(4)) # Computes directly without clock output!
```

## 3. Parameterized Decorators (Decorator Factories)

What if you want your decorator to accept arguments (e.g., `@repeat(num_times=3)`)?
A decorator that accepts arguments is **not** a decorator—it is a **Decorator Factory** that returns the actual decorator!

```
User Syntax: @repeat(num_times=3)
                   |
                   v
Step 1: factory = repeat(num_times=3)  ---> Returns actual decorator
Step 2: func = factory(func)           ---> Returns clocked wrapper
```

```python
import functools

def repeat(num_times: int = 2):
    """Decorator factory that invokes a function multiple times."""
    def decorator_repeat(func):
        @functools.wraps(func)
        def wrapper_repeat(*args, **kwargs):
            result = None
            for _ in range(num_times):
                result = func(*args, **kwargs)
            return result
        return wrapper_repeat
    return decorator_repeat
```

```python
@repeat(num_times=3)
def greet(name: str):
    print(f"Hello, {name}!")

greet("Alice")
# Output:
# Hello, Alice!
# Hello, Alice!
# Hello, Alice!
```

## 4. Classes as Decorators: Stateful Wrappers

When a decorator needs to maintain persistent internal state (such as call frequency, cache hits, or rate limits), implementing the decorator as a **class** with `__call__` is often cleaner than nesting multiple closure layers:

```python
import functools

class CallCounter:
    def __init__(self, func):
        self.func = func
        self.count = 0
        functools.update_wrapper(self, func) # Preserve metadata on class instance

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"Call {self.count} to {self.func.__name__}")
        return self.func(*args, **kwargs)
```

```python
@CallCounter
def process_data(x):
    return x * 2

print(process_data(5)) # Call 1 to process_data -> 10
print(process_data(8)) # Call 2 to process_data -> 16
print(process_data.count) # 2 (Inspect live state directly!)
```

## 5. Stacking Multiple Decorators

When stacking multiple decorators, they evaluate **bottom-up**:

```python
@decA
@decB
@decC
def target():
    pass

# Is exactly equivalent to:
target = decA(decB(decC(target)))
```

Execution order:
1. `decC` runs first at import time, wrapping `target`.
2. `decB` runs second, wrapping `decC`'s return value.
3. `decA` runs third, wrapping `decB`'s return value.
4. When `target()` is called at runtime, the code inside `decA` runs first, delegating down to `decB`, then `decC`, then the real `target`.

## 6. Authoritative Gotchas & Traps (Ramalho & Lutz)

### 6.1 The Disappearing Return Value Trap
```python
# DISASTROUS BUG:
def audit(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        func(*args, **kwargs) # Forgot to return result!
    return wrapper

@audit
def get_user_id():
    return 42

print(get_user_id()) # Prints: None !
```
Always assign `result = func(*args, **kwargs)` and explicitly `return result`.

### 6.2 Decorating Class Methods: The Missing `self`
When writing decorators meant for both regular functions and instance methods, always use `*args, **kwargs`. For an instance method, `args[0]` will automatically be the bound `self` instance. If your wrapper hardcodes specific parameters, decorating instance methods will raise `TypeError: missing required argument 'self'`.

## 7. Actionable Summary Checklist

- [x] Decorator code runs **at import time** when the module is loaded; wrapper code runs **at runtime** when the function is invoked.
- [x] **Always** decorate inner wrapper functions with `@functools.wraps(func)` to preserve docstrings, type annotations, and function names.
- [x] Parameterized decorators require **three levels** of nesting: Outer Factory $\to$ Decorator $\to$ Inner Wrapper.
- [x] Use `__wrapped__` to bypass decorator wrappers for unit testing or profiling raw functions.
- [x] Always capture and return the return value of the wrapped function inside your wrapper.
