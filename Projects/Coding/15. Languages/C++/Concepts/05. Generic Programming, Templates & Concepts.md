# C++ Concepts: Generic Programming, Templates & Concepts

**Foundational Texts:**  
- *The C++ Programming Language (4th Ed.)* by Bjarne Stroustrup, Chapters 23–29  
- *A Tour of C++ (3rd Ed.)* by Bjarne Stroustrup, Chapter 6: Concepts  

---

## 1. Theoretical Motivation: Compile-Time Static Polymorphism

In *The C++ Programming Language*, Bjarne Stroustrup contrasts two paradigms of polymorphism:
1. **Dynamic Polymorphism (Virtual Functions):** Bounded by base classes, resolved at runtime via `vtable` pointers, unable to be inlined, incurs pointer indirection.
2. **Static Polymorphism (Templates):** Parameterized types resolved entirely at **compile time**, zero runtime indirection, enables maximum optimizer inlining, and enforces static duck typing ("if it walks like a duck and quacks like a duck, it compiles").

```
                      [ Template Definition: min(T a, T b) ]
                                        |
                 +----------------------+----------------------+
                 | Instantiated with int                       | Instantiated with double
                 v                                             v
        [ min(int, int) Assembly ]                    [ min(double, double) Assembly ]
     Zero runtime overhead. Direct ALU registers!  Zero runtime overhead. Direct FPU registers!
```

## 2. Underlying Architecture: The Template Compilation Model

Unlike regular functions whose compiled object code lives in `.o` translation units, templates **must reside in header files (`.h` / `.hpp`)**.

### 2.1 Two-Phase Name Lookup
When the compiler encounters a template:
- **Phase 1 (Definition Time):** Non-dependent names (names that do not depend on template parameters) are parsed and type-checked immediately.
- **Phase 2 (Instantiation Time):** Dependent names (names that depend on `T`) are evaluated only when the template is instantiated with a concrete type.

```cpp
template <typename T>
void process(T& container) {
    // DEPENDENT TYPE: The compiler doesn't know if 'iterator' is a type or static field!
    // You MUST prefix dependent types with 'typename':
    typename T::iterator it = container.begin();
}
```

## 3. Variadic Templates & Fold Expressions (C++11 / C++17)

Variadic templates accept an arbitrary number of arguments using **parameter packs**:

```cpp
// Base case:
void print() { std::cout << '\n'; }

// Recursive Variadic Unpacking (C++11):
template <typename Head, typename... Tail>
void print(Head head, Tail... tail) {
    std::cout << head << " ";
    print(tail...); // Recursive pack expansion
}
```

### 3.1 Modern C++17 Fold Expressions:
Eliminates recursive template instantiation boilerplate by reducing packs using binary operators:

```cpp
// 1. Unary Left Fold: (... + args) => ((arg1 + arg2) + arg3)
template <typename... Args>
auto sum(Args... args) {
    return (... + args);
}

// 2. Binary Fold over comma operator:
template <typename... Args>
void printAll(const Args&... args) {
    ((std::cout << args << " "), ...) << '\n';
}

std::cout << sum(1, 2, 3, 4, 5); // Prints 15!
printAll("C++", 20, "is", "powerful");
```

## 4. The SFINAE Era vs. Modern C++20 Concepts

Prior to C++20, constraining template arguments relied on **SFINAE** (*Substitution Failure Is Not An Error*) via `std::enable_if_t`:

```cpp
// The Painful SFINAE Era (Cryptic, unreadable 10-page compiler errors):
template <typename T, 
          typename = std::enable_if_t<std::is_integral_v<T>>>
void calculate(T val) { ... }
```

### 4.1 Modern C++20 Concepts: Clean Semantic Constraints
Bjarne Stroustrup called Concepts **the single most important addition to modern C++**:

```cpp
#include <concepts>

// 1. Using Standard Library Concepts directly:
template <std::integral T>
T gcd(T a, T b) {
    while (b != 0) {
        T temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}

// 2. The 'requires' clause syntax:
template <typename T>
    requires std::floating_point<T>
T square_root(T val) {
    return std::sqrt(val);
}

// 3. Terse syntax (C++20 auto concept):
void logNumeric(std::integral auto val) {
    std::cout << "Integer value: " << val << '\n';
}
```

### 4.2 Authoring Custom Concepts
```cpp
// Define a concept: T must be serializable to string and hashable
template <typename T>
concept PrintableAndHashable = requires(T a) {
    { std::to_string(a) } -> std::same_as<std::string>;
    { std::hash<T>{}(a) } -> std::convertible_to<std::size_t>;
};
```

If a candidate calls `gcd(3.14, 2.71)`, the C++20 compiler produces an exact, one-line diagnostic:
`Error: deduced type 'double' does not satisfy concept 'std::integral'`.

## 5. Authoritative Gotchas & Traps (Stroustrup & Meyers)

### 5.1 Function Template Partial Specialization is ILLEGAL
```cpp
template <typename T, typename U>
void process(T a, U b);

// COMPILE ERROR! C++ does NOT permit partial specialization of function templates!
// template <typename T>
// void process<T, int>(T a, int b);
```
**The Solution:** Use **Function Overloading** or delegate to a helper struct (struct templates can be partially specialized):
```cpp
template <typename T>
void process(T a, int b); // Legal overload!
```

### 5.2 Template Code Bloat
Because the compiler generates distinct machine code for every type instantiated:
`std::vector<int>`, `std::vector<long>`, `std::vector<double>`, and `std::vector<Widget*>` each generate independent binary machine instructions, swelling executable file sizes.  
**Best Practice:** Thin template wrappers that delegate to void-pointer implementations for pointer types (`Widget*`, `User*`).

## 6. Actionable Summary Checklist

- [x] Use templates for zero-cost static compile-time polymorphism rather than runtime virtual tables.
- [x] Constrain template arguments using **C++20 Concepts** (`std::integral`, `std::invocable`) rather than legacy SFINAE `enable_if`.
- [x] Use modern **fold expressions** (`(... + args)`) in C++17 to eliminate recursive variadic boilerplate.
- [x] Always prefix dependent types with `typename` inside template definitions.
- [x] Never attempt to partially specialize function templates; use function overloading instead.
