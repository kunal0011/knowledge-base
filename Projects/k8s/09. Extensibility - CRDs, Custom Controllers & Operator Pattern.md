# Chapter 09: Kubernetes Extensibility — CRDs, Custom Controllers & The Operator Pattern

> "The Operator pattern encapsulates operational domain knowledge (deploying, scaling, backing up, failover, and upgrading stateful applications) into autonomous, self-healing software running directly inside the cluster."  
> — *Michael Hausenblas & Stefan Schimanski, Programming Kubernetes*

---

## 🧩 1. The Extensible Platform Architecture

Kubernetes is not merely an orchestrator for containers; it is a distributed, extensible operating system. By pairing **Custom Resource Definitions (CRDs)** with the **Operator Pattern**, engineers extend the Kubernetes API with domain-specific abstractions (e.g., `PostgresCluster`, `KafkaTopic`, `VaultSecret`).

```text
===================================================================================================
                                  THE OPERATOR PATTERN TRIANGLE
===================================================================================================

                               ┌───────────────────────────┐
                               │ Custom Resource Definition│
                               │   (Schema in etcd)        │
                               └─────────────┬─────────────┘
                                             │ Defines API schema
                                             ▼
  ┌───────────────────────────┐  Declares   ┌───────────────────────────┐
  │         Engineer          │────────────►│      Custom Resource      │
  │     (kubectl apply)       │   Desired   │ (e.g., PostgresCluster)   │
  └───────────────────────────┘    State    └─────────────┬─────────────┘
                                                          │ Observed by
                                                          ▼
                                            ┌───────────────────────────┐
                                            │     Custom Controller     │
                                            │      (Go Operator)        │
                                            └─────────────┬─────────────┘
                                                          │
                                                          ▼ Reconciles to
                                            ┌───────────────────────────┐
                                            │    Actual Infrastructure  │
                                            │  (Pods, PVs, AWS RDS, S3) │
                                            └───────────────────────────┘
```

## 📜 2. Custom Resource Definitions (CRDs) Deep Dive

A CRD registers a new REST endpoint on the `kube-apiserver`. 

### Production CRD Example with Validation and Subresources
```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: databases.database.acme.com
spec:
  group: database.acme.com
  names:
    kind: Database
    listKind: DatabaseList
    plural: databases
    singular: database
    shortNames:
      - db
  scope: Namespaced
  versions:
    - name: v1alpha1
      served: true
      storage: true
      subresources:
        status: {} # Enables status-only updates without incrementing generation
        scale:
          specReplicasPath: .spec.replicas
          statusReplicasPath: .status.replicas
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              required: ["engine", "storageSizeGi"]
              properties:
                engine:
                  type: string
                  enum: ["postgres", "mysql"]
                storageSizeGi:
                  type: integer
                  minimum: 10
                  maximum: 1000
                replicas:
                  type: integer
                  minimum: 1
                  default: 1
            status:
              type: object
              properties:
                phase:
                  type: string
                connectionEndpoint:
                  type: string
```

## ⚙️ 3. Inside `client-go`: The Controller Machinery Architecture

To write high-performance controllers that don't overwhelm the API server, Kubernetes uses the `client-go` caching and queuing architecture:

```text
===================================================================================================
                                 client-go CONTROLLER PIPELINE
===================================================================================================

       kube-apiserver
             │
             │ HTTP/2 Watch Stream
             ▼
      ┌──────────────┐
      │  Reflector   │
      └──────┬───────┘
             │ Enqueues
             ▼
      ┌──────────────┐
      │  DeltaFIFO   │
      └──────┬───────┘
             │ Dequeues
             ▼
      ┌──────────────┐
      │   Informer   │──────────► Local In-Memory Cache (Indexer)
      └──────┬───────┘            - Avoids hammering API server with GET calls!
             │ Triggers Events (Add, Update, Delete)
             ▼
     ┌────────────────┐
     │ ResourceEventHandler
     └───────┬────────┘
             │ Enqueues Key ("namespace/name")
             ▼
     ┌────────────────┐
     │   WorkQueue    │ ◄─── Exponential backoff rate limiting
     └───────┬────────┘
             │ Workers pop keys
             ▼
     ┌────────────────┐
     │ Reconcile Loop │ ─── Checks Indexer, mutates cluster, updates Status
     └────────────────┘
```

### Key Controller Design Invariants:
1. **Level-Triggered, Not Edge-Triggered:** You cannot assume you will receive an event for every single state mutation. Your `Reconcile` function must look at the *current* state and compare it to the *desired* state, converging the system regardless of how many intermediate transitions occurred.
2. **Idempotence:** Running `Reconcile()` once, ten times, or a hundred times with no state changes must yield the identical outcome without side effects.
3. **Optimistic Concurrency Control:** When updating objects, Kubernetes verifies `metadata.resourceVersion`. If another controller modified the object in etcd concurrently, a `409 Conflict` is returned. The controller must requeue and retry on fresh data.

## 💻 4. Building Operators with Kubebuilder (Go Implementation)

The industry standard framework for developing operators is **Kubebuilder** (built on `controller-runtime`).

### Production Reconciliation Loop in Go
```go
package controllers

import (
	"context"
	"fmt"
	"time"

	appsv1 "k8s.io/api/apps/v1"
	corev1 "k8s.io/api/core/v1"
	"k8s.io/apimachinery/pkg/api/errors"
	metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
	"k8s.io/apimachinery/pkg/runtime"
	ctrl "sigs.k8s.io/controller-runtime"
	"sigs.k8s.io/controller-runtime/pkg/client"
	"sigs.k8s.io/controller-runtime/pkg/log"

	dbv1alpha1 "acme.com/api/v1alpha1"
)

// DatabaseReconciler reconciles a Database object
type DatabaseReconciler struct {
	client.Client
	Scheme *runtime.Scheme
}

// +kubebuilder:rbac:groups=database.acme.com,resources=databases,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups=database.acme.com,resources=databases/status,verbs=get;update;patch
// +kubebuilder:rbac:groups=apps,resources=statefulsets,verbs=get;list;watch;create;update;patch;delete

func (r *DatabaseReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
	logger := log.FromContext(ctx)

	// 1. Fetch the Database instance from local cache
	var db dbv1alpha1.Database
	if err := r.Get(ctx, req.NamespacedName, &db); err != nil {
		if errors.IsNotFound(err) {
			// Object was deleted; garbage collection cleans up child resources
			return ctrl.Result{}, nil
		}
		logger.Error(err, "Failed to fetch Database resource")
		return ctrl.Result{}, err
	}

	// 2. Define desired child StatefulSet
	desiredSts := r.constructStatefulSet(&db)

	// 3. Check if StatefulSet already exists
	var existingSts appsv1.StatefulSet
	err := r.Get(ctx, client.ObjectKeyFromObject(desiredSts), &existingSts)

	if errors.IsNotFound(err) {
		logger.Info("Creating child StatefulSet", "Namespace", desiredSts.Namespace, "Name", desiredSts.Name)
		if err := r.Create(ctx, desiredSts); err != nil {
			return ctrl.Result{}, err
		}
		return ctrl.Result{RequeueAfter: 5 * time.Second}, nil
	} else if err != nil {
		return ctrl.Result{}, err
	}

	// 4. Update Status if replicas match
	if existingSts.Status.ReadyReplicas == *db.Spec.Replicas {
		if db.Status.Phase != "Ready" {
			db.Status.Phase = "Ready"
			db.Status.ConnectionEndpoint = fmt.Sprintf("%s.%s.svc.cluster.local:5432", db.Name, db.Namespace)
			if err := r.Status().Update(ctx, &db); err != nil {
				return ctrl.Result{}, err
			}
		}
	}

	return ctrl.Result{}, nil
}

func (r *DatabaseReconciler) constructStatefulSet(db *dbv1alpha1.Database) *appsv1.StatefulSet {
	sts := &appsv1.StatefulSet{
		ObjectMeta: metav1.ObjectMeta{
			Name:      db.Name + "-backend",
			Namespace: db.Namespace,
		},
		Spec: appsv1.StatefulSetSpec{
			Replicas: db.Spec.Replicas,
			// Pod template, volumeClaimTemplates configured here...
		},
	}
	// Set Database instance as the owner and controller
	ctrl.SetControllerReference(db, sts, r.Scheme)
	return sts
}

// SetupWithManager sets up the controller with the Manager
func (r *DatabaseReconciler) SetupWithManager(mgr ctrl.Manager) error {
	return ctrl.NewControllerManagedBy(mgr).
		For(&dbv1alpha1.Database{}).
		Owns(&appsv1.StatefulSet{}). // Automatically requeue Database if its child StatefulSet changes!
		Complete(r)
}
```
