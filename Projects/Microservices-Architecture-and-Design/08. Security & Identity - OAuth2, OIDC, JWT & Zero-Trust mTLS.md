# Chapter 08: Security & Identity - OAuth2, OIDC, JWT & Zero-Trust mTLS

> "Never trust, always verify. In modern microservices, the perimeter has dissolved. Every service must verify the identity and authorization of every incoming request, whether originated by a mobile user or an adjacent internal pod."  
> — *Zero Trust Architecture (NIST SP 800-207)*

---

## 1. Canonical Motivation & Theoretical Foundation

### The Fallacy of Perimeter Security ("Castle and Moat")
Traditional monoliths relied on perimeter security: a firewall protected internal servers, and all internal network traffic was implicitly trusted. 

In a modern microservices architecture, this model fails catastrophically:
1. **Lateral Movement:** If an attacker breaches one internet-facing microservice (e.g. via an RCE vulnerability in an image processing pod), they can query any internal database or billing service without authentication.
2. **Ephemeral Containers & Dynamic IPs:** In Kubernetes, pods are continuously scheduled, destroyed, and reassigned IP addresses. Static IP whitelisting or network firewall rules are fragile and operationally unsustainable.
3. **Multi-Tenant / Multi-Cloud Topologies:** Traffic traverses internal VPC peering connections, service meshes, and third-party SaaS APIs.

### Zero-Trust Architecture (ZTA)
Under Zero-Trust principles:
- **No Implicit Trust:** Network locality does not imply trust. Internal network traffic is assumed to be hostile.
- **Mutual Authentication (mTLS):** Every inter-service connection must cryptographically authenticate both the client and server using short-lived X.509 certificates.
- **End-to-End Identity Context:** Requests carry verifiable cryptographic claims representing both the caller identity (User) and the calling service identity (Workload).

### Asymmetric JWT Verification & JWKS Key Rotation
To avoid distributing shared secrets across dozens of services, production microservices use **asymmetric encryption** (RS256 / ES256 / EdDSA):
- The **Identity Provider (IdP)** (e.g. Keycloak, Auth0, Okta) signs JWTs using its private key.
- Microservices fetch public keys from the IdP's JSON Web Key Set endpoint (`/.well-known/jwks.json`).
- Services verify JWT signatures locally in memory **without making a remote HTTP call to the IdP per request**.

## 3. Core Mechanics, Algorithms & Invariants

### Anatomy of a JSON Web Token (RFC 7519)
A JWT consists of three Base64URL-encoded strings separated by dots:
$$\text{JWT} = \text{Base64URL}(\text{Header}) \,.\, \text{Base64URL}(\text{Payload}) \,.\, \text{Signature}$$

```
1. Header:   {"alg": "RS256", "typ": "JWT", "kid": "key-2026-q1"}
2. Payload:  {
               "iss": "https://auth.company.com",
               "sub": "user_98213",
               "aud": "api://ecommerce-gateway",
               "exp": 1773662400,
               "nbf": 1773658800,
               "scope": "orders:write payments:read",
               "tenant_id": "corp_alpha"
             }
3. Signature: RSA-SHA256(Header + "." + Payload, PrivateKey)
```

> [!WARNING]
> **JWTs are encoded, NOT encrypted!** Anyone in possession of a JWT can decode the payload. Never store database passwords, credit card numbers, or PII within JWT claims unless using JWE (JSON Web Encryption).

### Stateless Revocation Dilemma & Mitigation Strategies
Because JWTs are self-contained and verified locally, revoking a compromised token before its expiration (`exp`) is a distributed consistency challenge:
1. **Short-Lived Access Tokens:** Keep JWT validity short (5 to 15 minutes). Use long-lived, revocable Refresh Tokens stored in the IdP.
2. **Distributed Revocation Blocklist:** When a user logs out, their token ID (`jti`) is written to an in-memory Redis cluster with a TTL matching the token's remaining lifespan. Services check Redis only for high-privilege operations.

## 4. Practical Systems & Production Engineering Trade-offs

| Strategy | Advantages | Disadvantages |
| :--- | :--- | :--- |
| **Edge Gateway Authentication** | Microservices are shielded from authentication complexity; simpler backend code. | Internal traffic remains unauthenticated if an attacker breaches the network internally. |
| **End-to-End JWT Propagation** | Every service enforces fine-grained authorization (ABAC/RBAC) with full user context. | High token parsing/validation overhead; large HTTP headers. |
| **Service Mesh mTLS (Istio / Linkerd)** | Zero application code changes; automatic cert rotation, SPIFFE identity, and wire encryption. | Extra latency hop per pod (Envoy sidecar); high memory consumption. |

### Java (Spring Boot 3 + Spring Security 6 Resource Server)
Declarative RS256 JWT validation and method-level Role-Based Access Control (RBAC).

```java
package com.example.security.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationConverter;
import org.springframework.security.oauth2.server.resource.authentication.JwtGrantedAuthoritiesConverter;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
@EnableWebSecurity
@EnableMethodSecurity(prePostEnabled = true)
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health").permitAll()
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth2 -> oauth2
                .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthenticationConverter()))
            );
        return http.build();
    }

    @Bean
    public JwtAuthenticationConverter jwtAuthenticationConverter() {
        JwtGrantedAuthoritiesConverter grantedAuthoritiesConverter = new JwtGrantedAuthoritiesConverter();
        grantedAuthoritiesConverter.setAuthorityPrefix("ROLE_");
        grantedAuthoritiesConverter.setAuthoritiesClaimName("roles");

        JwtAuthenticationConverter jwtConverter = new JwtAuthenticationConverter();
        jwtConverter.setJwtGrantedAuthoritiesConverter(grantedAuthoritiesConverter);
        return jwtConverter;
    }
}
```

### Go (Cloud-Native Go + JWT Parsing Middleware)
High-performance HTTP middleware validating asymmetric RSA JWTs and extracting claims into `context.Context`.

```go
package main

import (
	"context"
	"crypto/rsa"
	"fmt"
	"net/http"
	"strings"

	"github.com/golang-jwt/jwt/v5"
)

type UserContextKey string
const ContextUserKey UserContextKey = "currentUser"

type CustomClaims struct {
	TenantID string   `json:"tenant_id"`
	Roles    []string `json:"roles"`
	jwt.RegisteredClaims
}

// JWTMiddleware validates RS256 Bearer tokens
func JWTMiddleware(publicKey *rsa.PublicKey) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			authHeader := r.Header.Get("Authorization")
			if authHeader == "" || !strings.HasPrefix(authHeader, "Bearer ") {
				http.Error(w, "Missing or invalid authorization header", http.StatusUnauthorized)
				return
			}

			tokenString := strings.TrimPrefix(authHeader, "Bearer ")
			claims := &CustomClaims{}

			// Parse and verify token signature using IdP public key
			token, err := jwt.ParseWithClaims(tokenString, claims, func(t *jwt.Token) (interface{}, error) {
				if _, ok := t.Method.(*jwt.SigningMethodRSA); !ok {
					return nil, fmt.Errorf("unexpected signing algorithm: %v", t.Header["alg"])
				}
				return publicKey, nil
			})

			if err != nil || !token.Valid {
				http.Error(w, fmt.Sprintf("Unauthorized: %v", err), http.StatusUnauthorized)
				return
			}

			// Inject parsed claims into context
			ctx := context.WithValue(r.Context(), ContextUserKey, claims)
			next.ServeHTTP(w, r.WithContext(ctx))
		})
	}
}

// Protected HTTP Handler
func HandleCreateOrder(w http.ResponseWriter, r *http.Request) {
	claims, ok := r.Context().Value(ContextUserKey).(*CustomClaims)
	if !ok {
		http.Error(w, "User context missing", http.StatusInternalServerError)
		return
	}

	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, "Authenticated user %s for tenant %s", claims.Subject, claims.TenantID)
}
```

### Python (FastAPI + Asymmetric JWT Dependency Injection)
FastAPI security dependency validating JWT signatures, scopes, and token expiration.

```python
from fastapi import FastAPI, Depends, HTTPException, status, Security
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials, SecurityScopes
import jwt
from pydantic import BaseModel
from typing import List

app = FastAPI(title="Zero-Trust Protected Microservice")
security = HTTPBearer()

# Loaded at startup from IdP's /.well-known/jwks.json
PUBLIC_KEY_PEM = """-----BEGIN PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAu12...
-----END PUBLIC KEY-----"""

class AuthenticatedUser(BaseModel):
    user_id: str
    tenant_id: str
    scopes: List[str]

async def get_current_user(
    security_scopes: SecurityScopes,
    credentials: HTTPAuthorizationCredentials = Security(security)
) -> AuthenticatedUser:
    token = credentials.credentials
    try:
        # Decode and cryptographically verify asymmetric signature
        payload = jwt.decode(
            token,
            PUBLIC_KEY_PEM,
            algorithms=["RS256"],
            audience="api://ecommerce-gateway",
            issuer="https://auth.company.com"
        )
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Token expired")
    except jwt.InvalidTokenError as e:
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail=f"Invalid token: {str(e)}")

    token_scopes = payload.get("scope", "").split()
    # Verify required endpoint scopes
    for required_scope in security_scopes.scopes:
        if required_scope not in token_scopes:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail=f"Not enough permissions: Missing {required_scope}"
            )

    return AuthenticatedUser(
        user_id=payload.get("sub"),
        tenant_id=payload.get("tenant_id"),
        scopes=token_scopes
    )

@app.post("/orders")
async def create_order(
    user: AuthenticatedUser = Security(get_current_user, scopes=["orders:write"])
):
    return {
        "status": "Order created",
        "user_id": user.user_id,
        "tenant_id": user.tenant_id
    }
```

## 6. Authoritative Gotchas, Pitfalls, Concurrency Anomaly Edge Cases & Outage Triage

### 1. The Algorithm Confusion Attack (`"alg": "none"`)
- **The Pitfall:** In poorly configured JWT decoders, an attacker submits a token with `{"alg": "none"}` in the header and omits the signature entirely. If the verification library accepts unsigned tokens by default, the attacker can forge arbitrary administrator tokens.
- **Remediation:** Explicitly enforce `algorithms=["RS256"]` in the JWT parser; never rely on the incoming token's header to select the algorithm.

### 2. JWKS Endpoint Failure & Cascading Auth Blackout
- **The Pitfall:** If microservices fetch keys synchronously from the IdP's `/.well-known/jwks.json` endpoint on every request, an IdP slowdown will freeze all microservices across the fleet.
- **Remediation:** Cache JWKS keys in memory with a stale-while-revalidate strategy (e.g. cache for 24 hours, refresh asynchronously).

### 3. Clock Skew Authentication Rejections
- **The Pitfall:** If the host clock on Service A is 3 seconds ahead of the Identity Provider, newly issued tokens will be rejected with `Token not yet valid (nbf error)`.
- **Remediation:** Synchronize all server clocks using NTP and configure a **leeway** of 30 to 60 seconds in JWT verification libraries.
