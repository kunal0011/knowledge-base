## 🏛️ 1. Public Key Infrastructure (PKI) & X.509 Trust Chains

Asymmetric cryptography requires a mechanism to cryptographically bind a public key to an entity's real-world identity. Without this, an adversary executes a trivial Man-in-the-Middle (MitM) substitution attack.

```text
===================================================================================================
                                   X.509 CERTIFICATE CHAIN OF TRUST
===================================================================================================

  [ Root Certificate Authority (CA) ]
  - e.g., Let's Encrypt Root X1, DigiCert
  - Self-Signed: Signs its own public key
  - Pre-installed in OS / Browser Trust Store (/etc/ssl/certs)
           │
           ▼ Cryptographically signs Intermediate Certificate
  [ Intermediate CA ]
  - Kept online to issue daily certificates while Root CA is locked in an offline safe
           │
           ▼ Cryptographically signs Leaf Certificate
  [ Leaf / End-Entity Certificate ]
  - Subject: *.production.com
  - Subject Alternative Name (SAN): api.production.com
  - Server Public Key: 256-bit ECDSA
```

### 1.1 Anatomy of an X.509 v3 Certificate
Defined in RFC 5280, a certificate contains:
1. **Subject:** The entity name and domain (`CN=api.production.com`).
2. **Subject Alternative Name (SAN):** List of authorized domain names.
3. **Subject Public Key Info:** The algorithm (e.g., ECDSA P-256) and the raw public key.
4. **Validity Window:** `NotBefore` and `NotAfter` timestamps.
5. **Basic Constraints:** `CA:FALSE` (ensures a web server cannot act as a rogue CA to sign certificates for other domains!).
6. **Digital Signature:** Computed by the issuing CA over all preceding fields.

---

### 1.2 Revocation: CRL, OCSP & OCSP Stapling
If a company's private key is leaked, the certificate must be revoked before its expiration date:
- **CRL (Certificate Revocation List):** A periodic list of revoked serial numbers downloaded by clients (slow and bandwidth-heavy).
- **OCSP (Online Certificate Status Protocol):** Client queries the CA in real time: *"Is certificate #1234 revoked?"* (Privacy disaster: the CA learns every website the user visits!).
- **OCSP Stapling (RFC 6066):** The web server periodically queries the CA, obtains a time-stamped, cryptographically signed OCSP proof, and "staples" it directly into the TLS handshake. Fast, private, and offline-resilient!

## 🔑 2. Shamir's Secret Sharing ($k$-of-$n$ Threshold Cryptography)

How can an organization store a master encryption key or a nuclear launch code such that no single person can use it alone, but any $k$ executives can reconstruct it?

In 1979, Adi Shamir designed **Shamir's Secret Sharing**, based on a fundamental theorem of algebra:
> *"A polynomial of degree $k - 1$ is uniquely determined by any $k$ distinct points."*

```text
===================================================================================================
                       SHAMIR'S SECRET SHARING (2-OF-3 THRESHOLD POLYNOMIAL)
===================================================================================================

       y ▲
         │                       P(x) = S + a1 * x (Degree k-1 = 1: A Straight Line!)
         │
         │                                      ● Share 3 (3, P(3))
         │
         │                         ● Share 2 (2, P(2))
         │
         │            ● Share 1 (1, P(1))
         │
   Secret├───────● Secret S = P(0)
       S │
       ──┼───────┴────┴────────────┴────────────► x
         │       1    2            3
```

### 2.1 The Protocol Algorithm
1. Let the secret be an integer $S$. Choose a prime $p > S, n$.
2. To create a **$k$-of-$n$ scheme**, choose $k - 1$ random coefficients: $a_1, a_2, \dots, a_{k-1} \in \mathbb{F}_p$.
3. Form the polynomial of degree $k-1$:
   $$P(x) = S + a_1 x + a_2 x^2 + \dots + a_{k-1} x^{k-1} \pmod p$$
   *(Notice that $P(0) = S$)*.
4. Distribute $n$ shares to $n$ trustees: Share $i$ is the pair **$(i, P(i))$**.

### 2.2 Reconstruction via Lagrange Interpolation
Any $k$ participants pool their points $(x_1, y_1), \dots, (x_k, y_k)$ and reconstruct the secret $S = P(0)$:
$$S = \sum_{j=1}^k y_j \cdot \ell_j(0) \pmod p \quad \text{where } \ell_j(0) = \prod_{m \ne j} \frac{0 - x_m}{x_j - x_m} \pmod p$$

**Information-Theoretic Security:** Any collection of $k - 1$ or fewer participants learns **mathematically zero information** about the secret $S$. For any possible secret $S'$, there exists a unique polynomial passing through the $k-1$ points!

## 🎭 3. Zero-Knowledge Proofs (ZKP)

A **Zero-Knowledge Proof** allows a Prover ($P$) to convince a Verifier ($V$) that a mathematical assertion is true, without revealing any confidential information beyond the validity of the assertion itself.

### 3.1 The Three Foundational Axioms of ZKP
1. **Completeness:** If the statement is true and both Prover and Verifier follow the protocol honestly, the Verifier will always be convinced.
2. **Soundness:** If the statement is false, no cheating Prover can convince the Verifier, except with a negligibly small probability ($P_{\text{cheat}} \le 2^{-\lambda}$).
3. **Zero-Knowledge:** If the statement is true, the Verifier learns nothing other than the fact that the statement is true (formalized via the existence of an algorithmic **Simulator**).

---

### 3.2 Schnorr's Identification Protocol (Proof of Discrete Log Knowledge)
Suppose Peggy knows a secret private key $x$ such that $y = g^x \bmod p$. Peggy wants to prove to Victor that she knows $x$, **without revealing $x$**!

```text
===================================================================================================
                               SCHNORR ZERO-KNOWLEDGE PROTOCOL
===================================================================================================

  Peggy (Prover)                                                    Victor (Verifier)
  Knows secret x such that y = g^x mod p                            Knows public y, g, p
  
  1. COMMITMENT:
     Picks random nonce r in Z_q
     Computes: R = g^r mod p
     │─────────────────────── Sends Commitment R ──────────────────►│
     │                                                              │
     │                                                              │ 2. CHALLENGE:
     │                                                              │    Picks random bit or
     │                                                              │    integer challenge c
     │◄────────────────────── Sends Challenge c ────────────────────│
     │                                                              │
  3. RESPONSE:                                                      │
     Computes: s = (r + c * x) mod q                                │
     │─────────────────────── Sends Response s ────────────────────►│
     │                                                              │
                                                                    4. VERIFICATION:
                                                                       Checks whether:
                                                                       g^s ≡ R * (y^c) (mod p)
                                                                       If equal, ACCEPTS!
```

#### Why Verification Works:
$$g^s = g^{r + c \cdot x} = g^r \cdot (g^x)^c = R \cdot y^c \pmod p$$

#### Why It is Zero-Knowledge:
Victor receives $(R, c, s)$. However, Victor could have simulated this exact transcript himself without Peggy: pick random $s$ and $c$, then calculate $R = g^s \cdot y^{-c} \bmod p$. Because the simulated transcript is mathematically indistinguishable from a real interaction, **Peggy revealed zero information about $x$!**

---

### 3.3 The Fiat-Shamir Heuristic (Non-Interactive ZKPs)
Interactive ZKPs require back-and-forth network round trips. The **Fiat-Shamir Heuristic** replaces the Verifier's random challenge $c$ with a cryptographic hash of the commitment:
$$c = H(g \mathbin{\Vert} y \mathbin{\Vert} R)$$
The proof becomes a self-contained pair **$(R, s)$** that anyone in the world can verify non-interactively! This is the direct mathematical foundation of **zk-SNARKs** and modern privacy blockchains.
