# 06. Security Hardening, XSS, CSRF & Enterprise CI-CD

Cross-Site Scripting (XSS), Server-Side Request Forgery (SSRF), secret leakage in client bundles, and Cross-Site Request Forgery (CSRF) must be mitigated with strict Content Security Policies, cryptographic nonces, and automated CI/CD guardrails."

## 1. Defending Against Server Action CSRF & Injection Attacks

Under the hood, every Server Action generates a hidden, publicly accessible POST endpoint (e.g., `POST /` with `Next-Action: <hash>`).

### 1.1 Next.js Built-In CSRF Protections
Next.js automatically compares the incoming HTTP `Origin` header against the `Host` header. If the origin does not match the server's domain, Next.js blocks the request with a `403 Forbidden`.

### 1.2 Enterprise Defense-in-Depth: Schema Validation & Authentication
Never assume a Server Action's input is valid just because client-side form validation passed. Always authenticate and validate via **Zod**:

```typescript
'use server';
import { z } from 'zod';
import { auth } from '@/lib/auth';
import { db } from '@/lib/db';

const CheckoutSchema = z.object({
  cartId: z.string().uuid(),
  paymentMethodId: z.string().min(5),
});

export async function processOrderAction(formData: FormData) {
  // 1. Enforce Authentication Check
  const session = await auth();
  if (!session?.userId) {
    throw new Error('Unauthorized: Authentication required');
  }

  // 2. Strict Input Sanitization & Validation
  const rawInput = {
    cartId: formData.get('cartId'),
    paymentMethodId: formData.get('paymentMethodId'),
  };

  const validation = CheckoutSchema.safeParse(rawInput);
  if (!validation.success) {
    return { error: 'Invalid input parameters', details: validation.error.flatten() };
  }

  const { cartId, paymentMethodId } = validation.data;

  // 3. Prevent Insecure Direct Object References (IDOR): Ensure cart belongs to current user!
  const cart = await db.carts.findFirst({
    where: { id: cartId, userId: session.userId },
  });
  if (!cart) {
    throw new Error('Cart not found or permission denied');
  }

  // 4. Execute transaction
  return { success: true, orderId: 'ORD-98765' };
}
```

## 2. Hardening Content Security Policy (CSP) with Nonces

A strict **Content Security Policy (CSP)** blocks inline script execution by malicious third parties.
Next.js supports **Cryptographic Nonces** generated dynamically per-request inside middleware:

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // Generate a cryptographically secure 16-byte random base64 nonce
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64');
  
  const cspHeader = `
    default-src 'self';
    script-src 'self' 'nonce-${nonce}' 'strict-dynamic';
    style-src 'self' 'nonce-${nonce}';
    img-src 'self' blob: data: https://images.enterprise.com;
    font-src 'self';
    object-src 'none';
    base-uri 'self';
    form-action 'self';
    frame-ancestors 'none';
  `.replace(/\s{2,}/g, ' ').trim();

  const requestHeaders = new Headers(request.headers);
  requestHeaders.set('x-nonce', nonce);
  requestHeaders.set('Content-Security-Policy', cspHeader);

  const response = NextResponse.next({
    request: {
      headers: requestHeaders,
    },
  });

  response.headers.set('Content-Security-Policy', cspHeader);
  return response;
}
```

## 3. Enterprise CI/CD Pipeline with GitHub Actions

Below is a production-grade GitHub Actions pipeline featuring ESLint, TypeScript type checking, Playwright end-to-end tests, and multi-stage Docker builds:

```yaml
name: Production Next.js CI/CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Type Check (tsc)
        run: npm run typecheck

      - name: Linting (ESLint)
        run: npm run lint

      - name: Run Unit Tests (Jest / Vitest)
        run: npm run test:unit

  e2e:
    needs: validate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
      - run: npm ci

      - name: Install Playwright Browsers
        run: npx playwright install --with-deps

      - name: Build Next.js Application
        run: npm run build
        env:
          DATABASE_URL: ${{ secrets.TEST_DATABASE_URL }}

      - name: Run E2E Playwright Tests
        run: npm run test:e2e

  deploy:
    needs: e2e
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to Vercel / Kubernetes Cluster
        run: echo "Triggering production deployment via webhook or Helm chart..."
```

## 4. Do's, Don'ts & Production Gotchas

| Category | Rule | Deep Technical Rationale |
| :--- | :--- | :--- |
| **DON'T** | Never prefix private API keys with `NEXT_PUBLIC_`. | Any variable prefixed with `NEXT_PUBLIC_` is inlined into the client-side JavaScript bundle during the build phase, exposing secret keys to anyone opening browser DevTools. |
| **DO** | Install and use the `server-only` package in all database and security files. | `import 'server-only'` throws a compile-time build failure if any file importing database connections or cryptographic keys is imported into a Client Component. |
| **GOTCHA** | `dangerouslySetInnerHTML` bypasses React's automatic string escaping. | If untrusted user input is passed directly to `dangerouslySetInnerHTML`, attackers can execute Cross-Site Scripting (XSS) attacks. Always sanitize HTML strings with **DOMPurify** before rendering. |
| **DO** | Set `X-Frame-Options: DENY` or `frame-ancestors 'none'` in your CSP. | Prevents clickjacking attacks by blocking malicious third-party websites from embedding your application inside hidden `<iframe>` tags. |
| **DON'T** | Avoid committing `.env` or `.env.local` files to Git repositories. | Add `.env*` to `.gitignore` and manage secrets using enterprise secret managers (Vercel Environment Variables, AWS Secrets Manager, Vault). |
