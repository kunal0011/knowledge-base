## 🧭 1. The Global Routing Hierarchy: Autonomous Systems (AS)

The Internet does not run a single flat routing algorithm across all 5 billion connected devices. A flat routing table would exceed hundreds of gigabytes, and a single link flap in Tokyo would force every router in London to recompute shortest paths.

The Internet is divided into $\approx 100,000$ independent networks called **Autonomous Systems (AS)**, identified by a unique **Autonomous System Number (ASN)** (e.g., Google is AS15169, Cloudflare is AS13335).

```text
===================================================================================================
                               INTERNET TWO-TIERED ROUTING HIERARCHY
===================================================================================================

  ┌────────────────────────────────────────┐       ┌────────────────────────────────────────┐
  │         Autonomous System 1 (AS 100)   │       │         Autonomous System 2 (AS 200)   │
  │                                        │       │                                        │
  │     [ Intra-AS: OSPF / IS-IS ]         │       │     [ Intra-AS: OSPF / IS-IS ]         │
  │   Interior Gateway Protocol (IGP)      │       │   Interior Gateway Protocol (IGP)      │
  │   Optimizes pure link latency/cost     │       │   Optimizes pure link latency/cost     │
  │                                        │       │                                        │
  │              [ Router A ]              │       │              [ Router B ]              │
  └───────────────────┬────────────────────┘       └───────────────────┬────────────────────┘
                      │                                                │
                      └───────────────────────►◄───────────────────────┘
                                       [ Inter-AS: BGP-4 ]
                                 Exterior Gateway Protocol (EGP)
                                 Governed by geopolitics & business contracts!
```

## 🔍 2. Link-State (LS) Routing & Dijkstra's Algorithm

In a **Link-State** protocol, every router floods the state of its directly connected links to **every other router in the network**. Each node builds an identical, complete mathematical graph $G = (V, E)$ of the entire network, then runs **Dijkstra's Shortest Path Algorithm** locally.

```text
===================================================================================================
                             DIJKSTRA'S SHORTEST PATH FLOW
===================================================================================================

  Given graph G=(V,E) with source node u:
  
  1. Initialization:
     N' = {u} (Set of settled nodes)
     For all v in V:
       D(v) = c(u, v) if directly adjacent, else INF
       p(v) = u
  
  2. Loop:
     Find node w NOT in N' such that D(w) is minimum.
     Add w to N'.
     For all neighbors v of w not in N':
       D(v) = min( D(v), D(w) + c(w, v) )
       If D(v) was updated: p(v) = w
     Repeat until N' contains all nodes in V!
```

### 2.1 Open Shortest Path First (OSPF - RFC 2328)
OSPF is the dominant enterprise Interior Gateway Protocol:
1. **Link-State Advertisements (LSAs):** Flooded reliably across routers over IP protocol `89` (no TCP/UDP overhead).
2. **Hierarchical Areas:** Large networks are partitioned into **Areas**. All areas must connect to the central **Backbone Area 0**. Routers only run Dijkstra within their local area, preventing link changes from triggering global CPU recalculations.

## 🔄 3. Distance-Vector (DV) Routing & The Bellman-Ford Equation

Unlike Link-State (where every router knows the entire global map), **Distance-Vector** algorithms are iterative, asynchronous, and distributed:
> *"Tell your neighbors about the entire world."*

### 3.1 The Bellman-Ford Optimality Equation
Let $d_x(y)$ be the cost of the least-cost path from node $x$ to node $y$:
$$d_x(y) = \min_{v \in \text{neighbors}} \left\{ c(x, v) + d_v(y) \right\}$$

Every router $x$ maintains a vector of distances to all destinations. Periodically, $x$ sends its distance vector to its immediate neighbors. When $x$ receives a vector from neighbor $v$, it updates its own table using Bellman-Ford.

---

### 3.2 The Count-to-Infinity Catastrophe & Poison Reverse
Distance-Vector protocols suffer from slow convergence when link costs increase, known as the **Count-to-Infinity Problem**:

```text
===================================================================================================
                                THE COUNT-TO-INFINITY ANOMALY
===================================================================================================

  Node A ──(cost 1)── Node B ──(cost 1)── Node C
  
  Suppose Link B-C breaks! (Cost becomes INF)
  1. Node B knows direct link to C is dead.
  2. But Node A had previously advertised: "I can reach C with cost 2".
  3. Node B falsely thinks: "I can reach C through Node A with cost 1 + 2 = 3!"
  4. Node B updates table and tells Node A: "My cost to C is 3".
  5. Node A thinks: "B's cost increased, so my cost is 1 + 3 = 4".
  6. Packets bounce endlessly between A and B in a routing loop, counting slowly up to infinity!
```

#### The Fix: Split Horizon with Poison Reverse
If Node $A$ routes traffic to destination $C$ through Node $B$, then Node $A$ explicitly lies to Node $B$, advertising its distance to $C$ as **$\infty$** ($d_A(C) = \infty$). This prevents Node $B$ from ever attempting to route back through $A$ to reach $C$!

## 🌍 4. Inter-Domain Routing: Border Gateway Protocol (BGP-4)

**BGP-4 (RFC 4271)** is the glue that holds the global Internet together. BGP is a **Path Vector** protocol: it does not optimize for the lowest mathematical link cost; it optimizes for **contractual business policies and geopolitical compliance**.

```text
===================================================================================================
                                       BGP AS-PATH ADVERTISEMENT
===================================================================================================

  [ AS 15169 (Google) ]
  Originates IP Prefix: 8.8.8.0/24
          │
          ▼ Advertises eBGP route: "8.8.8.0/24, AS-PATH: [15169]"
  [ AS 3356 (Lumen / Level 3 Transit) ]
          │
          ▼ Appends its own ASN to path:
  [ AS 13335 (Cloudflare) ]
  Receives: "8.8.8.0/24, AS-PATH: [3356, 15169]"
```

### 4.1 Loop Prevention via AS-PATH
If a router receives a BGP update whose `AS-PATH` attribute contains its **own ASN**, it immediately discards the update! This provides mathematically guaranteed loop detection across global networks.

### 4.2 BGP Route Selection Hierarchy
When a router learns multiple valid paths to the same prefix, it breaks ties using a strict, unyielding sequence of rules:
1. **Highest `LOCAL_PREF`:** Pure administrative preference (e.g., prefer cheap customer links over expensive provider links).
2. **Shortest `AS-PATH`:** Traverses fewer autonomous system hops.
3. **Lowest Origin Type:** IGP is preferred over EGP.
4. **Lowest `MED` (Multi-Exit Discriminator):** Sender AS expresses preferred ingress link.
5. **Shortest IGP Distance to BGP Next-Hop:** "Hot-Potato Routing" (dumps the packet out of its own network as quickly as possible!).
6. **Lowest Router ID:** Ultimate deterministic tie-breaker.
