# C++ Concepts: Compile-Time Metaprogramming & Constexpr

**Foundational Texts:**  
- *The C++ Programming Language (4th Ed.)* by Bjarne Stroustrup, Chapter 28  
- *Effective Modern C++* by Scott Meyers, Item 15: Use `constexpr` whenever possible  

---

## 1. Theoretical Motivation: Shifting Runtime Cost to Build Time

In modern C++, **computations that can be performed at compile time should be performed at compile time**. This achieves:
1. **Zero Runtime Latency:** Results are embedded directly as immediate operands in assembly instructions or baked into the read-only data segment.
2. **Absolute Correctness:** Invariants, boundary checks, and table generations are verified by the compiler before a single line of binary machine code is emitted.

```
Template Metaprogramming (Pre-C++11):
- Complex recursive template structs, enum hacks, and unreadable syntax.

Modern Constexpr (C++11 to C++20):
- Write standard, readable C++ code with loops, conditionals, and variables
  that executes seamlessly at compile time!
```

## 2. The Specifier Triad: `constexpr` vs. `consteval` vs. `constinit` (C++20)

```
+-----------------------------------------------------------------------------------------+
|                                 COMPILE-TIME SPECIFIERS                                 |
+-------------------+--------------------+------------------------+-----------------------+
| Specifier         | Target             | Execution Context      | Guarantees            |
+-------------------+--------------------+------------------------+-----------------------+
| `constexpr`       | Vars & Functions   | Compile-time OR Runtime| Compile-time if args  |
|                   |                    |                        | are constant exprs    |
+-------------------+--------------------+------------------------+-----------------------+
| `consteval`       | Functions only     | **STRICTLY Compile-time| Compile error if called|
| (Immediate fn)    |                    |                        | with runtime args!    |
+-------------------+--------------------+------------------------+-----------------------+
| `constinit`       | Static / thread_loc| Static Initialization  | Enforces compile-time |
|                   | variables          | Phase                  | init (No SIOF bug!)   |
+-------------------+--------------------+------------------------+-----------------------+
```

### 2.1 `consteval` (Immediate Functions)
`consteval` guarantees that a function **cannot** be called at runtime:
```cpp
consteval int square(int n) {
    return n * n;
}

constexpr int a = square(5); // Compiles fine: 25 evaluated at compile time

int runtime_val = 10;
// int b = square(runtime_val); // COMPILE ERROR! Argument is not a constant expression!
```

### 2.2 `constinit`: Eradicating the Static Initialization Order Fiasco (SIOF)
When two static variables in different translation units depend on each other, the order of runtime dynamic initialization is undefined. `constinit` guarantees static initialization occurs during compilation:
```cpp
constinit int global_config = 42; // Guaranteed zero runtime initialization delay!
```

## 3. `if constexpr`: Compile-Time Branch Elimination (C++17)

Prior to C++17, branching on types required complex SFINAE overloads. `if constexpr` evaluates branches at compile time, completely discarding the non-taken code paths:

```cpp
template <typename T>
auto getLength(const T& val) {
    if constexpr (std::is_pointer_v<T>) {
        return *val; // Only compiled if T is a pointer!
    } else if constexpr (std::is_same_v<T, std::string>) {
        return val.length(); // Only compiled if T is std::string!
    } else {
        return sizeof(val);
    }
}
```
In standard `if`, all branches must be syntactically valid for `T` even if never executed. In `if constexpr`, non-matching branches are discarded, allowing type-specific methods (`val.length()`) to compile safely!

## 4. Practical Systems Pattern: Compile-Time Lookup Tables (LUT)

Generating lookup tables at compile time eliminates startup initialization routines and runtime CPU cycles:

```cpp
#include <array>

// Generate a 256-entry CRC-32 lookup table at compile time:
constexpr auto generateCrc32Table() {
    std::array<uint32_t, 256> table{};
    for (uint32_t i = 0; i < 256; ++i) {
        uint32_t crc = i;
        for (int j = 0; j < 8; ++j) {
            crc = (crc & 1) ? (0xEDB88320 ^ (crc >> 1)) : (crc >> 1);
        }
        table[i] = crc;
    }
    return table;
}

// Baked directly into binary read-only memory (.rodata):
constexpr auto CRC_TABLE = generateCrc32Table();

// Verify first entry at compile time:
static_assert(CRC_TABLE[0] == 0);
```

## 5. Standard Library `<type_traits>`

Type traits are compile-time template queries and transformations:

```cpp
#include <type_traits>

// 1. Type Queries (Return bool value):
static_assert(std::is_integral_v<int>);
static_assert(!std::is_integral_v<double>);

// 2. Type Transformations (Return modified type):
using RawType = std::remove_reference_t<int&>; // int
using CleanType = std::decay_t<const int[5]>;   // int*

// 3. Conditional Type Selection:
template <bool UseFastBuffer>
using BufferType = std::conditional_t<UseFastBuffer, std::array<char, 1024>, std::vector<char>>;
```

## 6. Authoritative Gotchas & Traps (Meyers & Stroustrup)

### 6.1 Scott Meyers' Item 15: The Dual Nature of `constexpr` Functions
A `constexpr` function does **not** guarantee compile-time evaluation unless called in a context that requires a constant expression!
```cpp
constexpr int compute(int x) { return x * 2; }

// Context 1: Constant expression required -> Runs at COMPILE TIME:
constexpr int val1 = compute(5);

// Context 2: Runtime variable passed -> Compiles to standard RUNTIME function call!
int n = 10;
int val2 = compute(n); // Emits standard assembly function call at runtime!
```
**Rule:** If a function **must never** execute at runtime, declare it **`consteval`** (C++20).

### 6.2 The `constexpr` Dynamic Allocation Boundary (C++20)
C++20 permits `new`, `std::vector`, and `std::string` inside `constexpr` functions.  
**The Strict Rule:** Any memory dynamically allocated during compile-time evaluation **must be deallocated before the compile-time evaluation completes**! Leaking memory at compile time causes a compilation error.

## 7. Actionable Summary Checklist

- [x] Use `constexpr` whenever possible (Effective Modern C++ Item 15) to shift calculations to compile time.
- [x] Use `consteval` for functions that must strictly execute at compile time and never emit runtime binary calls.
- [x] Use `constinit` on static variables to completely eliminate the Static Initialization Order Fiasco.
- [x] Replace complex SFINAE boilerplate with C++17 **`if constexpr`** for compile-time branching.
- [x] Bake lookup tables (trigonometric tables, CRC tables, hash maps) into the binary using `constexpr` functions and `std::array`.
