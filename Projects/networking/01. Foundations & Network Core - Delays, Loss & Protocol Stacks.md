## ⚡ 2. Circuit Switching vs. Packet Switching

How should data be transported through the network core?

### 2.1 Circuit Switching (Frequency vs. Time Division)
In traditional telecommunication networks, a dedicated physical circuit with reserved transmission capacity is provisioned end-to-end between sender and receiver before communication can begin:
- **Frequency-Division Multiplexing (FDM):** The frequency spectrum is sliced into narrow bands; each call receives a dedicated frequency band.
- **Time-Division Multiplexing (TDM):** Time is divided into discrete recurring frames of fixed time slots; each call is allocated one slot per frame.

**The Flaw:** When a user is silent, their allocated bandwidth is completely wasted. It cannot be used by any other caller!

---

### 2.2 Packet Switching & Statistical Multiplexing
The Internet utilizes **Packet Switching**: messages are chopped into small discrete blocks called **packets**. Packets share network links on demand without any prior reservation.

```text
===================================================================================================
                         STATISTICAL MULTIPLEXING: CAPACITY ON DEMAND
===================================================================================================

  Users transmit bursts of packets. Packets from User A and User B are dynamically interleaved:
  
  User A [A1] [A2] ──┐
                     ▼
  Queue Buffer:  [A1] [B1] [A2] [B2] [B3] ──► Outbound 10 Gbps Trunk Link
                     ▲
  User B [B1] [B2] ──┘
```

#### The Binomial Congestion Proof: Why Packet Switching Wins
Suppose $N$ users share a $10\text{ Mbps}$ link. Each user requires $1\text{ Mbps}$ when transmitting, but each user is active only $10\%$ of the time ($p = 0.1$).
- **Under Circuit Switching:** At most $\frac{10\text{ Mbps}}{1\text{ Mbps}} = 10\text{ simultaneous users}$ can ever be supported.
- **Under Packet Switching:** Suppose we admit $35\text{ users}$. What is the probability that $11$ or more users want to transmit simultaneously (causing link overload)?
  Using the Binomial Distribution:
  $$P(\text{Active Users} \ge 11) = \sum_{k=11}^{35} \binom{35}{k} (0.1)^k (0.9)^{35-k} \approx 0.0004\ (0.04\%)$$
  With packet switching, the link easily supports **35 users** ($3.5\times$ more than circuit switching) with less than a $0.04\%$ chance of queueing delay!

## ⏱️ 3. The Four Sources of Nodal Delay

When a packet traverses a path of routers, it encounters four distinct delay components at every hop:
$$d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}$$

```text
===================================================================================================
                                      NODAL DELAY TIMELINE
===================================================================================================

  Ingress Packet Arrival ──► [ Processing Delay: d_proc ] (Verify checksum, header lookup)
                                         │
                                         ▼
                             [ Queueing Delay: d_queue ]  (Waiting in FIFO buffer for link)
                                         │
                                         ▼
                             [ Transmission Delay: d_trans = L / R ] (Pushing bits to wire)
                                         │
                                         ▼
                             [ Propagation Delay: d_prop = d / s ] (Light traveling down fiber)
                                         │
                                         ▼
                             Arrives at Next Router
```

### 3.1 Mathematical Breakdown

1. **Processing Delay ($d_{\text{proc}}$):** Time to inspect packet headers, verify CRC error-check codes, and execute a route lookup in the hardware FIB (Forwarding Information Base). Modern ASIC hardware achieves $d_{\text{proc}} < 1\ \mu\text{s}$.
2. **Queueing Delay ($d_{\text{queue}}$):** Time the packet waits in memory buffers. Governed by **Traffic Intensity ($I$)**:
   $$I = \frac{L \cdot a}{R}$$
   where $L = \text{packet length in bits}$, $a = \text{average packet arrival rate (packets/sec)}$, and $R = \text{link bandwidth (bps)}$.
   - If $I \ll 1$: Minimal queueing delay.
   - If $I \to 1$: Queueing delay shoots up asymptotically to infinity!
   - If $I > 1$: Arriving bits exceed link capacity; buffers fill and **Packet Loss** occurs.
3. **Transmission Delay ($d_{\text{trans}}$):** Time to push all $L$ bits onto the link:
   $$d_{\text{trans}} = \frac{L}{R}$$
4. **Propagation Delay ($d_{\text{prop}}$):** Time for electromagnetic waves to travel the distance $d$ through physical copper or glass fiber at speed $s \approx 2 \times 10^8\text{ m/s}$:
   $$d_{\text{prop}} = \frac{d}{s}$$

## 📦 4. The Bandwidth-Delay Product (BDP)

The **Bandwidth-Delay Product (BDP)** is one of the most critical equations in network engineering:
$$\text{BDP} = R \times \text{RTT}$$
where $R$ is link transmission capacity (bits/sec) and $\text{RTT}$ is the round-trip propagation time (seconds).

```text
===================================================================================================
                             BANDWIDTH-DELAY PRODUCT AS A PHYSICAL PIPE
===================================================================================================

        Transmitter                                                       Receiver
      ┌─────────────┐                                                   ┌─────────────┐
      │             ├═══════════════════════════════════════════════════┤             │
      │   Sender    │   Volume of the Pipe = Bandwidth (R) x RTT (s)    │  Receiver   │
      │             ├═══════════════════════════════════════════════════┤             │
      └─────────────┘                                                   └─────────────┘
      
  Physical Meaning: BDP is the maximum volume of bits that can be "in flight"
  inside the network medium simultaneously without receiving an acknowledgment!
```

### 4.1 Real-World Transatlantic Example
- A $100\text{ Gbps}$ dedicated fiber link between New York and London ($\text{RTT} = 70\text{ ms} = 0.07\text{ s}$).
$$\text{BDP} = 100 \times 10^9\text{ bps} \times 0.07\text{ s} = 7 \times 10^9\text{ bits} = 875\text{ Megabytes!}$$
To fully saturate this link without stalling, the sender must have an in-flight TCP window buffer of at least **$875\text{ MB}$**! If the TCP buffer is capped at a legacy default of $64\text{ KB}$, utilization drops below $0.01\%$.

## 📜 5. Protocol Layering & The End-to-End Principle

The Internet's longevity and scale are driven by the **End-to-End Principle** (formulated by Saltzer, Reed, and Clark in 1984):
> *"Functions placed at lower levels of a distributed system may be redundant or of little value when compared with the cost of providing them at that low level. Therefore, application-specific intelligence and reliability must reside at the end hosts, not inside the network core."*

### Why the Network Core is "Dumb"
The Internet core (routers and switches) does not track connections, does not manage application state, and does not retry lost packets. Its sole responsibility is forwarding individual, stateless datagrams as fast as physical silicon permits. All intelligence—reliable retransmissions, congestion backoff, flow control, cryptographic encryption, and session management—is placed at the **Edge** (in the operating system kernels of the endpoints).
