## 2. `ArrayList` Resizing Mechanics

`ArrayList` wraps a contiguous primitive object array:
```java
transient Object[] elementData; // Non-private to simplify nested class access
private int size;
```

```
Initial Capacity: 10
[ e0 | e1 | e2 | e3 | e4 | e5 | e6 | e7 | e8 | e9 ]  -> FULL!

Resize triggered on 11th element:
newCapacity = 10 + (10 >> 1) = 10 + 5 = 15
[ e0 | e1 | e2 | e3 | e4 | e5 | e6 | e7 | e8 | e9 | null | null | null | null | null ]
```

### 2.1 The 1.5x Growth Formula
When adding an element exceeds current capacity, `grow()` executes:
```java
int newCapacity = oldCapacity + (oldCapacity >> 1); // 1.5x growth
elementData = Arrays.copyOf(elementData, newCapacity);
```
- The bitwise right shift `>> 1` is integer division by 2.
- `Arrays.copyOf()` invokes native `System.arraycopy()`, copying memory blocks contiguously.

### 2.2 Cost of Index Insertions and Deletions
- Appending to end: **Amortized $\mathcal{O}(1)$**.
- Inserting at index 0 (`list.add(0, val)`): **$\mathcal{O}(N)$** because every subsequent element must be shifted right by one position via `System.arraycopy()`.

## 3. `ArrayDeque` vs `LinkedList` vs `Stack`

### 3.1 Why `Stack` is Obsolete
`java.util.Stack` extends `Vector`. Every single method (`push`, `pop`, `peek`) is `synchronized`. In single-threaded algorithmic environments, this incurs needless mutex lock overhead.

### 3.2 Why `ArrayDeque` Beats `LinkedList`
For Stack (LIFO) and Queue (FIFO) workloads, **always choose `ArrayDeque` over `LinkedList`**:

```
LinkedList Node Layout:
+--------------------------------------------------------+
| Node Object Header (16 bytes)                          |
| item pointer (8 bytes)                                 |
| next pointer (8 bytes)                                 |
| prev pointer (8 bytes)                                 |
+--------------------------------------------------------+
Total overhead: 40 bytes per node!
Non-contiguous in memory -> Frequent CPU L1/L2 cache misses.

ArrayDeque Layout:
[ Object* | Object* | Object* | Object* | Object* | ... ]
Packed contiguous pointer array -> Superior CPU spatial cache locality.
```

### 3.3 Circular Buffer Math in `ArrayDeque`
`ArrayDeque` enforces power-of-two capacities ($2^k$). Circular index increments and decrements use bitwise masking instead of slow modulo `%`:
```java
// Advance tail:
tail = (tail + 1) & (elements.length - 1);

// Retreat head:
head = (head - 1) & (elements.length - 1);
```

## 4. `HashMap` Deep Dive (Java 8+)

```
table: Node<K,V>[]
+-----+
|  0  | -> Node(hash, K, V) -> null
+-----+
|  1  | -> null
+-----+
| ... |
+-----+
|  8  | -> TreeNode (Red-Black Tree, formed when bucket size >= 8)
|     |       /   \
|     |    TreeNode TreeNode
+-----+
```

### 4.1 Perturbation Hash Function
To prevent high-order collision vulnerabilities when table size is small:
```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```
The bucket index is calculated as:
$$\text{index} = (n - 1) \ \& \ \text{hash}$$
Where $n$ is always a power of 2. Without the `(h >>> 16)` XOR shift, only the lowest bits of `hashCode()` would determine the bucket, resulting in massive clustering for hashes that vary only in their upper bits.

### 4.2 Treeification & Untreeification Thresholds
- `TREEIFY_THRESHOLD = 8`: If a single bucket accumulates $\ge 8$ entries, the linked list converts to a **Red-Black Tree** (`TreeNode`), reducing search time from $\mathcal{O}(N)$ to $\mathcal{O}(\log N)$.
- `MIN_TREEIFY_CAPACITY = 64`: Treeification only occurs if the total table capacity is $\ge 64$. If capacity $< 64$, the table simply **resizes (doubles)** instead to redistribute elements.
- `UNTREEIFY_THRESHOLD = 6`: When a resize splits a bucket such that the tree shrinks to $\le 6$ nodes, it is unpacked back into a standard linked list.

### 4.3 Lock-Free Doubling during Resize
When resizing from capacity $C$ to $2C$:
- The mask expands by one bit: `oldCap`.
- If `(e.hash & oldCap) == 0`, the element remains at index `index`.
- If `(e.hash & oldCap) != 0`, the element shifts to `index + oldCap`.
This avoids re-running expensive modulo or hash computations.

## 5. The `equals()` and `hashCode()` Contract

When placing custom objects as keys in a `HashMap` or elements in a `HashSet`, you **must override both methods**:

1. **Consistency:** If `o1.equals(o2) == true`, then `o1.hashCode() == o2.hashCode()` **MUST** be true.
2. **Non-uniqueness:** If `o1.hashCode() == o2.hashCode()`, `o1.equals(o2)` is not guaranteed to be true (hash collision).

### What Happens If You Override `equals()` But NOT `hashCode()`?
```java
class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Point p)) return false;
        return this.x == p.x && this.y == p.y;
    }
    // Failed to override hashCode()!
}

Map<Point, String> map = new HashMap<>();
map.put(new Point(1, 2), "Target");
System.out.println(map.get(new Point(1, 2))); // Prints null!
```
**Why it fails:** The default `Object.hashCode()` returns the memory identity hash. The two distinct `Point(1, 2)` instances hash to different bucket indices in the table. The lookup searches the wrong bucket and returns `null`.

## 6. `TreeMap` & `NavigableMap` Power Methods

`TreeMap` is implemented as a **Red-Black Tree**, guaranteeing $\mathcal{O}(\log N)$ performance for insertion, deletion, and search.

### Critical Interview API:
```java
TreeMap<Integer, String> map = new TreeMap<>();
map.put(10, "Ten");
map.put(20, "Twenty");
map.put(30, "Thirty");

// 1. floorKey(k): Greatest key <= k
System.out.println(map.floorKey(25));   // 20
System.out.println(map.floorKey(20));   // 20

// 2. ceilingKey(k): Smallest key >= k
System.out.println(map.ceilingKey(25)); // 30
System.out.println(map.ceilingKey(20)); // 20

// 3. lowerKey(k): Greatest key strictly < k
System.out.println(map.lowerKey(20));   // 10

// 4. higherKey(k): Smallest key strictly > k
System.out.println(map.higherKey(20));  // 30
```

These methods are the core building block for intervals, calendar scheduling, and dynamic range queries.

## 7. `PriorityQueue` Internals

Java's `PriorityQueue` is an unbounded **Min-Heap** backed by a contiguous array:
```java
transient Object[] queue;
int size = 0;
```

```
Tree Representation:                Array Representation:
        [ 3 ]                       Index:  0   1   2   3   4
       /     \                      Value: [3,  5,  8, 12,  9]
    [ 5 ]   [ 8 ]
    /   \
  [12]  [ 9 ]
```

### 7.1 Binary Heap Navigation Formulas
For an element at index $i$:
- **Parent Index:** `(i - 1) >>> 1`
- **Left Child Index:** `(i << 1) + 1`
- **Right Child Index:** `(i << 1) + 2`

### 7.2 Custom Comparator / Max-Heap
```java
// Default: Min-Heap
PriorityQueue<Integer> minHeap = new PriorityQueue<>();

// Max-Heap:
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());

// Custom Lambda Comparator:
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
```
