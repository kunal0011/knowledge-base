## 📈 1. Why Elliptic Curve Cryptography (ECC)?

In classical asymmetric cryptography (RSA and Diffie-Hellman), security relies on integer factorization or discrete logarithms in $\mathbb{Z}_p^*$. Because mathematicians invented the **General Number Field Sieve (GNFS)**—a sub-exponential algorithm—maintaining security requires massive, unwieldy key sizes.

```text
===================================================================================================
                       KEY SIZE COMPARISON FOR EQUIVALENT SECURITY
===================================================================================================

  Symmetric Security Level       RSA Key Length          ECC Key Length (NIST / Ed25519)
  ─────────────────────────────────────────────────────────────────────────────────────────────
  80 bits (Obsolete)             1024 bits               160 bits
  112 bits (Legacy)              2048 bits               224 bits
  128 bits (Current Standard)    3072 bits               256 bits  <-- 12x smaller than RSA!
  256 bits (Ultra-Secure)        15360 bits              512 bits  <-- 30x smaller than RSA!
```

Because ECC has **no known sub-exponential attack algorithms** (the best known attack is Pollard's Rho, requiring fully exponential $\mathcal{O}(\sqrt{n})$ operations), a **256-bit ECC key** delivers security equivalent to a monstrous **3072-bit RSA key**, slashing network bandwidth, CPU cycles, and battery drain on mobile devices.

## 📐 2. The Geometry & Algebra of Elliptic Curves

An **Elliptic Curve** over a prime finite field $\mathbb{F}_p$ ($p > 3$) is defined by the **Weierstrass Equation**:
$$y^2 \equiv x^3 + a x + b \pmod p$$
along with an abstract **Point at Infinity** ($\mathcal{O}$), where the coefficients $a, b \in \mathbb{F}_p$ satisfy the non-singularity condition:
$$4a^3 + 27b^2 \not\equiv 0 \pmod p$$
(guaranteeing the curve contains no sharp cusps or self-intersections).

```text
===================================================================================================
                                ELLIPTIC CURVE POINT ADDITION (P + Q = R)
===================================================================================================

       y ▲
         │                     . (Curve: y^2 = x^3 + ax + b)
         │                    /
         │     P (x1, y1)    /
         ├───────●──────────/─────────● Q (x2, y2)
         │        \        /         /
         │         \      /         /  (Draw secant line through P and Q)
       ──┼──────────\────/─────────/──────────────► x
         │           \  /         /
         │            \/         /
         │             \        /
         │              \      ● Intersect Point (x3, -y3)
         │               \     │
         │                \    │ (Reflect across the x-axis!)
         │                 \   ▼
         │                  \  ● Sum Point R = P + Q (x3, y3)
```

### 2.1 Group Law Algebraic Formulas
The set of points on the curve forms an **Abelian Group** under the addition operation:
1. **Identity:** $P + \mathcal{O} = P$.
2. **Inverse:** If $P = (x, y)$, then $-P = (x, -y \bmod p)$. Furthermore, $P + (-P) = \mathcal{O}$.
3. **Point Addition ($P \ne Q$):**
   $$\lambda = \frac{y_2 - y_1}{x_2 - x_1} \pmod p$$
   $$x_3 = \lambda^2 - x_1 - x_2 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$
4. **Point Doubling ($P = Q$):** Tangent slope:
   $$\lambda = \frac{3x_1^2 + a}{2y_1} \pmod p$$
   $$x_3 = \lambda^2 - 2x_1 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$

## ⚡ 3. Scalar Multiplication & The ECDLP

**Scalar Multiplication** is the core operation of ECC: adding a point $P$ to itself $k$ times:
$$Q = k \cdot P = \underbrace{P + P + \dots + P}_{k \text{ times}}$$

Computed efficiently using the **Double-and-Add Algorithm** in $\mathcal{O}(\log k)$ steps.

### 3.1 The Elliptic Curve Discrete Logarithm Problem (ECDLP)
- **Easy:** Given scalar integer $k$ and base point $G$, computing $Q = k \cdot G$ takes $< 1\text{ millisecond}$.
- **Computationally Infeasible (ECDLP):** Given public point $Q$ and generator $G$, find the integer scalar $k$!
On standardized 256-bit curves, solving this requires evaluating approximately $\sqrt{2^{256}} = 2^{128}$ point operations, rendering brute force mathematically impossible.

## 🤝 4. Elliptic Curve Diffie-Hellman (ECDH)

ECDH allows two parties to establish an identical symmetric session key over an untrusted channel:

```text
===================================================================================================
                                      ECDH KEY EXCHANGE FLOW
===================================================================================================

  Global Parameters: Elliptic Curve E(F_p), Base Generator Point G of prime order n
  
       ALICE                                                              BOB
  [ Picks Private Scalar d_A in Z_n ]                                [ Picks Private Scalar d_B in Z_n ]
  Computes Public Point:                                             Computes Public Point:
  Q_A = d_A * G                                                      Q_B = d_B * G
         │                                                                  │
         │──────────────────── 1. Sends Public Point Q_A ──────────────────►│
         │                                                                  │
         │◄─────────────────── 2. Sends Public Point Q_B ───────────────────│
         │                                                                  │
  Computes Shared Secret Point:                                      Computes Shared Secret Point:
  S = d_A * Q_B = d_A * (d_B * G)                                    S = d_B * Q_A = d_B * (d_A * G)
         │                                                                  │
         ▼                                                                  ▼
  ═══════════════════════════════════════════════════════════════════════════════════════════════
                 Both compute the IDENTICAL point S = (d_A * d_B) * G!
                 Session Key = KDF(x-coordinate of Point S)
  ═══════════════════════════════════════════════════════════════════════════════════════════════
```

## ✍️ 5. Digital Signatures: ECDSA vs. The Sony PS3 Disaster

A **Digital Signature** provides origin authentication, message integrity, and non-repudiation.

### 5.1 ECDSA (Elliptic Curve Digital Signature Algorithm)
To sign message hash $z = H(m)$ using private key $d$:
1. Select a cryptographically secure, random non-zero nonce $k \in \mathbb{Z}_n$.
2. Compute point $R = k \cdot G = (x_1, y_1)$.
3. Compute $r = x_1 \bmod n$ (if $r = 0$, retry).
4. Compute $s = k^{-1}(z + r \cdot d) \bmod n$ (if $s = 0$, retry).
5. The signature is the pair: **$(r, s)$**.

---

### 5.2 The Sony PlayStation 3 Epic Failure (2010)
In 2010, the hacker group fail0verflow completely extracted the root private master key used by Sony to secure the PlayStation 3 gaming console.

#### The Root Cause: Hardcoded Nonce $k$
Sony's engineers failed to generate a fresh random nonce $k$ for each signature; **they hardcoded $k$ as a static constant!**

Suppose an attacker intercepts two signatures $(r, s_1)$ and $(r, s_2)$ on two different messages $z_1$ and $z_2$ signed with the same key $d$:
$$s_1 \equiv k^{-1}(z_1 + r \cdot d) \pmod n$$
$$s_2 \equiv k^{-1}(z_2 + r \cdot d) \pmod n$$

Subtract the two equations:
$$s_1 - s_2 \equiv k^{-1}(z_1 - z_2) \pmod n \implies \mathbf{k \equiv \frac{z_1 - z_2}{s_1 - s_2} \pmod n}$$
The secret nonce $k$ is revealed in a single line of high-school algebra!

Once $k$ is known, the attacker extracts the private master key $d$:
$$\mathbf{d \equiv \frac{s_1 \cdot k - z_1}{r} \pmod n}$$
With Sony’s master private key public, players could sign custom homebrew firmware, permanently cracking the PS3 security perimeter.

## 🛡️ 6. The Modern Gold Standard: Ed25519 (EdDSA)

To eradicate nonce-reuse vulnerabilities and side-channel timing attacks, Daniel J. Bernstein engineered **Ed25519** (RFC 8032), based on the **Twisted Edwards Curve**:
$$-x^2 + y^2 = 1 - \frac{121665}{121666} x^2 y^2 \pmod{2^{255} - 19}$$

```text
===================================================================================================
                                     Ed25519 DESIGN HIGHLIGHTS
===================================================================================================

  1. Deterministic Nonce Generation:
     - The nonce k is NOT drawn from an external random number generator!
     - It is derived deterministically: k = SHA-512(Private_Seed || Message).
     - It is mathematically IMPOSSIBLE to reuse a nonce on different messages!

  2. Complete Addition Formulas:
     - No exceptional cases! Point addition works for ANY two points on the curve.
     - Zero division-by-zero checks -> Complete immunity to side-channel branch attacks!

  3. Blazing Speed:
     - Over 70,000 signature verifications per second on a single commodity CPU core.
     - Default choice in OpenSSH, Signal, Apple iOS, WireGuard, and TLS 1.3.
```
