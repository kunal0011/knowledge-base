> "In 1976, Whitfield Diffie and Martin Hellman proposed a radical, seemingly impossible concept: two parties could communicate over an insecure, tapped telephone line and establish a shared secret without ever having met beforehand, and without transmitting the secret across the wire."  
> — *Christof Paar & Jan Pelzl, Understanding Cryptography*

## 🤝 1. Diffie-Hellman Key Exchange: The Foundation of Public-Key

Before 1976, if $N$ users wanted to communicate securely using symmetric encryption, every pair required a pre-shared key. A network of 1,000 users required:
$$\text{Total Keys} = \frac{N(N - 1)}{2} = \frac{1000 \times 999}{2} = 499,500\text{ keys!}$$

The **Diffie-Hellman Key Exchange (DH)** eliminated this dilemma entirely:

```text
===================================================================================================
                               DIFFIE-HELLMAN KEY EXCHANGE FLOW
===================================================================================================

  Global Public Parameters: Large prime p (e.g. 2048 bits), Generator g in Z_p*
  
       ALICE                                                              BOB
  [ Picks Secret a in Z_p ]                                          [ Picks Secret b in Z_p ]
  Computes Public: A = g^a mod p                                     Computes Public: B = g^b mod p
         │                                                                  │
         │──────────────────── 1. Sends Public A ──────────────────────────►│
         │                                                                  │
         │◄─────────────────── 2. Sends Public B ───────────────────────────│
         │                                                                  │
  Computes Shared Secret:                                            Computes Shared Secret:
  K = B^a mod p = (g^b)^a = g^(ab) mod p                             K = A^b mod p = (g^a)^b = g^(ab) mod p
         │                                                                  │
         ▼                                                                  ▼
  ═══════════════════════════════════════════════════════════════════════════════════════════════
                 Both compute the IDENTICAL secret key K = g^(ab) mod p!
  ═══════════════════════════════════════════════════════════════════════════════════════════════
```

### 1.1 What the Eavesdropper Sees
An attacker sniffing the network intercepts:
$$\{p,\ g,\ A = g^a \bmod p,\ B = g^b \bmod p\}$$
To compute the shared secret $K = g^{ab} \bmod p$, the attacker must compute $a = \log_g(A) \bmod p$. This is the **Discrete Logarithm Problem (DLP)**, which is computationally intractable for 2048-bit primes!

### 1.2 The Man-in-the-Middle (MitM) Vulnerability
Diffie-Hellman provides secrecy, but **zero authentication**. An active attacker (Mallory) sitting between Alice and Bob intercepts Alice's public key $A$ and sends Mallory's own key $M$ to Bob, establishing separate keys with both parties. To prevent this, Diffie-Hellman **must be authenticated** via Digital Signatures (as done in TLS 1.3).

## 🏛️ 2. The RSA Cryptosystem (Rivest, Shamir, Adleman - 1977)

RSA is the first practical asymmetric algorithm supporting both **public-key encryption** and **digital signatures**.

```text
===================================================================================================
                                       RSA KEY GENERATION
===================================================================================================

  1. Select two massive, distinct prime numbers p and q (e.g., 1024 bits each).
  
  2. Compute Modulus:
     n = p * q  (Length = 2048 bits)
  
  3. Compute Euler's Totient:
     phi(n) = (p - 1) * (q - 1)
  
  4. Choose Public Exponent e:
     Select e such that gcd(e, phi(n)) = 1.
     (Universal Industry Standard: e = 65537 = 2^16 + 1, prime with only two 1-bits!)
  
  5. Compute Private Exponent d:
     d = e^(-1) mod phi(n)  (via Extended Euclidean Algorithm)
     Such that: e * d ≡ 1 (mod phi(n))
  
  ═══════════════════════════════════════════════════════════════════════════════════════════════
  Public Key:   (e, n)   ──► Shared openly with the world
  Private Key:  (d, n)   ──► Kept strictly secret (p and q are securely shredded from RAM!)
  ═══════════════════════════════════════════════════════════════════════════════════════════════
```

## 🔐 3. Encryption, Decryption & Mathematical Proof of Correctness

### 3.1 Operations
- **Encryption:** Given plaintext message $m$ ($0 \le m < n$):
  $$c = m^e \bmod n$$
- **Decryption:** Given ciphertext $c$:
  $$m = c^d \bmod n$$

### 3.2 Formal Proof of Correctness
We must prove that for any message $m$:
$$c^d \equiv (m^e)^d \equiv m^{ed} \equiv m \pmod n$$

**Proof:**
By definition of the modular inverse:
$$ed \equiv 1 \pmod{\phi(n)} \implies ed = k \cdot \phi(n) + 1 = k(p - 1)(q - 1) + 1$$
Therefore:
$$m^{ed} = m^{k(p - 1)(q - 1) + 1} = \left( m^{p - 1} \right)^{k(q - 1)} \cdot m$$

- **Case 1: $\gcd(m, p) = 1$**  
  By Fermat’s Little Theorem, $m^{p-1} \equiv 1 \pmod p$:
  $$m^{ed} \equiv (1)^{k(q - 1)} \cdot m \equiv m \pmod p$$
- **Case 2: $\gcd(m, p) \ne 1$**  
  Since $p$ is prime, this implies $p \mid m$, which means $m \equiv 0 \pmod p$.
  $$m^{ed} \equiv 0^{ed} \equiv 0 \equiv m \pmod p$$

Thus, in all cases: $m^{ed} \equiv m \pmod p$.  
By identical logic: $m^{ed} \equiv m \pmod q$.

Because $p$ and $q$ are distinct coprime primes, by the **Chinese Remainder Theorem**:
$$m^{ed} \equiv m \pmod{p \cdot q} \implies m^{ed} \equiv m \pmod n$$
$\blacksquare$ **Decryption is mathematically guaranteed to recover the exact original message $m$.**

## 💥 4. Textbook RSA is Insecure: Real-World Vulnerabilities

"Textbook RSA" (raw $c = m^e \bmod n$) must **never be used in production** due to severe mathematical vulnerabilities:

### 4.1 Determinism & The Chosen-Plaintext Attack (CPA)
Because RSA encryption is deterministic, encrypting the same message $m$ with public key $(e, n)$ always produces the exact same ciphertext $c$. An attacker guessing between two messages ($m_0 = \text{"YES"}, m_1 = \text{"NO"}$) simply computes $\text{Enc}(m_0)$ and $\text{Enc}(m_1)$ and compares them to the intercepted ciphertext. Textbook RSA fails IND-CPA security!

### 4.2 Multiplicative Homomorphism & Malleability
RSA preserves multiplication:
$$\text{Enc}(m_1) \cdot \text{Enc}(m_2) \equiv (m_1^e)(m_2^e) \equiv (m_1 \cdot m_2)^e \equiv \text{Enc}(m_1 \cdot m_2) \pmod n$$
An attacker can multiply an intercepted ciphertext $c = m^e$ by $2^e \bmod n$, creating $c' = (2m)^e \bmod n$. When the victim decrypts $c'$, they receive $2m$!

### 4.3 Small Exponent / Small Message Attack ($e = 3$)
If an organization chooses $e = 3$ for fast encryption, and a short message $m$ is encrypted such that $m^3 < n$, the modulus $n$ is never triggered! The ciphertext is simply the regular arithmetic cube: $c = m^3$. An attacker decrypts the message by computing the standard integer cube root $\sqrt[3]{c}$ in Python with zero keys!

## 🛡️ 5. Optimal Asymmetric Encryption Padding (RSA-OAEP)

To neutralize all malleability and deterministic attacks, modern RSA mandates **OAEP (RFC 8017 / PKCS#1 v2.2)**:

```text
===================================================================================================
                                      RSA-OAEP ENCODING
===================================================================================================

  Plaintext M (Padded with zeros)                     Random Seed r (e.g. 256 bits)
               │                                                    │
               ▼                                                    ▼
              XOR ◄────── [ Mask Gen Fxn: MGF(r) ] ◄────────────────┤
               │                                                    │
               ▼ MaskedDB                                           ▼
               ├────────────────────────────────────────► [ Mask Gen Fxn: MGF(MaskedDB) ]
               │                                                    │
               │                                                    ▼
               │                                                   XOR
               │                                                    │
               ▼                                                    ▼ MaskedSeed
  Encoded Message EM = [ 0x00 || MaskedSeed || MaskedDB ]
  
  Final Ciphertext: C = EM^e mod n
```

### Why OAEP is Provably Secure:
1. **Randomized Padding:** The fresh random seed $r$ ensures that encrypting the same message 1,000 times produces 1,000 completely different, uncorrelated ciphertexts (achieving IND-CPA).
2. **All-or-Nothing Property:** The two-round Feistel structure diffuses the seed and message across the entire modulus. Flipping even a single bit of the ciphertext scrambles the entire decoded block, causing OAEP verification to reject the padding and neutralizing all padding oracle and malleability attacks!
