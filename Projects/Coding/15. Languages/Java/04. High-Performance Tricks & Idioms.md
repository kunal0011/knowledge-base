# Java: High-Performance Tricks & Idioms

**Target Audience:** Software engineers and competitive programmers looking to maximize throughput, eliminate GC overhead, and write high-efficiency Java code  
**Topic:** Quicksort vs Timsort internals, `BitSet` optimizations, Fast I/O, JVM bitwise intrinsics, and primitive loop speedups

## 1. The `Arrays.sort(int[])` Quicksort Trap vs Timsort

In Java, the sorting algorithm selected by `Arrays.sort()` depends strictly on the runtime type of the array:

```
                  Arrays.sort()
                 /             \
        Primitive Types         Object Types (Integer[], String[], etc.)
               |                                   |
    Dual-Pivot Quicksort                        Timsort
  Average: O(N log N)                     Average: O(N log N)
  Worst-Case: O(N^2) !                    Guaranteed Worst-Case: O(N log N)
  Not Stable                              Stable
```

### 1.1 The Vulnerability
Adversarial test cases on competitive platforms (e.g., Codeforces, LeetCode) deliberately generate input sequences that exploit the dual-pivot selection heuristic, forcing Dual-Pivot Quicksort into its worst-case **$\mathcal{O}(N^2)$** complexity and causing sudden TLE (Time Limit Exceeded).

### 1.2 Two Workarounds to Guarantee $\mathcal{O}(N \log N)$

**Workaround 1: Fisher-Yates Random Shuffle prior to sort (Recommended for primitives)**
```java
static void safeSort(int[] arr) {
    Random rnd = ThreadLocalRandom.current();
    for (int i = arr.length - 1; i > 0; i--) {
        int index = rnd.nextInt(i + 1);
        int temp = arr[index];
        arr[index] = arr[i];
        arr[i] = temp;
    }
    Arrays.sort(arr); // Quicksort now runs in O(N log N) with 99.9999% statistical probability
}
```

**Workaround 2: Box to `Integer[]` (Invokes Timsort)**
```java
Integer[] boxed = Arrays.stream(arr).boxed().toArray(Integer[]::new);
Arrays.sort(boxed); // Uses Timsort: Guaranteed O(N log N)
```

## 2. `BitSet`: Memory & Speed Optimization for Booleans

In HotSpot JVM, each element of a `boolean[]` consumes **1 byte (8 bits)** of heap memory for alignment and addressing simplicity.
`java.util.BitSet` stores booleans packed into an internal `long[]` array (64 bits per `long`), reducing memory usage by **$8\times$** while enabling hardware-level parallel bitwise operations.

```
boolean[64]:  64 bytes of heap memory
BitSet(64):   8 bytes (1 long word) of payload!
```

### 2.1 BitSet API & SIMD Speed
```java
BitSet bs1 = new BitSet(1000);
BitSet bs2 = new BitSet(1000);

bs1.set(10);
bs1.set(50);
bs2.set(50);
bs2.set(100);

// Bitwise AND / Intersection (modifies bs1 in-place at 64 bits per CPU cycle):
bs1.and(bs2); // bs1 now only contains {50}

// Bitwise OR / Union:
bs1.or(bs2);

// Find next set bit starting at index (extremely fast for sparse graphs):
int next = bs1.nextSetBit(0);
while (next != -1) {
    // Process set bit
    next = bs1.nextSetBit(next + 1);
}
```

## 3. High-Performance Bitwise Intrinsics

The `java.lang.Integer` and `java.lang.Long` classes contain intrinsic methods that HotSpot replaces directly with single CPU hardware instructions (e.g., `POPCNT`, `LZCNT`, `TZCNT` on x86-64):

```java
int x = 40; // binary: 0b00000000_00000000_00000000_00101000

// 1. Popcount (Count Set Bits): Maps to CPU POPCNT instruction
int bits = Integer.bitCount(x);             // 2

// 2. Count Leading Zeros: Maps to CPU LZCNT / BSR
int lz = Integer.numberOfLeadingZeros(x);   // 26

// 3. Count Trailing Zeros: Maps to CPU TZCNT / BSF
int tz = Integer.numberOfTrailingZeros(x);  // 3

// 4. Highest Set Bit (Power of 2):
int high = Integer.highestOneBit(x);        // 32

// 5. Lowest Set Bit:
int low = Integer.lowestOneBit(x);          // 8
```

## 4. Traditional Loops vs Java Streams: The Hot-Path Tradeoff

```java
// Option A: Java 8 Stream
int sum = Arrays.stream(nums).filter(x -> x % 2 == 0).sum();

// Option B: Traditional for-loop
int sum = 0;
for (int i = 0; i < nums.length; i++) {
    if (nums[i] % 2 == 0) {
        sum += nums[i];
    }
}
```

### Performance Comparison in Algorithmic Code:
- **Streams:** Instantiates pipeline pipeline objects, spliterators, and invokes lambda function calls. The JIT cannot always inline lambda call sites cleanly under tight constraints.
- **Traditional For-Loop:** Direct memory index access. HotSpot executes loop unrolling, SIMD vectorization (AVX2), and bounds check elimination.
- **Benchmark:** Traditional loops run **$2\times \text{ to } 5\times$ faster** than Stream pipelines in tight algorithmic loops ($N \ge 10^6$). In interviews, use Streams for clean expressiveness in non-hot paths, but favor loops in performance-critical sections.

## 5. Fast I/O for Large Scale Input Processing

`java.util.Scanner` uses regular expressions and synchronized buffers, making it too slow to read $10^6$ integers within standard $1.0\text{s}$ time limits.
Use this battle-tested `FastScanner` pattern:

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.util.StringTokenizer;

public class FastIO {
    static class FastScanner {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer("");

        String next() {
            while (!st.hasMoreTokens()) {
                try {
                    String line = br.readLine();
                    if (line == null) return null;
                    st = new StringTokenizer(line);
                } catch (Exception e) {
                    return null;
                }
            }
            return st.nextToken();
        }

        int nextInt() {
            return Integer.parseInt(next());
        }

        long nextLong() {
            return Long.parseLong(next());
        }
    }

    public static void main(String[] args) {
        FastScanner in = new FastScanner();
        PrintWriter out = new PrintWriter(System.out);

        // Read and write:
        // int n = in.nextInt();
        // out.println(n);

        out.flush(); // Crucial: Flush buffer at end!
    }
}
```

## 6. SIMD Acceleration with `System.arraycopy`

Never copy array ranges using manual element-by-element loops:
```java
// SLOW: O(N) loop with individual JVM bounds checks
for (int i = 0; i < len; i++) {
    dest[destPos + i] = src[srcPos + i];
}

// ULTRA-FAST: Native C-speed block memory copy (memcpy/AVX SIMD)
System.arraycopy(src, srcPos, dest, destPos, len);
```
`System.arraycopy()` is a JVM intrinsic that copies 32 or 64 bytes per CPU cycle using SIMD vector registers without per-element bounds checking.
