# Java: Interview Gotchas & Common Pitfalls

**Target Audience:** Software engineers and candidates preparing for Java technical coding interviews  
**Topic:** Language subtleties, arithmetic edge cases, memory traps, and Collections gotchas in Java

---

## 1. Top Java Gotchas Summary

| Pitfall | Symptoms / Result | Underlying JVM Cause | Correct Solution |
|:---|:---|:---|:---|
| **`==` on Objects** | `Integer(1000) == Integer(1000)` is `false` | `==` compares reference addresses, not values | Always use `.equals()` or `Integer.compare()` |
| **`ConcurrentModificationException`** | Crash when removing element inside `for-each` | `modCount != expectedModCount` check in iterator | Use `Iterator.remove()` or `collection.removeIf()` |
| **`Math.abs(MIN_VALUE)`** | `Math.abs(-2147483648)` returns negative `-2147483648` | Two's complement asymmetry ($\vert \text{MIN} \vert > \text{MAX}$) | Cast to `long`: `Math.abs((long) val)` |
| **Comparator Underflow** | `(a, b) -> a - b` sorts in reverse or crashes | Integer underflow when subtracting large opposing signs | Use `Integer.compare(a, b)` |
| **Midpoint Overflow** | `(low + high) / 2` becomes negative | Sum exceeds $2^{31}-1$, overflowing into negative | Use `low + (high - low) / 2` or `(low + high) >>> 1` |
| **`Arrays.asList(int[])`** | List has size 1 containing the entire `int[]` | Varargs receives primitive array as a single object | Use `Arrays.stream(arr).boxed().toList()` |
| **`Arrays.asList().add()`** | Throws `UnsupportedOperationException` | Returns fixed-size private wrapper, not `java.util.ArrayList` | Wrap: `new ArrayList<>(Arrays.asList(...))` |
| **Generics Type Erasure** | `new T[n]` or `instanceof List<T>` fails to compile | Type parameters erased to `Object` at runtime | Pass `Class<T>` token or use `Object[]` with casts |
| **String `+` in Loop** | Quadratic runtime $\mathcal{O}(N^2)$ causing TLE | Compiles to new `StringBuilder` instantiation every loop | Use a single outer `StringBuilder` |

## 2. Equality: `==` vs `.equals()`

In Java:
- `==` compares **primitive values** or **object memory references**.
- `.equals()` checks for **logical value equivalence**.

### The Autoboxing Cache Trap
```java
Integer a = 127, b = 127;
System.out.println(a == b); // true (reused from IntegerCache [-128, 127])

Integer x = 128, y = 128;
System.out.println(x == y); // false! (separate heap instances)
System.out.println(x.equals(y)); // true
```

### String Comparison
```java
String s1 = "apple";
String s2 = "apple";
String s3 = new String("apple");

System.out.println(s1 == s2);      // true (String Pool reference)
System.out.println(s1 == s3);      // false (Heap allocation vs Pool)
System.out.println(s1.equals(s3));  // true (Character-by-character check)
```

> [!WARNING]
> In interviews, never use `==` when comparing Strings or wrapper classes (`Integer`, `Long`, `Character`). Always use `.equals()`.

## 3. `ConcurrentModificationException` & Fail-Fast Iterators

### The Trap
```java
List<Integer> list = new ArrayList<>(List.of(1, 2, 3, 4, 5));
for (Integer x : list) {
    if (x % 2 == 0) {
        list.remove(x); // Throws ConcurrentModificationException!
    }
}
```

### Why it Happens
The enhanced `for` loop compiles to an `Iterator`:
```java
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    Integer x = it.next();
    if (x % 2 == 0) list.remove(x); // Modifies list directly!
}
```
`ArrayList` maintains an internal mutation counter `modCount`. When the iterator is created, it captures `expectedModCount = modCount`. Calling `list.remove()` increments `modCount`. On the next call to `it.next()`, the check fails:
```java
if (modCount != expectedModCount)
    throw new ConcurrentModificationException();
```

### The Idiomatic Solutions
```java
// Solution 1: Explicit Iterator.remove()
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    if (it.next() % 2 == 0) {
        it.remove(); // Updates both modCount and expectedModCount
    }
}

// Solution 2: Java 8+ Predicate (Cleanest & Fast)
list.removeIf(x -> x % 2 == 0);
```

## 4. Integer Overflow Traps

### 4.1 `Math.abs(Integer.MIN_VALUE)`
In 32-bit two's complement:
- `Integer.MAX_VALUE =  2,147,483,647` ($2^{31} - 1$)
- `Integer.MIN_VALUE = -2,147,483,648` ($-2^{31}$)

Because $+2,147,483,648$ cannot be represented in a 32-bit signed integer, negating `MIN_VALUE` wraps right back to `MIN_VALUE`:
```java
int val = Integer.MIN_VALUE;
System.out.println(Math.abs(val)); // Prints -2147483648 (Still negative!)
```
**Fix:** Cast to `long` before computing absolute value:
```java
long absVal = Math.abs((long) val);
```

### 4.2 Midpoint Calculation in Binary Search
```java
// WRONG: If low + high > 2,147,483,647, sum overflows to negative number!
int mid = (low + high) / 2;

// CORRECT (Safe against overflow):
int mid = low + (high - low) / 2;

// ALTERNATIVE (Bitwise unsigned right shift):
int mid = (low + high) >>> 1;
```

### 4.3 Comparator Subtraction Overflow Bug
```java
// WRONG: Subtraction bug
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
```
If `a[0] = -2,000,000,000` and `b[0] = 1,000,000,000`:
$$a[0] - b[0] = -3,000,000,000 \implies \text{underflows to } +1,294,967,296 > 0$$
The comparator reports that `a` is greater than `b`, completely corrupting the sorted order!

**CORRECT:**
```java
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
```

## 5. `Arrays.asList()` Traps

### Trap 1: Immutability / Fixed Size
```java
List<String> list = Arrays.asList("a", "b", "c");
list.add("d"); // Throws java.lang.UnsupportedOperationException!
```
`Arrays.asList()` returns an instance of an internal private static class `java.util.Arrays.ArrayList`. It wraps the underlying array and does **not** support addition or removal.
**Fix:**
```java
List<String> list = new ArrayList<>(Arrays.asList("a", "b", "c"));
```

### Trap 2: Primitive Arrays Boxed as Single Element
```java
int[] nums = {1, 2, 3};
List<int[]> list = Arrays.asList(nums);
System.out.println(list.size()); // Prints 1! (A List containing a single int[] array)
```
Generics require object types. A primitive `int[]` is an `Object`, so varargs packs the entire array as the single first element of `List<int[]>`.
**Fix:**
```java
List<Integer> list = Arrays.stream(nums).boxed().toList();
```

## 6. Generics Type Erasure

Java compiles generic types by **erasing** type parameters and replacing them with their bounding class (`Object` if unbounded):

```java
// In your code:
List<String> names = new ArrayList<>();
names.add("Alice");
String s = names.get(0);

// In compiled bytecode:
List names = new ArrayList();
names.add("Alice");
String s = (String) names.get(0); // Compiler inserts synthetic cast
```

### Consequences:
1. **Cannot Instantiate Generic Arrays:**
   ```java
   T[] arr = new T[10]; // Compile Error!
   // Standard workaround:
   T[] arr = (T[]) new Object[10];
   ```
2. **Cannot Check Types with `instanceof`:**
   ```java
   if (obj instanceof List<String>) // Compile Error: Illegal generic type for instanceof
   ```
3. **Cannot Overload with Identical Erasures:**
   ```java
   public void process(List<String> list) {}
   public void process(List<Integer> list) {} // Compile Error: Both erase to process(List)
   ```

## 7. Array Covariance vs Generics Invariance

- **Java Arrays are Covariant:**
  If `Sub` extends `Super`, then `Sub[]` is a subtype of `Super[]`.
  ```java
  Object[] objs = new String[3];
  objs[0] = 100; // Compiles fine, but throws ArrayStoreException at runtime!
  ```
- **Java Generics are Invariant:**
  `List<String>` is **not** a `List<Object>`. This protects type safety at compile time.
  To allow subtyping with generics, use **bounded wildcards**:
  - Upper bounded: `List<? extends Number>` (Producer Extends - Read-only)
  - Lower bounded: `List<? super Integer>` (Consumer Super - Write-only)
  *(Mnemonic: PECS - Producer Extends, Consumer Super)*

## 8. String Concatenation in Loops ($\mathcal{O}(N^2)$ TLE)

```java
// ANTI-PATTERN: O(N^2) Time Complexity!
String s = "";
for (int i = 0; i < n; i++) {
    s += i; // Allocates a new StringBuilder and String object each iteration
}

// OPTIMAL: O(N) Time Complexity
StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) {
    sb.append(i);
}
String s = sb.toString();
```
In a tight loop running $10^5$ iterations, the `+=` operator triggers thousands of intermediate buffer allocations and garbage collections, leading to Time Limit Exceeded (TLE) in interviews.
