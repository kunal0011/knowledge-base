## 🪣 2. Object Storage Deep Dive: S3 vs. Azure Blob vs. GCS

Object storage decouples metadata management from raw binary chunk storage, distributing data across thousands of storage nodes using **Reed-Solomon Erasure Coding**:

===================================================================================================

              │
              ▼

 ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐   ┌────┐ ┌────┐ ┌────┐ ┌────┐
 │ D1 │ │ D2 │ │ D3 │ │ D4 │ │ D5 │ │ D6 │ │ D7 │ │ D8 │   │ P1 │ │ P2 │ │ P3 │ │ P4 │
 └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘   └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘
   │      │      │      │      │      │      │      │       │      │      │      │
   ▼      ▼      ▼      ▼      ▼      ▼      ▼      ▼       ▼      ▼      ▼      ▼

### 2.1 Strong Consistency vs. Eventual Consistency
- **Historical Context:** Prior to December 2020, Amazon S3 operated under **Eventual Consistency** for overwrite `PUT` and `DELETE` requests. A `PUT` immediately followed by a `GET` could return the stale previous version or a 404 Not Found.
- **Modern Reality:** Today, **AWS S3, Azure Blob, and Google Cloud Storage all provide Strong Read-After-Write Consistency** for all new object `PUT`s, updates, and deletes with zero performance penalty.

## 💾 3. Block Storage: Amazon EBS vs. Azure Managed Disks vs. GCP Persistent Disk

Block storage volumes are virtualized Storage Area Network (SAN) devices attached over PCIe or network fabrics to compute instances. They are strictly **zonal resources** (an EBS volume in `us-east-1a` cannot attach directly to an EC2 instance in `us-east-1b`).

```text
===================================================================================================
                       THE IOPS VS. THROUGHPUT VS. BLOCK SIZE RELATIONSHIP
===================================================================================================

 All block storage performance is governed by the universal physics formula:
 
                  Throughput (MB/s) = IOPS × I/O Block Size (KB) / 1024
 
 Examples:
 1. Small Random I/O (OLTP Database - 8 KB Block Size):
    - 16,000 IOPS × 8 KB = 128,000 KB/s = 125 MB/s throughput.
 2. Large Sequential I/O (Data Streaming / Video - 256 KB Block Size):
    - 1,000 IOPS × 256 KB = 256,000 KB/s = 250 MB/s throughput.
```

## 💥 6. Real-World Storage Post-Mortem: S3 US-East-1 Cascading Outage

### The Incident: S3 Subsystem Cascade (February 28, 2017)
One of the most consequential cloud outages in history occurred in the `us-east-1` region during routine maintenance:

```text
===================================================================================================
                      THE S3 US-EAST-1 CIRCULAR DEPENDENCY CASCADE
===================================================================================================

  1. Authorized engineer executes operational command to decommission a small subsystem
     of servers in the S3 billing index.
                         │
                         ▼
  2. Input typo in command argument: Accidentally decommissions massive cluster of servers
     running two primary S3 internal subsystems:
     - The Index Subsystem (Manages all metadata & location mappings for US-East-1).
     - The Placement Subsystem (Allocates new storage positions).
                         │
                         ▼
  3. S3 us-east-1 drops completely offline!
                         │
                         ▼
  4. Cascading Cross-Service Failure:
     - Amazon EC2 cannot launch new instances (relies on S3 for AMI images).
     - Amazon EBS volumes cannot create snapshots (relies on S3 for block backup).
     - AWS Management Console status dashboard displays green checkmarks because
       the status dashboard itself hosted its health icon images on... S3 US-East-1!
                         │
                         ▼
  5. Recovery Bottleneck: S3 index subsystem had grown so vast since its creation that
     running cold-start integrity checks and cache rebuilding took over 4.5 hours!
```

#### Architectural Lessons:
- **Blast Radius Decomposition:** Cloud providers subsequently decomposed massive monolithic regional indexes into isolated internal cells.
- **Eliminate Circular Dependencies:** Core control systems and health monitoring infrastructure must never depend on the data plane services they monitor.

## 🛠️ 7. Production Terraform: Automated S3 Data Lake Tiering & Encryption

```hcl
# ==============================================================================
# SECURE ENTERPRISE S3 BUCKET WITH INTELLIGENT TIERING & KMS
# ==============================================================================
resource "aws_kms_key" "s3_key" {
  description             = "Customer Master Key for Enterprise Data Lake"
  deletion_window_in_days = 30
  enable_key_rotation     = true
}

resource "aws_s3_bucket" "data_lake" {
  bucket = "enterprise-datalake-analytics-prod-001"
}

# Block all public access at bucket level
resource "aws_s3_bucket_public_access_block" "block_public" {
  bucket = aws_s3_bucket.data_lake.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# Enforce Server-Side Encryption with Customer Managed Key (SSE-KMS)
resource "aws_s3_bucket_server_side_encryption_configuration" "kms_encryption" {
  bucket = aws_s3_bucket.data_lake.id

  rule {
    apply_server_side_encryption_by_default {
      kms_master_key_id = aws_kms_key.s3_key.arn
      sse_algorithm     = "aws:kms"
    }
    bucket_key_enabled = true # Reduces KMS API request costs by 99%!
  }
}

# Automated Lifecycle Management for Cost Optimization
resource "aws_s3_bucket_lifecycle_configuration" "lake_lifecycle" {
  bucket = aws_s3_bucket.data_lake.id

  rule {
    id     = "transition-cold-data"
    status = "Enabled"

    transition {
      days          = 30
      storage_class = "STANDARD_IA"
    }

    transition {
      days          = 90
      storage_class = "GLACIER"
    }

    transition {
      days          = 365
      storage_class = "DEEP_ARCHIVE"
    }

    expiration {
      days = 2555 # 7-Year Compliance Purge
    }
  }
}
```

## 🎯 8. Architectural Takeaways & Storage Checklist

1. **Calculate IOPS vs Throughput Carefully:** High IOPS do not compensate for narrow throughput limits. Align your database block sizes with volume throughput caps.
2. **Enable S3 Bucket Keys:** When using KMS encryption on object storage, always enable S3 Bucket Keys to avoid million-dollar KMS API billing shocks.
3. **Multi-AZ Replication for File Systems:** Use multi-AZ deployment configurations for EFS, Azure NetApp Files, or Filestore Enterprise to prevent storage unavailability during zonal outages.
