## 💾 1. The Offline-First Paradigm & Single Source of Truth (SSOT)

In naive mobile architectures, screens make network calls, parse JSON, and display it directly on the screen. When the device loses cellular connectivity or enters airplane mode, the app displays blank screens and error dialogs.

Under **Offline-First Architecture**:
1. **The UI observes strictly the Local Database** via reactive streams (`Flow<List<Product>>` in Room, `Stream<List<Product>>` in Drift).
2. **Network sync runs in the background**, upserting fresh records into the local database.
3. The database engine emits a fresh snapshot over the stream, updating the UI automatically!

```
===================================================================================================
                             OFFLINE-FIRST DATA SYNC FLOW (SSOT)
===================================================================================================

                    +-----------------------------------------+
                    |           UI / Compose Screen           |
                    +--------------------+--------------------+
                                         ▲
                                         │ 1. Observes Reactive Stream
                                         │    (Instant UI Render from Disk Cache!)
                    +--------------------+--------------------+
                    |        Room / Drift Local Database      | <── [ Single Source of Truth ]
                    +--------------------+--------------------+
                                         ▲
                                         │ 3. Writes Fresh Payload to SQLite
                    +--------------------+--------------------+
                    |       Repository Sync Worker            |
                    +--------------------+--------------------+
                                         │
                                         │ 2. Background Asynchronous Fetch
                                         ▼
                    +-----------------------------------------+
                    |          Remote Backend API             |
                    +-----------------------------------------+
```

## 🗄️ 2. Android Persistence: Room vs. DataStore

### 2.1 Room Database Architecture
Room provides an abstraction layer over native SQLite with compile-time query verification using Kotlin Symbol Processing (KSP):
- **WAL (Write-Ahead Logging) Mode:** Permits concurrent readers while a background thread executes write operations.
- **Reactive Queries:** Queries returning `Flow<T>` automatically register table observers in SQLite, emitting new results whenever the underlying table undergoes `INSERT`, `UPDATE`, or `DELETE`.

### 2.2 Why SharedPreferences is Replaced by DataStore
`SharedPreferences` had two critical flaws:
1. `apply()` and `commit()` can trigger synchronous disk I/O on the Main UI thread, triggering **ANR (Application Not Responding)** crashes.
2. No transactional safety or schema migration capability.

**Jetpack DataStore** replaces it with:
- **Preferences DataStore:** Key-value storage built on Kotlin Coroutines and Flow (non-blocking).
- **Proto DataStore:** Type-safe object storage using Protocol Buffers contracts.

## 💻 3. Side-by-Side Production Implementations: Offline-First Repository

We implement an offline-first **Product Catalog Repository** featuring local database persistence, reactive streams, and network sync in:
1. **Kotlin (Room Database + Coroutines Flow)**
2. **Dart (Drift Reactive SQLite)**

---

### 3.1 Android Implementation: Room Database with Flow & Migration

```kotlin
package com.enterprise.mobile.data.local

import androidx.room.*
import kotlinx.coroutines.flow.Flow

// 1. Database Entity
@Entity(tableName = "products")
data class ProductEntity(
    @PrimaryKey val id: String,
    val title: String,
    val priceCents: Long,
    val cachedAt: Long = System.currentTimeMillis()
)

// 2. Data Access Object (DAO)
@Dao
interface ProductDao {
    // Emits a new List every time the 'products' table changes!
    @Query("SELECT * FROM products ORDER BY title ASC")
    fun observeAllProducts(): Flow<List<ProductEntity>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsertProducts(products: List<ProductEntity>)

    @Query("DELETE FROM products")
    suspend fun clearAll()
}

// 3. Room Database Definition with Manual Migration
@Database(entities = [ProductEntity::class], version = 1, exportSchema = true)
abstract class AppDatabase : RoomDatabase() {
    abstract fun productDao(): ProductDao
}

// 4. Offline-First Repository Implementation
class OfflineFirstProductRepository(
    private val productDao: ProductDao,
    private val remoteApi: ProductApiService
) {
    // UI observes local disk data directly
    val productsStream: Flow<List<ProductEntity>> = productDao.observeAllProducts()

    // Background sync function
    suspend fun refreshProducts() {
        try {
            val remoteList = remoteApi.fetchProducts()
            val entities = remoteList.map { dto ->
                ProductEntity(
                    id = dto.id,
                    title = dto.name,
                    priceCents = dto.priceCents
                )
            }
            productDao.upsertProducts(entities) // Updates SQLite -> triggers UI Flow!
        } catch (e: Exception) {
            // Offline gracefully: cached data remains visible!
            println("Network sync failed, using cached data: ${e.message}")
        }
    }
}

// Mock API
interface ProductApiService {
    suspend fun fetchProducts(): List<ProductDto>
}
data class ProductDto(val id: String, val name: String, val priceCents: Long)
```

### 3.2 Flutter Implementation: Drift (Reactive SQLite ORM)

```dart
import 'package:drift/drift.dart';
import 'package:drift/native.dart';

// 1. Drift Table Schema
class Products extends Table {
  TextColumn get id => text()();
  TextColumn get title => text().withLength(min: 1, max: 100)();
  Int64Column get priceCents => int64()();
  DateTimeColumn get cachedAt => dateTime().withDefault(currentDateAndTime)();

  @override
  Set<Column> get primaryKey => {id};
}

// 2. Database Definition
@DriftDatabase(tables: [Products])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(NativeDatabase.memory()); // Use native file in production

  @override
  int get schemaVersion => 1;

  // Reactive Stream Query: Emits automatically on table mutations!
  Stream<List<Product>> watchAllProducts() {
    return select(products).watch();
  }

  Future<void> upsertProducts(List<ProductsCompanion> entries) async {
    await batch((batch) {
      batch.insertAllOnConflictUpdate(products, entries);
    });
  }
}

// Generated boilerplate class representation
abstract class _$AppDatabase extends GeneratedDatabase {
  _$AppDatabase(QueryExecutor e) : super(e);
  $ProductsTable get products => throw UnimplementedError();
}
class $ProductsTable extends Products with TableInfo {}

// 3. Offline-First Repository
class OfflineFirstProductRepositoryFlutter {
  final AppDatabase db;
  final RemoteApiClient api;

  OfflineFirstProductRepositoryFlutter(this.db, this.api);

  Stream<List<Product>> get productStream => db.watchAllProducts();

  Future<void> refreshProducts() async {
    try {
      final remoteList = await api.getProducts();
      final companions = remoteList.map((dto) {
        return ProductsCompanion.insert(
          id: dto.id,
          title: dto.title,
          priceCents: BigInt.from(dto.priceCents),
        );
      }).toList();

      await db.upsertProducts(companions);
    } catch (err) {
      print('Network sync failed: $err. Showing offline cache.');
    }
  }
}

class RemoteApiClient {
  Future<List<dynamic>> getProducts() async => [];
}
```

## 🚨 4. Production Pitfalls & Storage Triage Runbook

```
===================================================================================================
                                 STORAGE ANOMALY TRIAGE RUNBOOK
===================================================================================================

  Anomaly: Main Thread Database Query Crash (Android ANR)
  ├── Symptom: Android app throws 'Cannot access database on the main thread since it may potentially lock the UI'.
  ├── Root Cause: Executing synchronous Room DAO queries directly on Main/UI Dispatcher.
  └── Triage: Always use 'suspend' DAO methods or return Coroutine 'Flow<T>' which Room offloads to I/O threads.

  Anomaly: Room Migration Failure Crash on App Upgrade
  ├── Symptom: App crashes on launch immediately after Play Store update: 'IllegalStateException: Migration failed'.
  ├── Root Cause: Database schema version incremented without providing an explicit 'Migration(from, to)' block.
  └── Triage: Implement explicit Room migrations, write a MigrationTest, or configure '.fallbackToDestructiveMigration()'
              ONLY for non-critical cache databases.

  Anomaly: Multi-Process SQLite Locking
  ├── Symptom: 'database is locked (code 5 SQLITE_BUSY)' when using background WorkManager.
  ├── Root Cause: WorkManager process and Main Application process opening separate SQLite connections.
  └── Triage: Enforce Single-Process Room access or configure SQLite Write-Ahead Logging (WAL) mode.
===================================================================================================
```
