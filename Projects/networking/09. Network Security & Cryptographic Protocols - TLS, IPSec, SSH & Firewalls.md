## 🔒 1. Cryptographic Building Blocks: Symmetric, Asymmetric & Hashes

Network security rests upon three foundational mathematical mechanisms:

```text
===================================================================================================
                                CRYPTOGRAPHIC MECHANISM MATRIX
===================================================================================================

  Primitive               Algorithm                Key Characteristics & Network Use
  ─────────────────────────────────────────────────────────────────────────────────────────────
  Symmetric Ciphers       AES-256-GCM, ChaCha20    Shared secret key. Blazing fast (hardware AES-NI).
                                                   Used for bulk payload encryption in TLS & IPSec.
  Asymmetric Ciphers      RSA-4096, ECC X25519     Public/Private keypair. Computationally expensive.
                                                   Used for key exchange and digital signatures.
  Cryptographic Hashes    SHA-256, SHA-3           One-way trapdoor function. Fixed-size output.
                                                   Guarantees message integrity against tampering.
  HMAC / AEAD             HMAC-SHA256, Poly1305    Keyed authentication. Proves data was not altered
                                                   and originated from legitimate key holder.
```

### 1.1 Public Key Infrastructure (PKI) & X.509 Certificates
How does a browser connecting to `https://bank.com` know it is speaking with the real bank rather than a Man-in-the-Middle (MitM) attacker?
1. The server presents an **X.509 Digital Certificate** containing its public key and domain name.
2. The certificate is cryptographically signed by a trusted **Certificate Authority (CA)** (e.g., Let's Encrypt, DigiCert).
3. The client verifies the signature using the CA's root public key pre-installed in the operating system trust store.

## 🛡️ 2. Transport Layer Security: TLS 1.2 vs. TLS 1.3

**TLS (RFC 8446)** encrypts application-layer data traveling over TCP. TLS 1.3 deprecated broken legacy ciphers (MD5, SHA-1, RC4, RSA key transport) and cut handshake latency in half.

```text
===================================================================================================
                               TLS 1.2 VS. TLS 1.3 HANDSHAKE TIMELINE
===================================================================================================

  [ TLS 1.2 Handshake (2 Full RTTs) ]               [ TLS 1.3 Handshake (1 RTT Handshake) ]
  Client                            Server          Client                            Server
    │─── ClientHello ──────────────►│                 │─── ClientHello + Key Share ──►│
    │◄── ServerHello + Certificate ─│                 │    (Speculates ECDHE key!)    │
    │─── ClientKeyExchange ────────►│                 │◄── ServerHello + Cert + FIN ──│
    │◄── Finished ──────────────────│                 │                               │
    │═══ Encrypted App Data ═══════►│                 │═══ Encrypted App Data ═══════►│
```

### 2.1 Forward Secrecy (PFS)
In legacy TLS, if an attacker recorded all encrypted network traffic over a 5-year period and subsequently stole the server's private RSA key, they could decrypt all historical traffic retrospectively.

TLS 1.3 mandates **Perfect Forward Secrecy (PFS)** via **Ephemeral Diffie-Hellman (ECDHE)**:
- A unique, temporary session key is negotiated for every connection and deleted from memory immediately upon teardown.
- Compromising the server's long-term certificate private key in the future **cannot decrypt historical past sessions**!

## 🌐 3. Network Layer Security: IPSec (AH vs. ESP)

While TLS secures individual application connections at Layer 4, **IPSec (RFC 4301)** operates at Layer 3, encrypting and authenticating **all IP traffic** between routers or hosts (the foundation of corporate VPNs).

```text
===================================================================================================
                             IPSEC TRANSPORT MODE VS. TUNNEL MODE
===================================================================================================

 [ 1. Transport Mode (Host-to-Host) ]
 Original Packet: [ IP Header ] [ TCP Header ] [ Application Payload ]
 IPSec ESP:       [ IP Header ] [ ESP Header ] [ Encrypted: TCP Hdr | App Payload ] [ ESP Auth ]
 (Original IP header remains visible; only payload is encrypted!)

 [ 2. Tunnel Mode (Gateway-to-Gateway Corporate VPN) ]
 Original Packet: [ Inner IP Header ] [ TCP Header ] [ Application Payload ]
 IPSec ESP:       [ New Outer IP Hdr ] [ ESP Hdr ] [ Encrypted: Inner IP | TCP | Data ] [ ESP Auth ]
 (Entire original packet is hidden inside a fresh outer IP packet! Route hops cannot see source/dest!)
```

### 3.1 Protocols within IPSec:
- **AH (Authentication Header):** Provides integrity and origin authentication, but **zero encryption** (data travels in plaintext). Rarely used today.
- **ESP (Encapsulating Security Payload):** Provides both robust encryption (AES-GCM) and authentication.
- **IKEv2 (Internet Key Exchange):** The control protocol that authenticates peers and negotiates Security Associations (SAs).

## 🧱 4. Firewalls & Intrusion Prevention Systems (IDS/IPS)

A **Firewall** acts as an electronic security gatekeeper between trusted private subnets and the hostile public Internet.

```text
===================================================================================================
                                  FIREWALL EVOLUTION STAGES
===================================================================================================

  1. Stateless Packet Filter (L3/L4)
     - Inspects each packet in isolation: Source IP, Dest IP, Protocol, Port.
     - Rule: DROP if Port == 23 (Telnet).
     - Flaw: Cannot distinguish an unsolicited inbound SYN from an expected ACK reply!

  2. Stateful Inspection Firewall (iptables / conntrack)
     - Tracks active TCP connection state machine: NEW, ESTABLISHED, RELATED.
     - Automatically permits inbound packets if they belong to an existing session initiated from inside!

  3. Next-Generation Firewall (NGFW) & Deep Packet Inspection (DPI)
     - Reassembles full application layer streams.
     - Decrypts TLS (via corporate proxy), identifies actual protocol (detects BitTorrent over port 80),
       and blocks malware payloads in real-time.
```

## 🌊 5. Distributed Denial of Service (DDoS) Mitigation

A **DDoS Attack** attempts to exhaust server CPU, memory, or network bandwidth by flooding targets with massive traffic volume from hundreds of thousands of infected botnet nodes.

### 5.1 Common Attack Vectors & Defenses
1. **Volumetric Reflection/Amplification Attacks (DNS / NTP):**
   - Attacker sends $60\text{-byte}$ UDP queries with spoofed victim source IP to misconfigured open DNS resolvers.
   - Resolvers respond with $3000\text{-byte}$ records directed at the victim ($50\times$ amplification!).
   - **Defense:** Upstream ISP filtering via BCP 38 (ingress source-address validation), Anycast CDN scrubbing centers (Cloudflare, AWS Shield).
2. **SYN Flood Attack:**
   - Exhausts kernel half-open socket tables.
   - **Defense:** Enable Linux Kernel SYN Cookies (`net.ipv4.tcp_syncookies = 1`).
3. **Application Layer HTTP Floods (Slowloris):**
   - Sends HTTP headers agonizingly slowly (1 byte every 10 seconds), keeping thousands of web server worker threads tied up indefinitely.
   - **Defense:** Reverse proxies with aggressive connection timeouts (Nginx, Envoy).
