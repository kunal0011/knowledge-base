# Python: High-Performance Tricks & Idioms

**Target Audience:** Engineers seeking clean, idiomatic, and high-performance Python code for technical interviews  
**Topic:** Language-level micro-optimizations, functional libraries (`itertools`, `functools`), grid transformations, and bitwise tricks

## 1. Advanced Unpacking & Dictionary Merging

### 1.1 Extended Star Unpacking
Capture slices cleanly without index slicing bounds errors:
```python
nums = [10, 20, 30, 40, 50]

first, *middle, last = nums
# first = 10, middle = [20, 30, 40], last = 50

*head, tail = nums
# head = [10, 20, 30, 40], tail = 50

# Unpacking into function arguments:
def query(x, y, z): return x + y + z
coords = [1, 2, 3]
print(query(*coords))  # 6
```

### 1.2 Dictionary Union Operators (Python 3.9+)
Instead of mutating with `.update()` or using `{**d1, **d2}`:
```python
d1 = {"a": 1, "b": 2}
d2 = {"b": 99, "c": 3}

# Merge into a new dictionary (right operand takes precedence on duplicate keys):
merged = d1 | d2       # {'a': 1, 'b': 99, 'c': 3}

# In-place merge:
d1 |= d2               # d1 updated in-place
```

## 2. `itertools`: The Functional Powerhouse

The `itertools` module executes in optimized C routines, often running **3–10x faster** than manual Python `for` loops.

### 2.1 `itertools.accumulate`: Instant Prefix Computations
```python
import itertools, operator

nums = [3, 1, 4, 1, 5, 9]

# Prefix sums: [3, 4, 8, 9, 14, 23]
prefix_sums = list(itertools.accumulate(nums))

# Running maximums: [3, 3, 4, 4, 5, 9]
running_max = list(itertools.accumulate(nums, func=max))

# Prefix products: [3, 3, 12, 12, 60, 540]
prefix_prod = list(itertools.accumulate(nums, func=operator.mul))
```

### 2.2 Combinations, Permutations & Cartesian Product
Eliminates tedious recursive backtracking boilerplate:
```python
from itertools import combinations, permutations, product

arr = [1, 2, 3]

# Combinations (order does not matter, length k):
# [(1, 2), (1, 3), (2, 3)]
comb = list(combinations(arr, 2))

# Permutations (order matters, all orderings):
# [(1, 2, 3), (1, 3, 2), (2, 1, 3), ...]
perm = list(permutations(arr))

# Cartesian Product (equivalent to nested loops):
# Generate all coordinates for a 2x3 grid:
coords = list(product(range(2), range(3)))
# [(0,0), (0,1), (0,2), (1,0), (1,1), (1,2)]
```

### 2.3 `itertools.groupby`: Run-Length Encoding
```python
from itertools import groupby

s = "aaabbccccdaa"
# Group adjacent identical elements (NOTE: data must be pre-sorted or contiguous!)
encoded = [(char, len(list(group))) for char, group in groupby(s)]
# [('a', 3), ('b', 2), ('c', 4), ('d', 1), ('a', 2)]
```

### 2.4 Flattening Nested Iterables with `chain.from_iterable`
```python
from itertools import chain

nested = [[1, 2], [3, 4], [5]]
flat = list(chain.from_iterable(nested))  # [1, 2, 3, 4, 5]
```

## 3. `functools` Speed Enhancements

### 3.1 Zero-Boilerplate DP with `@cache` and `@lru_cache`
In Python 3.9+, `@cache` provides an unbounded memoization hash map implemented in C:
```python
from functools import cache

@cache
def rob(i: int) -> int:
    if i >= len(nums):
        return 0
    return max(nums[i] + rob(i + 2), rob(i + 1))
```

To limit cache size and prevent Out-Of-Memory errors in large state spaces:
```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def knapsack(idx, remaining_weight):
    ...
```

> [!IMPORTANT]
> Always call `rob.cache_clear()` between multiple test cases if your recursive function references global or instance state.

### 3.2 Custom Sorting Comparators with `cmp_to_key`
Python 3 removed the `cmp=` parameter in favor of `key=`. For problems where elements depend on pairwise comparisons (e.g., LeetCode 179 *Largest Number*):

```python
from functools import cmp_to_key

nums = ["3", "30", "34", "5", "9"]

def compare(a, b):
    # If a+b > b+a, 'a' should come before 'b' (return negative for standard sort)
    if a + b > b + a:
        return -1
    elif a + b < b + a:
        return 1
    return 0

sorted_nums = sorted(nums, key=cmp_to_key(compare))
# Result: ['9', '5', '34', '3', '30']
```

## 4. Matrix & Grid Transformations

```
Original Matrix:          Transposed (zip(*M)):     Rotated 90 Clockwise:
[ 1, 2, 3 ]               [ 1, 4, 7 ]               [ 7, 4, 1 ]
[ 4, 5, 6 ]      ===>     [ 2, 5, 8 ]      ===>     [ 8, 5, 2 ]
[ 7, 8, 9 ]               [ 3, 6, 9 ]               [ 9, 6, 3 ]
```

### 4.1 Transposing a Matrix
```python
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]

# Transpose rows and columns:
transpose = [list(row) for row in zip(*matrix)]
# [[1, 4, 7], [2, 5, 8], [3, 6, 9]]
```

### 4.2 Rotating a Matrix by 90° Clockwise
Rotate $90^\circ$ Clockwise = **Reverse vertically, then Transpose** (or Transpose, then reverse each row):
```python
# Rotate 90 degrees clockwise in one line:
rotated_cw = [list(col) for col in zip(*matrix[::-1])]

# Rotate 90 degrees counter-clockwise:
rotated_ccw = [list(col) for col in zip(*matrix)][::-1]
```

### 4.3 Compact Grid Direction Vectors
Instead of defining bulky direction arrays:
```python
# 4 Cardinal Directions using itertools.pairwise:
from itertools import pairwise

# (dr, dc) sequentially: (-1, 0), (0, 1), (1, 0), (0, -1)
for dr, dc in pairwise((-1, 0, 1, 0, -1)):
    nr, nc = r + dr, c + dc
```

## 5. Bit Manipulation Idioms

Python integers have **arbitrary precision** (bignums). Unlike C++ or Java where numbers wrap around at 32/64 bits, Python integers have infinite precision.

### 5.1 Count Set Bits (Popcount)
```python
x = 29  # binary: 0b11101 (4 bits set)

# Python 3.10+ (Native C-speed method):
count = x.bit_count()  # 4

# Fallback for Python <= 3.9:
count = bin(x).count('1')  # 4
```

### 5.2 Bit Length & Lowest Bit Tricks
```python
x = 40  # binary: 0b101000

# Total bits required to represent number:
length = x.bit_length()  # 6 (since 2^5 <= 40 < 2^6)

# Extract lowest set bit (LSB):
lsb = x & (-x)           # 8 (binary: 0b001000)

# Clear lowest set bit:
cleared = x & (x - 1)    # 32 (binary: 0b100000)
```

### 5.3 Simulating 32-bit Signed Integers in Python
When implementing bitwise algorithms designed for 32-bit two's complement arithmetic (e.g., LC 371 *Sum of Two Integers*):

```python
MASK = 0xFFFFFFFF        # 32 ones: 4294967295
MAX_INT = 0x7FFFFFFF     # 2147483647

def add_32bit(a: int, b: int) -> int:
    while b != 0:
        carry = (a & b) << 1
        a = (a ^ b) & MASK
        b = carry & MASK
    
    # If sign bit (bit 31) is set, convert from 32-bit unsigned to negative signed:
    return a if a <= MAX_INT else ~(a ^ MASK)
```

## 6. List Comprehension vs `for` Loop Bytecode Efficiency

Why are list comprehensions noticeably faster in Python?

```python
# Approach A: for loop with .append()
res = []
for x in range(1000000):
    res.append(x * 2)

# Approach B: List comprehension
res = [x * 2 for x in range(1000000)]
```

### Bytecode Analysis via `dis`:
- **Approach A:** Every iteration emits `LOAD_FAST` (res), `LOAD_METHOD` (append), evaluates `x * 2`, and executes `CALL_METHOD`. The method lookup on `res.append` occurs repeatedly in the interpreter loop.
- **Approach B:** Emits a specialized CPython bytecode instruction: `LIST_APPEND`. This writes the pointer directly into the C array without Python-level function call overhead.

Benchmark: List comprehensions are **$30\%\text{ to }45\%$ faster** than manual loop appends.

## 7. String Concatenation: `join()` vs `+=`

```python
# ANTI-PATTERN: O(N^2) in general
s = ""
for ch in char_list:
    s += ch

# IDIOMATIC & FAST: Guaranteed O(N)
s = "".join(char_list)
```

### Why `join()` is Superior:
CPython's `"".join(seq)` executes in two passes at the C level:
1. First pass: Iterates through `seq` to compute the total byte length required.
2. Allocation: Allocates a single `PyUnicodeObject` buffer of the exact needed size.
3. Second pass: Copies character memory blocks directly into the allocated buffer using `memcpy()`.

## 8. `collections.Counter` Arithmetic

`Counter` objects support multiset set operations:
```python
from collections import Counter

c1 = Counter("aabbccc")
c2 = Counter("abbcd")

# Multiset subtraction (keeps only positive counts):
diff = c1 - c2  # Counter({'c': 2, 'a': 1})

# Multiset addition:
combined = c1 + c2  # Counter({'c': 4, 'b': 3, 'a': 3, 'd': 1})

# Multiset intersection (min count per key):
inter = c1 & c2     # Counter({'b': 2, 'a': 1, 'c': 1})

# Top k most frequent elements:
top2 = c1.most_common(2)  # [('c', 3), ('a', 2)]
```
