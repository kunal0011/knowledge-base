# Chapter 02: Unity Catalog & Unified Lakehouse Governance

> "Traditional data governance was fragmented: one system governed SQL tables, another managed cloud storage IAM keys, and machine learning models were un-governed artifacts in S3. Unity Catalog establishes a unified control plane where data, files, and AI models share a single 3-level namespace and access control model."

## 1. Canonical Motivation & Theoretical Foundation

### The Legacy Governance Fragmentation
Prior to Unity Catalog, enterprise Databricks deployments suffered from severe architectural friction:
1. **Per-Workspace Hive Metastores:** Every Databricks workspace operated an isolated Apache Hive Metastore. Sharing tables between teams required replicating data or mounting external storage with shared IAM keys.
2. **Coarse Storage Credential Leaks:** Notebooks frequently mounted cloud storage buckets using root access keys:
   ```python
   # DANGEROUS LEGACY ANTI-PATTERN:
   dbutils.fs.mount("s3a://prod-bucket", "/mnt/prod", extra_configs={"fs.s3a.awsAccessKeyId": "..."})
   ```
   Once mounted, any user with access to the workspace could read, write, or delete production data files directly.
3. **The Un-Governed AI Asset Silo:** Machine learning models in MLflow and unstructured training files (PDFs, images) lived in completely separate systems without audit logging, row filtering, or column masking.

### Managed Tables vs. External Tables vs. Volumes

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ 1. Managed Tables                                                              │
│    • Databricks manages both metadata and physical Delta files in storage.     │
│    • Syntax: CREATE TABLE catalog.schema.orders (id INT, amount DOUBLE);       │
│    • WARNING: Issuing DROP TABLE permanently deletes both metadata AND files!  │
├────────────────────────────────────────────────────────────────────────────────┤
│ 2. External Tables                                                             │
│    • Managed metadata, but points to user-specified cloud storage path.        │
│    • Syntax: CREATE TABLE ... LOCATION 's3://my-bucket/orders/';               │
│    • Dropping table deletes metadata ONLY; underlying S3 data files are kept.  │
├────────────────────────────────────────────────────────────────────────────────┤
│ 3. Volumes (Governance for Non-Tabular Data)                                   │
│    • Governs unstructured files (images, PDFs, audio, Parquet checkpoints).    │
│    • Path accessible via POSIX format: /Volumes/catalog/schema/volume_name/    │
└────────────────────────────────────────────────────────────────────────────────┘
```

## 3. Core API Mechanics & Modern Idiomatic Patterns

### 1. Fine-Grained Access Control: Row Filters & Column Masks
Unity Catalog evaluates security rules natively during query planning:

```sql
-- 1. Define Row-Filter Function
CREATE OR REPLACE FUNCTION production.compliance.region_filter(region STRING)
RETURN IF(IS_ACCOUNT_GROUP_MEMBER('global_executives'), true, region = 'US');

-- 2. Apply Row-Filter to Table
ALTER TABLE production.finance.transactions 
SET ROW FILTER production.compliance.region_filter ON (region);

-- 3. Define Column Masking Function
CREATE OR REPLACE FUNCTION production.compliance.mask_ssn(ssn STRING)
RETURN IF(IS_ACCOUNT_GROUP_MEMBER('compliance_officers'), ssn, 'XXX-XX-XXXX');

-- 4. Apply Column Mask to Sensitive Column
ALTER TABLE production.finance.transactions 
ALTER COLUMN ssn SET MASK production.compliance.mask_ssn;
```

### 2. Delta Sharing (Open Data Sharing Protocol)
Databricks Unity Catalog natively implements **Delta Sharing**, the industry's first open-source protocol for secure real-time data sharing across organizations:
- **Zero Data Copying:** Data stays in the provider's S3/ADLS bucket.
- **Vendor Agnostic:** The recipient can query data directly using Python, Pandas, PowerBI, Apache Spark, or DuckDB **without having a Databricks account**.

## 4. Practical Systems & Production Use Cases

### Multi-Environment Catalog Segregation Pattern
Production enterprises configure three primary catalogs in Unity Catalog:
1. `prod_catalog`: Strictly locked down. Writable only by automated CI/CD service principals. Analysts have read-only access with RLS/CLS masks.
2. `staging_catalog`: Automated integration test environment.
3. `dev_sandbox`: Freeform scratchpad for data scientists to prototype transformations without risk of corrupting production data.

## 5. Annotated Production Implementations

### 1. SQL DDL: End-to-End Unity Catalog Governance Setup
Configures a complete multi-tier catalog structure, storage credentials, managed volumes, and role-based permissions.

```sql
-- 1. Create Production Catalog & Schemas
CREATE CATALOG IF NOT EXISTS enterprise_prod
MANAGED LOCATION 's3://enterprise-lakehouse-prod-us-east-1/uc-warehouse/';

USE CATALOG enterprise_prod;

CREATE SCHEMA IF NOT EXISTS finance
COMMENT 'Regulated enterprise financial records';

-- 2. Create Managed Volume for Unstructured Documents
CREATE VOLUME IF NOT EXISTS enterprise_prod.finance.invoices_raw
COMMENT 'Raw PDF and scanned invoice documents';

-- 3. Create Governed Managed Table
CREATE TABLE IF NOT EXISTS enterprise_prod.finance.ledger (
    transaction_id STRING,
    customer_id STRING,
    amount DOUBLE,
    account_number STRING,
    country STRING,
    created_at TIMESTAMP
)
USING DELTA
TBLPROPERTIES ('delta.enableDeletionVectors' = true);

-- 4. Grant Least-Privilege Role-Based Permissions
GRANT USAGE ON CATALOG enterprise_prod TO `finance_analysts`;
GRANT USAGE ON SCHEMA enterprise_prod.finance TO `finance_analysts`;
GRANT SELECT ON TABLE enterprise_prod.finance.ledger TO `finance_analysts`;
GRANT READ VOLUME ON VOLUME enterprise_prod.finance.invoices_raw TO `finance_analysts`;
```

import os

spark = SparkSession.builder.getOrCreate()

df = spark.read.table("enterprise_prod.finance.ledger")

## 6. Authoritative Gotchas, Pitfalls & Performance Anti-Patterns

### 1. The Managed Table Data Eradication Trap
- **The Pitfall:** Running `DROP TABLE my_table;` on a Unity Catalog **Managed Table**.
- **Consequence:** In a Managed Table, Databricks owns the storage lifecycle. Dropping the table permanently deletes the underlying Delta/Parquet files from S3/ADLS storage. If accidental, the entire table is destroyed.
- **Rule:** For critical enterprise data where raw files must survive metadata drop operations, use **External Tables** (`CREATE TABLE ... LOCATION 's3://...'`), or enforce strict Unity Catalog drop permissions.

### 2. The Legacy `hive_metastore` Workspace Drift
- **The Pitfall:** Migrating to Unity Catalog while allowing users to continue creating tables in the default `hive_metastore` catalog.
- **Failure Mode:** Data assets become split between two incompatible security models. Tables in `hive_metastore` lack Row-Level Security, audit lineage, and cross-workspace visibility.
- **Remediation:** Disable workspace-level Hive Metastore access by default and enforce Unity Catalog on all clusters:
  `spark.databricks.acl.dfAclsEnabled true`.

### 3. Outage Triage: Storage Credential Expiration
- **Symptom:** Spark queries fail abruptly with:
  `[INSUFFICIENT_PERMISSIONS] User does not have permission on External Location ...`.
- **Root Cause:** The underlying AWS IAM Role or Azure Service Principal secret associated with the Unity Catalog **Storage Credential** expired or was rotated without updating the catalog.
- **Resolution:** Re-authenticate the storage credential via SQL or Terraform:
  ```sql
  ALTER STORAGE CREDENTIAL aws_s3_lakehouse_cred
  SET IAM_ROLE = 'arn:aws:iam::123456789012:role/databricks-uc-storage-role';
  ```
