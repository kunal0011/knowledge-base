## 🔢 1. Modular Arithmetic & Group Theory

Asymmetric cryptography operates not over the infinite set of real numbers, but over **finite mathematical algebraic structures** where numbers wrap around like hours on a clock.

### 1.1 Congruence Modulo $n$
Let $a, b \in \mathbb{Z}$ and $n \in \mathbb{Z}^+$. We say $a$ is congruent to $b$ modulo $n$, denoted:
$$a \equiv b \pmod n$$
if and only if $n$ divides the difference $(a - b)$, written $n \mid (a - b)$.

### 1.2 Fast Modular Exponentiation: The Square-and-Multiply Algorithm
In RSA and Diffie-Hellman, we must compute massive powers: $x = a^b \bmod n$, where $b$ is a 2048-bit integer ($b \approx 10^{600}$). Calculating $a^b$ directly would produce a number with trillions of digits, overflowing all computer memory.

The **Square-and-Multiply Algorithm** computes $a^b \bmod n$ in **$\mathcal{O}(\log b)$ modular squarings**:

```python
def square_and_multiply(base, exponent, modulus):
    result = 1
    base = base % modulus
    # Convert exponent to binary: e.g. b = 1101_2
    bin_exp = bin(exponent)[2:]
    for bit in bin_exp:
        result = (result * result) % modulus  # SQUARE on every bit
        if bit == '1':
            result = (result * base) % modulus  # MULTIPLY only if bit is 1
    return result
```
Even for a 4096-bit exponent, the calculation completes in less than **1 millisecond**!

## 📐 2. The Euclidean & Extended Euclidean Algorithms

### 2.1 The Euclidean Algorithm for Greatest Common Divisor ($\gcd$)
Based on the invariant that $\gcd(a, b) = \gcd(b, a \bmod b)$:
```text
  Compute gcd(252, 105):
  252 = 2 * 105 + 42
  105 = 2 * 42  + 21
   42 = 2 * 21  + 0   ===> gcd(252, 105) = 21
```

---

### 2.2 The Extended Euclidean Algorithm & Modular Multiplicative Inverse
By Bézout’s Identity, for any integers $a$ and $b$, there exist integers $x$ and $y$ such that:
$$a \cdot x + b \cdot y = \gcd(a, b)$$

If $\gcd(a, m) = 1$, then $a$ and $m$ are coprime. Reducing modulo $m$:
$$a \cdot x + m \cdot y \equiv 1 \pmod m \implies a \cdot x \equiv 1 \pmod m$$
The integer $x$ is the **Modular Multiplicative Inverse** of $a$ modulo $m$, denoted $a^{-1} \pmod m$.

```python
def extended_gcd(a, b):
    if b == 0:
        return a, 1, 0
    gcd, x1, y1 = extended_gcd(b, a % b)
    x = y1
    y = x1 - (a // b) * y1
    return gcd, x, y

def mod_inverse(a, m):
    gcd, x, _ = extended_gcd(a, m)
    if gcd != 1:
        raise ValueError("Modular inverse does not exist (numbers are not coprime)!")
    return x % m
```
This computation is the critical mathematical step in generating RSA decryption keys!

## 👑 3. Euler's Totient Function & Fermat's Little Theorem

### 3.1 Euler's Totient Function ($\phi(n)$)
$\phi(n)$ counts the number of positive integers less than $n$ that are coprime to $n$:
1. If $p$ is a prime number:
   $$\phi(p) = p - 1$$
2. If $n = p \cdot q$ is the product of two distinct primes $p$ and $q$:
   $$\phi(n) = \phi(p) \cdot \phi(q) = (p - 1)(q - 1)$$

---

### 3.2 Euler's Theorem & Fermat's Little Theorem
- **Euler's Theorem:** If $\gcd(a, n) = 1$, then:
  $$a^{\phi(n)} \equiv 1 \pmod n$$
- **Fermat's Little Theorem (FLT):** A special case of Euler's Theorem where $n = p$ is prime:
  $$a^{p-1} \equiv 1 \pmod p \implies a^p \equiv a \pmod p$$

## 🏛️ 4. Chinese Remainder Theorem (CRT)

Let $m_1, m_2, \dots, m_k$ be pairwise coprime moduli. The system of simultaneous congruences:
$$x \equiv a_1 \pmod{m_1}$$
$$x \equiv a_2 \pmod{m_2}$$
$$\dots$$
$$x \equiv a_k \pmod{m_k}$$
has a unique solution modulo $M = m_1 \cdot m_2 \cdots m_k$.

### Cryptographic Application: CRT-RSA Decryption Acceleration
In RSA, computing $m = c^d \bmod n$ (where $n = pq$ is a 2048-bit modulus) is slow. Using the Chinese Remainder Theorem:
1. Compute $m_1 = c^{d \bmod (p-1)} \bmod p$ ($1024\text{-bit}$ math).
2. Compute $m_2 = c^{d \bmod (q-1)} \bmod q$ ($1024\text{-bit}$ math).
3. Combine $m_1$ and $m_2$ via CRT.
Because modular multiplication complexity scales cubically ($\mathcal{O}(k^3)$), splitting the 2048-bit exponentiation into two 1024-bit operations **accelerates RSA private-key decryption by $4\times$**!

## 🎲 5. Primality Testing: The Miller-Rabin Algorithm

Generating a 2048-bit RSA key requires finding two random 1024-bit prime numbers. Trial division would require checking $\approx 10^{150}$ divisors (exceeding the age of the universe). Modern systems use the **Miller-Rabin Probabilistic Primality Test**.

```text
===================================================================================================
                             MILLER-RABIN PRIMALITY TEST FLOW
===================================================================================================

  Given odd candidate n:
  1. Factor out powers of 2 from (n - 1): Write n - 1 = 2^s * d (where d is odd).
  2. Pick random witness base a in [2, n - 2].
  3. Compute: x = a^d mod n.
     - If x == 1 or x == n - 1: Candidate passes this round!
  4. Repeat s - 1 times:
     - x = x^2 mod n
     - If x == n - 1: Candidate passes this round!
     - If x == 1: COMPOSITE (Definitely not prime)!
  5. If loop finishes without returning: COMPOSITE!
```

**Security Bound:** A composite number passes a single round of Miller-Rabin with probability at most $\frac{1}{4}$. Running $k = 40$ rounds reduces the probability of mistakenly accepting a composite number to:
$$\Pr[\text{False Prime}] \le \left(\frac{1}{4}\right)^{40} = 2^{-80} \approx 8.27 \times 10^{-25}$$
which is statistically less likely than a hardware cosmic-ray flipping a bit in CPU memory!

## 🔒 6. The Hard Problems of Asymmetric Cryptography

Modern public-key cryptosystems rely on three computationally intractable mathematical trapdoor functions:

```text
===================================================================================================
                               ASYMMETRIC MATHEMATICAL ASSUMPTIONS
===================================================================================================

  [ 1. Integer Factorization Problem (IFP) ]
  - Easy: Given primes p and q, compute n = p * q in nanoseconds.
  - HARD: Given composite n (2048 bits), find factors p and q!
  - Best Classical Algorithm: General Number Field Sieve (GNFS) - Sub-exponential time.
  - Basis of: RSA Encryption & Signatures.

  [ 2. Discrete Logarithm Problem (DLP) ]
  - Easy: Given generator g, base p, and exponent x, compute y = g^x mod p.
  - HARD: Given y, g, and p, find the secret exponent x = log_g(y) mod p!
  - Basis of: Classic Diffie-Hellman, ElGamal, DSA.

  [ 3. Elliptic Curve Discrete Logarithm Problem (ECDLP) ]
  - Easy: Given curve generator Point G and scalar k, compute public Point P = k * G.
  - HARD: Given Point P and Point G, recover the secret scalar k!
  - No sub-exponential algorithm exists! Requires Pollard's Rho: O(sqrt(n)).
  - Basis of: ECDH, ECDSA, Ed25519 (Modern Internet Standard).
```
