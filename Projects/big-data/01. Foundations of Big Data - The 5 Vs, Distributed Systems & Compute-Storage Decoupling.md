## ⏱️ 2. Theoretical Scaling Limits: Amdahl's Law vs. Gustafson's Law

When scaling big data algorithms across a 1,000-node cluster, how much faster does the job run?

### 2.1 Amdahl's Law (Fixed Workload Size)
Amdahl's Law evaluates execution time for a **fixed-size problem** as the number of parallel processors $N$ increases. Let $\alpha \in [0, 1]$ be the strictly serial portion of the algorithm (e.g., initial coordinator setup, global sorting, final aggregations):

$$S(N) = \frac{1}{\alpha + \frac{1 - \alpha}{N}}$$

As $N \to \infty$:
$$S_{\max} = \lim_{N \to \infty} S(N) = \frac{1}{\alpha}$$

> [!CAUTION]
> **The Amdahl Bottleneck:** If just **$5\%$** of a Spark job is serial ($\alpha = 0.05$), the maximum theoretical speedup across an infinite number of servers is capped at:
> $$S_{\max} = \frac{1}{0.05} = 20\times!$$
> Adding 10,000 nodes will never make the job run more than $20\times$ faster!

---

### 2.2 Gustafson's Law (Scaled Workload Size)
John Gustafson noted that in real-world big data engineering, we do not run the exact same tiny dataset across larger clusters. **As computational capacity grows, we expand the size of the dataset proportionally** (e.g., analyzing 10 years of logs instead of 1 month):

$$S(N) = N - \alpha(N - 1)$$

Under Gustafson’s law, if $\alpha = 0.05$ and $N = 1000$:
$$S(1000) = 1000 - 0.05(999) = \mathbf{950.05\times}\text{ speedup!}$$
This proves that horizontal scale-out is mathematically sound for data-intensive processing as long as dataset volume scales with node count.

### 3.1 Why Compute-Storage Decoupling Won
1. **Independent Resource Scaling:** In co-located Hadoop, if an organization needed more disk space, it had to buy whole servers (paying for unneeded CPUs and RAM). Decoupling allows paying pennies per gigabyte for storage on AWS S3 while scaling compute clusters dynamically on Kubernetes.
2. **Cluster Multi-Tenancy:** A single central Data Lake on S3 can be queried simultaneously by a Spark batch ETL pipeline, a Trino interactive SQL engine, and a Python PyTorch machine learning cluster without moving or duplicating data.
3. **Eliminating Hardware Maintenance:** Object stores provide $99.999999999\%$ ($11\text{ nines}$) durability out of the box, eliminating the operational overhead of replacing failed hard drives and rebalancing HDFS nodes.
