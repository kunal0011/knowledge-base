## 1. Theoretical Motivation: Python as a Framework

In *Fluent Python*, Luciano Ramalho describes the **Python Data Model** as a formalized API that defines the language itself. Rather than forcing developers to memorize arbitrary API method names (like Java's `size()`, `length()`, or `length`), Python unifies object interaction through **Special Methods** (informally known as *dunder* methods, short for "double underscore").

```
             User Code: len(collection), collection[0], a + b
                                    |
                                    v
            Python Interpreter: The Python Data Model
                                    |
                                    v
     Dunder Protocol: __len__(), __getitem__(), __add__()
                                    |
                                    v
         CPython C-API: tp_as_sequence, tp_as_number
```

### The Design Philosophy:
By implementing special methods in your custom classes, your objects behave naturally like built-in types:
1. **Consistency:** Users of your class do not need to read documentation to know how to iterate over it (`for x in obj:`), check its length (`len(obj)`), or slice it (`obj[1:5]`).
2. **Reinventing the Wheel Prevention:** Python's rich standard library (e.g., `random.choice`, `sorted`, `reversed`, `itertools`) automatically works on custom objects that conform to the sequence or collection protocols without requiring custom adapters.

## 2. Underlying Architecture & CPython C-Slots

Why does Python provide built-in functions like `len(x)` instead of an object-oriented method call `x.len()`?

### 2.1 The C-Level Shortcut
In CPython, built-in types like `list`, `str`, and `tuple` do not perform a dynamic method lookup when `len()` is called. Instead, `len(x)` delegates to `PyObject_Size()` in C:

```c
// CPython source: Objects/object.c
Py_ssize_t PyObject_Size(PyObject *o) {
    PySequenceMethods *m;
    if (o == NULL) return null_error();
    m = Py_TYPE(o)->tp_as_sequence;
    if (m && m->sq_length)
        return m->sq_length(o); // Directly reads the ob_size field!
    return PyMapping_Size(o);
}
```

```
Built-in PyVarObject (e.g., list, str, tuple):
+-------------------------------------------------------+
| ob_refcnt (8 bytes)                                   |
| ob_type   (8 bytes) -> &PyList_Type                   |
| ob_size   (8 bytes) = 4  <--- len(x) reads THIS field! |
+-------------------------------------------------------+
(Zero dictionary lookup overhead, O(1) single-cycle pointer dereference)
```

For user-defined classes, CPython translates `len(my_obj)` to `type(my_obj).__len__(my_obj)`. Notice that Python looks up special methods on the **class (`PyTypeObject`)**, not on the instance dictionary `__dict__`, bypassing instance-level shadowing for maximum speed and safety.

## 3. The Core Dunder Protocols Matrix

| Protocol Category | Special Methods | Triggering Expression / Builtin |
|:---|:---|:---|
| **String / Byte Representation** | `__repr__`, `__str__`, `__format__`, `__bytes__` | `repr(x)`, `print(x)`, `f"{x}"`, `bytes(x)` |
| **Boolean Truth Value** | `__bool__`, fallback to `__len__` | `bool(x)`, `if x:` |
| **Collection & Sequence** | `__len__`, `__getitem__`, `__setitem__`, `__delitem__`, `__contains__` | `len(x)`, `x[key]`, `x[k] = v`, `del x[k]`, `item in x` |
| **Iteration** | `__iter__`, `__next__`, `__reversed__` | `iter(x)`, `next(x)`, `reversed(x)`, `for item in x:` |
| **Callable Objects** | `__call__` | `my_obj(*args, **kwargs)` |
| **Attribute Access** | `__getattr__`, `__getattribute__`, `__setattr__`, `__delattr__` | `obj.attr`, `obj.attr = val`, `del obj.attr` |
| **Arithmetic Operators** | `__add__`, `__sub__`, `__mul__`, `__truediv__`, `__floordiv__`, `__matmul__` | `a + b`, `a - b`, `a * b`, `a / b`, `a // b`, `a @ b` |
| **Reverse Arithmetic** | `__radd__`, `__rsub__`, `__rmul__`, `__rtruediv__` | Called on right operand if left operand returns `NotImplemented` |
| **In-place Assignment** | `__iadd__`, `__isub__`, `__imul__` | `a += b`, `a -= b`, `a *= b` |
| **Equality & Ordering** | `__eq__`, `__ne__`, `__lt__`, `__le__`, `__gt__`, `__ge__` | `a == b`, `a != b`, `a < b`, `a <= b`, `a > b`, `a >= b` |
| **Hashing Contract** | `__hash__` | `hash(x)`, used in `dict` keys and `set` elements |

## 4. Comprehensive Production Implementation: `Vector2D`

Here is an annotated implementation demonstrating arithmetic overloading, rich representations, boolean evaluation, sequence slicing, and hashability.

```python
import math
from typing import Iterator

class Vector2D:
    """A 2D mathematical vector adhering to the Python Data Model."""
    __slots__ = ('_x', '_y')  # Memory optimization: suppresses instance __dict__

    def __init__(self, x: float, y: float) -> None:
        self._x = float(x)
        self._y = float(y)

    @property
    def x(self) -> float:
        return self._x

    @property
    def y(self) -> float:
        return self._y

    # 1. Representation Protocol
    def __repr__(self) -> str:
        # Unambiguous string representation: eval(repr(v)) == v
        return f"Vector2D({self._x!r}, {self._y!r})"

    def __str__(self) -> str:
        # User-friendly display
        return f"({self._x}, {self._y})"

    def __format__(self, format_spec: str = "") -> str:
        if format_spec.endswith('p'):  # Polar coordinates format
            fmt = format_spec[:-1]
            mag = abs(self)
            ang = math.atan2(self._y, self._x)
            return f"<{mag:{fmt}}, {ang:{fmt}} rad>"
        return f"({self._x:{format_spec}}, {self._y:{format_spec}})"

    # 2. Boolean Truth Value
    def __bool__(self) -> bool:
        # A vector is falsy if its magnitude is zero
        return bool(self._x or self._y)

    # 3. Numeric & Arithmetic Protocol
    def __abs__(self) -> float:
        # Hypotenuse: magnitude
        return math.hypot(self._x, self._y)

    def __add__(self, other: object) -> 'Vector2D':
        if isinstance(other, Vector2D):
            return Vector2D(self._x + other._x, self._y + other._y)
        return NotImplemented  # Allows other.__radd__ to handle it

    def __radd__(self, other: object) -> 'Vector2D':
        return self.__add__(other)

    def __mul__(self, scalar: float) -> 'Vector2D':
        if isinstance(scalar, (int, float)):
            return Vector2D(self._x * scalar, self._y * scalar)
        return NotImplemented

    def __rmul__(self, scalar: float) -> 'Vector2D':
        return self.__mul__(scalar)

    # 4. Sequence Protocol (Emulating 2-element sequence)
    def __len__(self) -> int:
        return 2

    def __getitem__(self, index: int) -> float:
        if index == 0 or index == -2:
            return self._x
        elif index == 1 or index == -1:
            return self._y
        raise IndexError(f"{self.__class__.__name__} index out of range")

    def __iter__(self) -> Iterator[float]:
        yield self._x
        yield self._y

    # 5. Equality & Hashability Protocol
    def __eq__(self, other: object) -> bool:
        if isinstance(other, Vector2D):
            return self._x == other._x and self._y == other._y
        return NotImplemented

    def __hash__(self) -> int:
        # Requires immutable components; allows storing Vector2D in sets/dict keys
        return hash((self._x, self._y))
```

### Execution Trace & Verification:
```python
v1 = Vector2D(3, 4)
v2 = Vector2D(1, 2)

print(repr(v1))        # Vector2D(3.0, 4.0)
print(abs(v1))         # 5.0
print(v1 + v2)         # (4.0, 6.0)
print(v1 * 3)          # (9.0, 12.0)
print(3 * v1)          # (9.0, 12.0) - Dispatched via __rmul__!
print(f"{v1:.2f}")     # (3.00, 4.00)
print(f"{v1:.2fp}")    # <5.00, 0.93 rad> (Polar format!)

# Unpacking works automatically because __iter__ or __getitem__ is implemented:
x, y = v1
print(x, y)            # 3.0 4.0

# Set membership works because __hash__ and __eq__ are implemented:
s = {v1, v2}
print(Vector2D(3, 4) in s)  # True
```

## 5. Practical Systems & Software Patterns

### 5.1 The French Deck (Ramalho's Canonical Example)
Implementing just `__len__` and `__getitem__` transforms any object into a fully compliant Python sequence:

```python
import collections

Card = collections.namedtuple('Card', ['rank', 'suit'])

class FrenchDeck:
    ranks = [str(n) for n in range(2, 11)] + list('JQKA')
    suits = 'spades diamonds clubs hearts'.split()

    def __init__(self):
        self._cards = [Card(rank, suit) for suit in self.suits
                                        for rank in self.ranks]

    def __len__(self):
        return len(self._cards)

    def __getitem__(self, position):
        return self._cards[position]
```

### What You Get for Free:
Because `FrenchDeck` implements `__len__` and `__getitem__`:
- **Indexing & Slicing:** `deck[0]`, `deck[-1]`, `deck[:3]` work immediately.
- **Random Sampling:** `random.choice(deck)` works with zero extra code.
- **Iteration:** `for card in deck:` works automatically.
- **Reverse Iteration:** `reversed(deck)` works automatically.
- **Membership Testing:** `'spades' in deck` works via sequential linear search fallback.
- **Sorting:** `sorted(deck, key=card_value_fn)` works seamlessly.

## 6. Authoritative Gotchas & Traps (Ramalho & Lutz)

### 6.1 Trap 1: Implementing `__str__` without `__repr__`
```python
class Item:
    def __init__(self, name): self.name = name
    def __str__(self): return self.name

items = [Item("A"), Item("B")]
print(items) # Prints [<__main__.Item object at 0x...>, <__main__.Item object at 0x...>]
```
**Why it happens:** Containers (`list`, `dict`, `tuple`) print their elements using `repr()`, not `str()`. If `__repr__` is omitted, Python falls back to the default object address.  
**Rule (Fluent Python):** If you only implement one string representation method, **always implement `__repr__`**. Python automatically falls back to `__repr__` when `__str__` is not defined!

### 6.2 Trap 2: Returning `False` instead of `NotImplemented`
In arithmetic operators (`__add__`, `__eq__`), if your class does not support an operand type:
```python
# ANTI-PATTERN:
def __add__(self, other):
    if not isinstance(other, Vector2D):
        raise TypeError(...) # Prevents right operand's __radd__ from being evaluated!

# CORRECT:
def __add__(self, other):
    if not isinstance(other, Vector2D):
        return NotImplemented # Signals Python runtime to try other.__radd__(self)
```

### 6.3 Trap 3: The Mutable `__hash__` Disaster
If a class overrides `__eq__` without defining `__hash__`, Python sets `__hash__ = None`, making the class unhashable.
If you manually define `__hash__` on an object with mutable state:
```python
class BadKey:
    def __init__(self, val): self.val = val
    def __hash__(self): return hash(self.val)
    def __eq__(self, other): return self.val == other.val

k = BadKey(10)
d = {k: "found"}
k.val = 20 # Mutated key!
print(d[k]) # KeyError! Hash changed; searches the wrong bucket!
```
**Rule (Effective Python / Fluent Python):** Only implement `__hash__` on strictly immutable objects.

## 7. Actionable Summary Checklist

- [x] Special methods are called by the Python interpreter and CPython internals; do not call `my_obj.__len__()` directly—use `len(my_obj)`.
- [x] Implement `__repr__` first to ensure debugging and container inspections are readable.
- [x] Implement `__len__` and `__getitem__` to get slicing, iteration, `in` checks, and `random.choice` for free.
- [x] Return `NotImplemented` (not `TypeError`) from arithmetic methods when encountering unknown types to enable reverse operator fallback.
- [x] Ensure objects implementing `__hash__` also implement `__eq__` and remain immutable throughout their lifecycle.
