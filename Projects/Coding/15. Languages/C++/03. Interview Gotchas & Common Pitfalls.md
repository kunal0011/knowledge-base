# C++: Interview Gotchas & Common Pitfalls

**Target Audience:** Software engineers and candidates preparing for C++ technical interviews  
**Topic:** Critical language traps, memory invalidation, unsigned arithmetic bugs, and STL comparator crashes

---

## 1. Top C++ Gotchas Summary

| Pitfall | Symptoms / Manifestation | Underlying Cause | Correct Idiomatic Solution |
|:---|:---|:---|:---|
| **Iterator Invalidation** | Random crashes / segfaults during loop | `push_back` reallocates buffer; `erase` shifts memory | Use returned iterator: `it = v.erase(it)` or `std::erase_if` |
| **Unsigned `size_t` Underflow** | Infinite loop or instant segfault | `size_t` is unsigned; `0 - 1` wraps to $2^{64}-1$ | Cast: `int i = (int)v.size() - 1` or use reverse iterators |
| **Non-Strict Weak Ordering** | Segfault inside `std::sort` | Comparator returning `true` for equality (`<=`) violates axiom | Always use strict `<`; equality must return `false` |
| **Accidental Deep Copy** | $\mathcal{O}(N^2)$ TLE in recursive DFS | Passing `std::vector` by value copies entire memory buffer | Pass by reference: `const std::vector<T>&` or `std::vector<T>&` |
| **`std::unordered_map` Hack** | $\mathcal{O}(N^2)$ TLE on LeetCode/Codeforces | Default integer hash is identity; adversarial inputs collide | Use custom randomized hash (SplitMix64) |
| **`auto` Stripping Qualifiers** | Unintended deep copies during iteration | `auto` drops reference `&` and `const` modifiers | Use `const auto& x` or `auto& x` explicitly |
| **Dangling String Pointer** | Garbage memory or segfault | Calling `.c_str()` on temporary `std::string` | Bind `std::string` to named local variable first |

## 2. Iterator Invalidation

Iterators are essentially smart pointers into container memory. When the container alters its underlying layout, iterators can become dangling pointers.

### 2.1 The `push_back` Invalidation Trap
```cpp
std::vector<int> v = {1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == 2) {
        v.push_back(99); // DANGEROUS! Reallocation invalidates all iterators!
    }
}
```
If `v.size() == v.capacity()`, `push_back()` allocates a new memory block, copies elements over, and deallocates the old memory. The iterator `it` now dereferences freed heap memory, triggering undefined behavior or a crash.

### 2.2 The `erase` Invalidation Trap
```cpp
// INCORRECT: Causes crash or skipped elements
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) {
        v.erase(it); // it is now invalidated! ++it is Undefined Behavior!
    }
}

// CORRECT: erase() returns an iterator to the next valid element
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) {
        it = v.erase(it);
    } else {
        ++it;
    }
}

// MODERN C++20 IDIOM:
std::erase_if(v, [](int x) { return x % 2 == 0; });
```

## 3. The Unsigned `size_t` Loop Underflow Bug

In C++, container `.size()` returns `std::size_t`, which is an **unsigned 64-bit integer**.

```cpp
// DEADLY BUG 1: Infinite Loop!
for (size_t i = v.size() - 1; i >= 0; --i) {
    std::cout << v[i] << " ";
}
```

### Why it Fails:
An unsigned integer can **never** be negative. The condition `i >= 0` is tautologically `true` for every unsigned value.
When `i` reaches `0`, `--i` decrements it to:
$$0 - 1 = 18,446,744,073,709,551,615 \ (2^{64} - 1)$$
The loop never terminates, accessing out-of-bounds memory and causing an instant segmentation fault.

### DEADLY BUG 2: Empty Container Crash
```cpp
// When v is empty (v.size() == 0):
int last_idx = v.size() - 1; // 0ULL - 1ULL = 18446744073709551615ULL!
```

### The Idiomatic Solutions
```cpp
// Solution A: Explicit signed cast (Standard in Interviews)
for (int i = static_cast<int>(v.size()) - 1; i >= 0; --i) { ... }

// Solution B: Reverse Iterators (Clean & idiomatic)
for (auto it = v.rbegin(); it != v.rend(); ++it) { ... }
```

## 4. Strict Weak Ordering & `std::sort` Segfaults

When supplying a custom comparator to `std::sort` or `std::priority_queue`, it **MUST** establish a **Strict Weak Ordering**.

### Mathematical Axiom:
$$\text{comp}(a, a) == \text{false} \quad (\text{Irreflexivity})$$

```cpp
// FATAL COMPILATION BUG: Using <= instead of <
std::sort(v.begin(), v.end(), [](int a, int b) {
    return a <= b; // CRASH! Violates Strict Weak Ordering!
});
```

### Why it Crashes:
`std::sort` (Introsort) performs quicksort partitioning using pointers without redundant array bounds checks on every iteration. It assumes that encountering a pivot equal to itself will cause `comp(pivot, pivot)` to return `false`, stopping the scanning pointer.
When `comp(a, a)` returns `true`, the inner pointer scan never stops, walks off the end of the array, and crashes with `SIGSEGV` or `SIGBUS`.

> [!CAUTION]
> **Golden Rule:** Custom sorting comparators must return `true` **strictly** when element `a` must precede `b`. If they are equal, always return `false`.

## 5. Pass-by-Value vs Pass-by-Reference in Recursion

```cpp
// DISASTROUS: Copies entire vector on every single stack frame!
void dfs(int u, std::vector<int> path) {
    path.push_back(u);
    for (int v : adj[u]) dfs(v, path);
}
```
If the recursion reaches depth $N$, this allocates and copies $\mathcal{O}(N)$ elements on each frame, blowing complexity to **$\mathcal{O}(N^2)$ time and memory**, easily triggering Time Limit Exceeded (TLE) or Out-Of-Memory (OOM).

### The Correct Pattern: Pass by Reference with Backtracking
```cpp
void dfs(int u, std::vector<int>& path) {
    path.push_back(u);
    for (int v : adj[u]) {
        dfs(v, path);
    }
    path.pop_back(); // Backtrack
}
```

## 6. `std::unordered_map` Anti-Hash Collisions ($\mathcal{O}(N^2)$ Hack)

In GNU GCC libstdc++, `std::hash<long long>` is implemented as the **identity function**:
```cpp
// GCC libstdc++ implementation:
template<> struct hash<long long> {
    size_t operator()(long long x) const noexcept { return x; }
};
```

### The Attack:
Because the bucket count is prime (e.g., $107,897$), an adversary constructs an input array of multiples:
$$\{0, 107897, 215794, 323691, \dots\}$$
All $10^5$ numbers compute to the exact same hash bucket index `0`!
Every insertion and lookup degrades to scanning a singly-linked list of size $N$, collapsing the entire algorithm from $\mathcal{O}(N)$ to **$\mathcal{O}(N^2)$**.

### The Solution: Custom SplitMix64 Hash
```cpp
#include <chrono>

struct custom_hash {
    static uint64_t splitmix64(uint64_t x) {
        // High-performance bit mixer
        x += 0x9e3779b97f4a7c15;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9;
        x = (x ^ (x >> 27)) * 0x94d049bb133111eb;
        return x ^ (x >> 31);
    }

    size_t operator()(uint64_t x) const {
        static const uint64_t FIXED_RANDOM = 
            std::chrono::steady_clock::now().time_since_epoch().count();
        return splitmix64(x + FIXED_RANDOM);
    }
};

// Safe against any adversarial test cases:
std::unordered_map<long long, int, custom_hash> safe_map;
```

## 7. `auto` Dropping Reference and `const` Qualifiers

```cpp
std::vector<std::string> words = {"apple", "banana", "cherry"};

// BUG: words are copied by value on every iteration!
for (auto word : words) { ... }

// OPTIMAL: Read-only reference (zero copies)
for (const auto& word : words) { ... }

// OPTIMAL: Mutable reference (in-place modification)
for (auto& word : words) { ... }
```
When iterating over vectors of non-trivial objects (`std::string`, `std::vector`, custom structs), omitting `&` triggers an expensive copy constructor on every single loop iteration.
